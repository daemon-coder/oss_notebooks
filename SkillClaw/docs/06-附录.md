## A. 术语表

| 术语 | 定义 | 首次出现 |
|---|---|---|
| **Skill** | 一个可复用的能力单元,= `<name>/SKILL.md` + 可选 `scripts/ references/ assets/` | 01 |
| **SKILL.md** | Skill 的文本文件:YAML frontmatter + Markdown body | 01 |
| **frontmatter** | `SKILL.md` 顶部的 YAML 块,必须含 `name` + `description` | 01 |
| **Session** | 一次用户对话 = 多个 turn,从第一个用户消息到 `session_done=true` | 01 |
| **Turn** | 一对 user + assistant(可能含 tool_calls) | 03.01 |
| **PRM** | Process Reward Model,SkillClaw 里弱化为"turn-level 回复质量评分" | 04.09 |

| **Workflow engine** | Evolve Server 的默认引擎,3 阶段 LLM 流水线 | 03.04 |
| **Agent engine** | Evolve Server 的 opt-in 引擎,启动 OpenClaw 子进程 | 03.05 |
| **Sharing** | 跨用户的 skill 共享,通过对象存储(OSS/S3/local/Nacos) | 03.03 |
| **Hub** | 共享层的逻辑名,`SkillHub` / `NacosSkillHub` | 04.04 |
| **Bundle** | 一个 skill 的所有文件 dict,`{rel_path: bytes}` | 04.04 |

| **Generation** | `SkillManager.generation`,文件变化时自增 | 04.03 |

| **Job / Result** | 共享存储上的 `validation/jobs/<job_id>.json` 和 `validation/results/<user>/<job_id>.json` | 04.10 |

| **Nacos** | Alibaba 的服务发现 + 配置中心,Nacos 3.x 加了 Skill Registry API | 04.05 |
| **Working version** | Nacos 概念:可编辑的 skill 版本 | 04.05 |

## C. 待确认清单(源码读不透的项)

下面这些是**我无法从源码 100% 确定**的内容,需要项目维护者确认或读 PR / issue 历史才能明确。

### C.1 设计意图类

1. **`use_success_feedback` 字段实际作用** —— `EvolveServerConfig` 里有这个字段(默认 `True`),但没在 `engines/` 看到读取点,可能在 `pipeline/execution.py` 某个 prompt 模板里有条件分支但 grep 没定位到。
2. **`evolve_strategy` 字段值集合** —— 默认 `"dynamic_edit_conservative"`,但代码里只看到这一个值被使用,其他策略可能未实现或被注释掉。
3. **`skill_reload_mode=callback` 的实现** —— 配置项允许 `off/poll/callback`,但只看到 `poll` 的实现。`callback` 是否被实现、怎么 hook,源码不明确。
4. **Nacos `admin=True` 的权限模型** —— Nacos 端点区分"客户端可读"和"管理员可读",但 SkillClaw 端的 `nacos_access_token` 是否真的有 admin scope,需要 Nacos 端配置确认。
5. **`proxy_api_key` 与 `llm_api_key` 的关系** —— `proxy_api_key` 看起来是给 `/internal/*` 端点用,但 client 自己调 LLM 时是否也用它作为 bearer,源码不明确。
6. **`replay` 之外的 validation mode** —— `validation_mode` 默认 `"replay"`,其他值(`"human_review"`?)在源码未实现或注释掉。

### C.2 行为类(没有看测试无法确认)

1. **`SkillManager.refresh_if_changed` 的 mtime 检测精度** —— 用 `mtime_ns`,但容器 / NFS / 某些 FUSE 文件系统 `mtime_ns` 精度可能不够,导致 fingerprint 漏检。
2. **`evolve_server` `--use-skillclaw-config` 时 `from_skillclaw_config` 的容错** —— 看到 `try/except`,但失败时具体行为(部分配置是否生效)不清楚。
3. **`api_server._trigger_evolve` 重试逻辑** —— 3 次,每次 sleep 1s,2s,但为什么是这个数。详见 [03.02 D 节](./03-核心流程/03.02-会话录制与归档.md) 的 "**`_trigger_evolve` 重试逻辑**" 段(已补充 rationale)。
4. **`dashboard` 的 `dashboard_evolve_server_url` 实际作用** —— 看起来给 dashboard 用来直接调 evolve server,但不明确是否真的被用。
5. **`prm_scorer` 的"Azure content filter 触发"判断标准** —— `_sanitize_text` 看起来是绕过触发,但具体哪些 tag 触发了 filter 不可知。
6. **Nacos `_wait_nacos_publish` 的 30s 超时合理性** —— Nacos v3 审核管线 30s 是否够,生产数据没有。

### C.3 行为类(测试覆盖不到 / 罕见路径)

1. **Windows 上的 `start_new_session` 行为** —— macOS / Linux 测试覆盖,Windows 看代码但没看到 Windows 集成测试。
2. **`--mock` 模式下的 `MockBucket` 与真实 OSS 的行为差异** —— 看到 `mock_bucket.py` 是个简化版,真实 OSS 的 list / delete 语义可能不完全一致。
3. **多进程同时跑 evolve server 时的并发安全** —— `SkillIDRegistry` 是内存状态,多进程实例会冲突(尽管有 `load_from_oss` 启动恢复,但写入仍可能 race)。
4. **`session_done` 漏传时的状态** —— `_resolve_tui_session` 启发式推断,但具体多长算"同一 session"在不同 config / 不同 IP 下表现差异。
5. **大 session(> 100 turn)的处理** —— `_session_turns` 内存累积无上限,evolve server `evolve_batch_size=20` 默认只看 20 个 session,**不**是 session 内的 turn 数,要看清楚。

### C.4 实现细节(需要看 git blame / PR)

1. **`evolve_server/.env` 的存在与否** —— `core/config.py` 提到 `evolve_server/.env` 自动加载,但仓库里 `evolve_server/evolve_server.env.example` 才是模板,实际 `.env` 是用户复制后加的,源码不直接 include。
2. **`scripts/install_skillclaw.sh` 在不同 Python 版本下的行为** —— 没在 macOS / Linux 多版本测试矩阵看,只看到 `python -m venv .venv` 的样板。
3. **`dashboard_assets/app.js` 是否有外部依赖** —— 看了几行像纯 vanilla JS,但完整文件没扫,可能引了 CDN。
4. **`share` 字段在某些 agent 框架(尤其是 Claude Code)的兼容性矩阵** —— 各 Agent 版本兼容性可能在 README 之外有 caveat。

### C.5 文档未覆盖的"将来要做"事项

1. **"plugin" 机制** —— README 没明确说"如何加新 Agent"和"如何加新 storage backend"的扩展点位置。
2. **A/B testing skill** —— 没有"两个 skill 版本同时跑,看哪个效果更好"的实验框架。
3. **skill 的语义搜索 vs 关键字搜索** —— 当前只有 embedding 模式;没有 BM25 / Elasticsearch 之类。
4. **多语言 skill** —— 没看到针对"中文 skill vs 英文 skill"的特殊处理。

### C.6 历史修复记录(已修复,留作溯源)

这一节是 sourcebook 自身演进的修复记录,**当前源码已无对应问题**,新读者可以跳过。

1. **`claw_adapter._ADAPTERS` 的 `opencode` 重复 key** —— sourcebook round 1 review 之后,正文中曾加过一条注释说明"早期版本(在 review 前) `_ADAPTERS` 中曾出现 `opencode` 重复 key 两次,两次都指向同一函数(语义等价,后写覆盖前写)。当前源码已修复为唯一的 12 个 key"。**已于当前源码修复**(模块底部 12 个唯一 key,无重复),round 3 精修时将这条注释从 [04.06](./04-模块详解/04.06-代理适配层.md) 章节正文移除,挪到本节作为溯源条目。
