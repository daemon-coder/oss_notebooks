# 03.3 共享 skill 同步:本地 ↔ 共享存储

> 这一章讲 client 怎么把本地 skill 推到云端(push)、怎么把云端拉下来(pull)、怎么在本地维护"和云端一致"的视图。

## 设计动机

如果 SkillClaw 只是单用户本地 skill 库,流程到 03.02 就结束了。但 README 强调的卖点是"集体进化"——多个用户 / 多个设备的 skill 要**合并 + 去重 + 共享**。这就要求 client 有一个**双向同步层**。

设计目标:

1. **增量** —— 不要每次都全量传几百个文件,基于 sha256 决定要不要重传。
2. **可回滚** —— 拉新 skill 时可能覆盖本地,如果拉回来发现版本不对,要能恢复到拉之前。
3. **可选** —— 默认关,用户用 `skillclaw setup` 显式打开 sharing 才走这条路径。
4. **可插拔后端** —— 不绑定 OSS,可以是 S3、本地目录、Nacos。

## 实现流程(pseudo-code)

### A. Push(本地 → 共享)

```
# skill_hub.py
def push_skills(self, local_skills_dir):
    manifest = self._load_remote_manifest()    # 读 {group_id}/manifest.jsonl
    
    for skill_dir in scan(local_skills_dir):
        name = skill_dir.name
        bundle = read_skill_bundle(skill_dir)  # { "SKILL.md": bytes, "scripts/...": bytes }
        tree_sha = bundle_tree_sha256(bundle)
        
        record = manifest.get(name)
        if record and record["tree_sha256"] == tree_sha:
            continue  # 增量:内容一致,跳过
        
        if record and record["tree_sha256"] != tree_sha:
            # 内容不同:覆盖上传
            for rel_path, content in bundle.items():
                key = self._skill_bundle_key(name, rel_path)
                self._bucket.put_object(key, content)
            
            # 删除云端已存在但本地已删除的多余文件
            self._delete_remote_bundle_extras(name, keep_paths=bundle.keys())
        
        else:
            # 新增:全部上传
            for rel_path, content in bundle.items():
                self._bucket.put_object(self._skill_bundle_key(name, rel_path), content)
    
    # 更新 manifest(追加 + 整体覆盖)
    new_manifest = {...}
    save_manifest(bucket, prefix, new_manifest)
```

> **批量**:push 不是逐 skill 写 manifest,而是先全部写完再 save 一次 manifest,保证原子性(对 S3/OSS 来说,单个 key 写是原子的,所以 manifest 是 last-writer-wins,但至少不会出现 manifest 比 skill 更新的"幽灵 manifest")。

### B. Pull(共享 → 本地)

```
def pull_skills(self, local_skills_dir, skip_names=None):
    remote_manifest = self._load_remote_manifest()
    
    # 1. 备份现有本地
    backup_root = self._create_local_backup(local_skills_dir)
    
    try:
        # 2. 镜像远端
        local_names = {p.name for p in scan(local_skills_dir)}
        remote_names = set(remote_manifest.keys())
        
        # 2a. 下载新增/更新
        for name in remote_names - skip_names:
            record = remote_manifest[name]
            bundle = self._download_skill_bundle(name, record)
            write_skill_bundle(local_skills_dir / name, bundle)
        
        # 2b. 删除云端没有的(可选)
        # (默认不删,见 hub.pull_skills 的 deleted 计数)
        
        # 3. 返回统计
        return {
            "downloaded": N, "skipped": M, "failed": K, "deleted": D,
            "total_remote": len(remote_names), "failed_names": [...]
        }
    except Exception:
        # 4. 出错就回滚
        self._restore_local_backup(backup_root, local_skills_dir)
        raise
```

### C. Nacos 后端的特殊处理

`NacosSkillHub` 不走对象存储 key tree,改用 Nacos 的 skill lifecycle API:
- 上传走 `NacosSkillClient.upload_skill_zip`(把 SKILL.md + 附件打成 zip)
- 走 `submit` + `publish` 两步(后者等 Nacos v3 审核管线批准)
- 版本号由 `_next_version()` 自动算,`latest` label 由 Nacos 端管

详细 API 列表见 [04.05](./04-模块详解/04.05-nacos适配.md)。

## 常见误区

1. **"pull 会覆盖本地未上传的修改"** —— **是**,pull 假设云端是 source of truth。如果你在本地改了 skill 但没 push,下次 pull 会被覆盖。规避:本地用 `--skip-names` 显式排除,或者**先 push 再 pull**。
2. **"push 是默认行为"** —— 错。`sharing.enabled=False` 时 push/pull 都是空操作,只在 `auto_pull_on_start=true` 时启动时拉一次(还是要 enabled)。
3. **"Nacos 后端和 OSS 后端可以同时用"** —— 部分对。`sharing.skill_backend=nacos` 时,skill 资产走 Nacos,**会话和验证 job 仍然走** `sharing.backend`(通常是 oss / s3 / local)。见 `SkillHub.object_storage_from_config` 的拆分逻辑(`skill_hub.py:`附近)。
4. **"manifest.jsonl 是追加写"** —— **是**。每条 skill 的记录都是一行 JSON,`save_manifest` 把整个 dict 序列化成 jsonl。读时按行 parse,后写覆盖前写。**不是**真"append-only log",是 "read all + overwrite all" 的简化。
5. **"SkillHub 拉完会立刻生效"** —— 是的,但需要 `SkillManager` 配合:client 端 `pull_skills` 之后会调 `skill_manager.refresh_if_changed()`,后者做指纹比对,变了才真正 reload。所以"拉了但没生效"通常是 `refresh_if_changed` 的 fingerprint 没变化(skill 内容被远端覆盖了但内容相同)。
6. **"`sharing.skill_backend` 可以是 Nacos 之外的任何后端"** —— 设计上是为 Nacos 留的口子,但当前实现只在 `nacos` 值时切换走 `NacosSkillHub`;`local`/`s3`/`oss` 走的是同一份 `SkillHub`。
