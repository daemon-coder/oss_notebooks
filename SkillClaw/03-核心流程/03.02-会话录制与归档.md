# 03.2 会话录制、归档与 PRM 评分

> 03.01 解决了"skill 怎么进去",这一章解决"会话怎么留下来 + 怎么被打分"。

## 设计动机

SkillClaw 的核心价值是"从真实会话中进化 skill"。前提是:**它必须能拿到完整、忠实、带可观测评分的会话数据**。

为此,代理在每个请求结束后需要做三件事:

1. **累积 turn** —— 把当前请求 / 响应累积到 `session_id` 关联的内存列表里,带 tool_calls、tool_results、错误信息。
2. **判断 session 边界** —— 决定"这是不是一段会话的最后一条"。
3. **打 PRM 分** —— 异步调 LLM judge,评判当前回复对当前用户指令是否有用(+1/0/-1),写入 `prm_scores.jsonl`,并回填到 `SkillManager` 的 effectiveness 计数。

最后,周期性地把累积的完整 session 上传到共享存储。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| **Turn** | 一对 user + assistant 消息(可能含 tool_calls / tool_results) | 03.01 |
| **Session** | 一次用户对话 = 多个 turn,从第一个用户消息到 `session_done=true` 或 idle 超时 | 01 |
| `record_dir` | 本地落盘目录,默认 `records/` | `config.py:84` |
| `conversations.jsonl` | 每个 turn 一行,完整 trace | `api_server.py:1497` |
| `prm_scores.jsonl` | 每个 PRM 打分动作一行 | `api_server.py:1498` |
| `_session_turns` | 内存中的 session → turns 列表映射(进程级状态) | `api_server.py` 内部状态 |
| `sharing_session_upload_interval` | 每 N 个 user-visible turn 上传一次(0 = 不自动上传) | `config.py:117` |
| `session_idle_close_seconds` | 多久没活动就关 session,默认 180s | `api_server.py:79` 常量 |
| **PRM(Process Reward Model)** | "turn-level 回复质量评分",LLM judge 打 {-1, 0, 1};多投票 + majority vote(详见 04.09) | `prm_scorer.py` |
| `effectiveness` | `positive_count / inject_count`,默认 0.5 | `skill_manager.py:230` |
| **Majority vote** | 跑 `prm_m` 次 LLM judge,取出现次数最多的分(平局 → 0) | `prm_scorer.py:_majority_vote` |

## 实现流程(pseudo-code)

### A. Turn 累积(in-request)

```
# 03.01 _post_request_hooks 中的步骤
def post_request_hooks(session_id, turn_type, request_body, response, skills_injected):
    # 1. 把 turn 写到内存
    turn = build_turn_record(
        request_body, response,
        skills_referenced=skills_injected,
        tool_calls=extract_tool_calls(response),
        tool_results=extract_tool_results(...),
        tool_errors=extract_tool_errors(...)
    )
    self._session_turns[session_id].append(turn)
    
    # 2. 写 conversations.jsonl
    with open(record_file, "a") as f:
        f.write(json.dumps(turn) + "\n")
    
    # 3. 如果 session_done,关闭
    if session_done:
        close_session(session_id)
    
    # 4. 异步触发 PRM 评分(只有 final 类型的 main turn)
    if turn_type == "main" and turn_is_final:
        asyncio.create_task(prm_score(turn))
```

### B. PRM 评分(async)

```
# skillclaw/prm_scorer.py
async def prm_score(turn):
    response_text = turn["assistant_content"]
    instruction = turn["last_user_message"]
    
    # 1. 调 LLM judge prm_m 次(默认 3)
    tasks = [judge_vote(response_text, instruction) for _ in range(prm_m)]
    votes = await asyncio.gather(*tasks)
    
    # 2. majority vote
    score = majority(votes)   # -1, 0, or 1
    
    # 3. 写 prm_scores.jsonl
    with open(prm_record_file, "a") as f:
        f.write(json.dumps({
            "session_id": session_id, "turn_num": ...,
            "votes": votes, "score": score
        }) + "\n")
    
    # 4. 回填到 SkillManager
    skill_manager.record_feedback(turn["skills_referenced"], score)
```

`record_feedback` 会更新每个被注入 skill 的 `positive_count` / `negative_count`,并重算 `effectiveness`。这个数字会被下次的 skill 排序(embedding 模式下的 `_weighted_score`)使用。

### C. Session 边界与上传

```
# api_server.py: 内存中的 _session_turns 维护
触发关闭的三种路径:
  1. 显式 session_done=True (body 或 X-Session-Done header)
  2. 空闲超时:上次活动距今 > session_idle_close_seconds
  3. 进程退出 (lifespan shutdown)

关闭时:
  - 把 session_id 从 active set 移除
  - (可选) 触发最后一次上传

# 周期上传触发(不是关闭触发!)
每隔 sharing_session_upload_interval 个 user_turn,主动上传:
def maybe_upload_session_snapshot(session_id, user_turn_num):
    if user_turn_num % interval == 0:
        turns = deepcopy(self._session_turns[session_id])
        asyncio.create_task(upload_session_data(session_id, turns))
        # 上传成功后,可选触发 evolve server
        asyncio.create_task(trigger_evolve())
```

### D. Evolve 触发链路(client → server → client)

```
client                                 evolve_server
  │                                          │
  │  POST {evolve_server_url}/trigger        │
  │ ────────────────────────────────────────▶│
  │                                          │  跑一次 run_once()
  │                                          │  摘要 + 聚合 + 进化 + 上传
  │  HTTP 200 { uploaded_skills: N }         │
  │ ◀────────────────────────────────────────│
  │                                          │
  │  如果 uploaded_skills > 0:                │
  │  主动 pull_skills()                      │
  │  SkillManager.refresh_if_changed()       │
  │                                          │
```

`/trigger` 这个端点在 `evolve_server/engines/workflow.py:1034`–`:1035`(workflow 引擎)和 `engines/agent.py:491`(agent 引擎)。

**`_trigger_evolve` 重试逻辑**(`api_server.py:3121`):

- **3 次尝试**(`for attempt in range(3)`),每次 `httpx.AsyncClient(timeout=300.0)`,即 **5 分钟** 单次请求超时(覆盖一次 `run_once` 的最坏时间)。
- **退避**:`attempt 0 → sleep 1.0s`,`attempt 1 → sleep 2.0s`,`attempt 2(最后一次)→ 不 sleep`。3 次全部失败后 `logger.warning(...)` 然后**直接返回**,不抛异常(不影响主请求路径)。
- **成功后**:如果响应 JSON 里 `uploaded_skills > 0`,**主动**调 `_pull_skills_from_cloud()` 把新 skill 拉下来;否则下次正常 `pull` 周期才拿到。
- **副作用**:`_trigger_evolve` 是在 `asyncio.create_task` 里跑的 fire-and-forget,主请求路径不阻塞。日志级别 INFO,失败降级为 WARNING。

> 为什么是"3 次 + 1s/2s"而不是"更多次"或"指数退避":evolve server 跑一次 LLM 流水线可能要 1-2 分钟,**3 次累计 ~3 分钟已经能覆盖"evolve server 慢"场景**;如果 3 次都失败,通常意味着更严重的问题(配置错、bucket 不可达),继续重试意义不大。退避用 1s/2s 而不是 1s/2s/4s/8s 是为了**早失败**(主流程不需要等 8s 才发现)。

## 常见误区

1. **"每个 turn 都打分"** —— 不。只有 `turn_type == "main"` 且是 final 类型的 turn(用户能感知的、不是工具调用中转)才打,见 `_is_user_turn_boundary`。
2. **"PRM 立刻影响下次注入"** —— 部分。`record_feedback` 是同步的(立刻更新内存中的 stats),但 skill 排序时**只在 embedding 模式**才把这个数字乘进权重(见 `_weighted_score`);template 模式只用 effectiveness 排序。
3. **"session 关闭 = 上传"** —— **错**。实际是"每 N 个 user_turn 上传一次",session 关闭本身不一定上传。上传是"节奏控制"动作,关闭是"状态清理"动作,两者独立。
4. **"evolve_server_url 必填"** —— 错。空着的话,只本地 session 录制,不触发进化。`trigger_evolve` 在 `evolve_server_url` 为空时直接 `return`。
5. **"上传 session 会立刻推新 skill"** —— **也不一定**。只有当 `uploaded_skills > 0` 时,client 才会主动 `pull_skills()`;否则下次正常 `pull` 周期才会拿到。
6. **"PRM 是 skill 验证器"** —— **不是**。PRM 是 turn-level 的回复质量评分,跟 `pipeline/skill_verifier.py` 的 skill 验证是两回事。后者只看"候选 skill 本身写得对不对",见 [03.04](./03.04-workflow引擎进化.md)。
