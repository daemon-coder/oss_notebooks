# 03.5 Agent 引擎的 skill 编辑(OpenClaw 驱动)

> `evolve_server` 的另一种实现方式:**不用 LLM 直接编辑 SKILL.md,而是启动一个 OpenClaw 子进程,让它用工具把 skill 写出来**。

## 设计动机

Workflow 引擎的 3 阶段流水线**硬编码**了"摘要 → 聚合 → 进化"的形态。LLM 拿到 evidence,然后**输出 JSON**,**客户端代码解析** JSON,自己写文件。这对"稳定的、可控的"演进够用,但有两个限制:

1. **不能用工具**。LLM 不能 read 远端 skill、不能 grep session 中的 tool result 原文、不能逐行编辑。
2. **不能迭代**。一次 LLM 调用出一个 JSON,坏了好重跑,没有"先 read 现状 → 决定改哪儿 → 验证"的循环。

Agent 引擎就是为了解决这两个问题:把 OpenClaw(一个本身就支持工具调用的 LLM agent)放进一个**有文件系统的 workspace**里,让它自己决定怎么读、怎么改。

代价:**更慢、更贵、更难调试**。所以默认是 workflow,agent 是 opt-in。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| **Agent 引擎** | Evolve Server 的 opt-in 引擎,启动 OpenClaw 子进程用工具编辑 skill(对比 workflow 是直接 LLM 输出 JSON) | 03.04 / 04.14 |
| **OpenClaw** | NousResearch 维护的 agent 框架(不是 SkillClaw 自家产品);agent 引擎通过 `OpenClawRunner` 调它的 CLI 子进程 | `engines/openclaw_runner.py` |
| `--engine agent` | 启动时切换到 agent 引擎 | `evolve_server/__main__.py:_build_server` |
| `OpenClawRunner` | 启动 `openclaw` CLI 子进程(`asyncio.create_subprocess_exec` + timeout) | `engines/openclaw_runner.py:24` |
| **Agent Workspace** | agent 的工作目录(文件操作的舞台,默认 `evolve_server/agent_workspace/`) | `engines/agent_workspace.py` |
| **EVOLVE_AGENTS.md** | agent 的"系统提示词"——告诉 OpenClaw agent 要做什么、硬规则 | `engines/agents_md.py:load_agents_md` |
| `agent_workspace` | 默认 workspace 目录 | `core/config.py` 中 `workspace_root` 字段 |
| `fresh=true` | 每次 run_once 都重置 workspace(默认) | `core/config.py` |
| `agents_md_path` | 自定义 EVOLVE_AGENTS.md 路径 | `core/config.py` |

## 实现流程(pseudo-code)

### A. 启动与 workspace 准备

```
# engines/agent.py:run_once
async def run_once(self):
    # 1. 准备 workspace(agent 的文件操作舞台,默认 evolve_server/agent_workspace/)
    if self.config.fresh:
        self._workspace.reset()              # 清空所有上次文件(fresh=True 默认)
    self._workspace.bootstrap_skills(remote_skills)  # 把远端 skill 拷到 workspace/skills/(只读镜像)
    self._workspace.bootstrap_sessions(sessions)     # 把要处理的 session 写到 workspace/sessions/
    
    # 2. 构造 agent 任务(prompt: 描述"处理这批 session,输出 skill")
    task = self._build_task(sessions)
    
    # 3. 启动 OpenClaw 子进程(用 --workspace 指向本机工作目录, --agents-md 指向系统提示)
    result = await self._openclaw.run(
        task=task,
        workspace=self._workspace.root,
        agents_md_path=self.config.agents_md_path or default_path,
        timeout=self.config.agent_timeout,   # 默认较长,可能 1-5 分钟
    )
    
    # 4. 收割结果(diff workspace 里被改的 SKILL.md)
    new_skills = self._workspace.collect_changed_skills()  # 找出 workspace/skills/ 里被改 / 新增的 SKILL.md
    
    # 5. 上传(走与 workflow 引擎相同的 _resolve_and_upload:检冲突 + 上传 + 更新 manifest)
    for skill in new_skills:
        await self._resolve_and_upload(skill, "agent_edit")
```

### B. OpenClawRunner 与子进程

```
# engines/openclaw_runner.py
class OpenClawRunner:
    async def run(self, *, task, workspace, agents_md_path, timeout):
        cmd = [
            self.openclaw_bin,                  # 默认 "openclaw"
            "--workspace", str(workspace),
            "--agents-md", str(agents_md_path),
            "task", task,                       # 子命令 task + 参数
        ]
        env = os.environ.copy()
        env["OPENCLAW_HOME"] = str(self.config.openclaw_home)
        env["AGENT_EVOLVE_LLM_API_KEY"] = self.config.llm_api_key
        env["AGENT_EVOLVE_LLM_BASE_URL"] = self.config.llm_base_url
        env["AGENT_EVOLVE_MODEL"] = self.config.llm_model
        
        proc = await asyncio.create_subprocess_exec(
            *cmd,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.PIPE,
            env=env,
        )
        try:
            stdout, stderr = await asyncio.wait_for(proc.communicate(), timeout=timeout)
        except asyncio.TimeoutError:
            proc.kill()
            raise
        
        if proc.returncode != 0:
            raise RuntimeError(f"openclaw failed: {stderr.decode()[:200]}")
        return parse_output(stdout)
```

### C. EVOLVE_AGENTS.md(系统提示)

`engines/agents_md.py:load_agents_md` 读取一个 markdown 文档,内容大致描述:

```
# SkillClaw Evolve Agent

You are an expert SkillClaw skill engineer. Your job is to evolve reusable
SKILL.md documents from a batch of agent session records.

## Inputs
- {workspace}/sessions/   — JSON files of agent sessions to process
- {workspace}/skills/     — current remote skills (read-only mirror)

## Outputs
- {workspace}/skills/<name>/SKILL.md  — your edits / creations

## Editing principles
(同 workflow 引擎的 _EVOLVE_FROM_SESSIONS_SYSTEM 提炼版)

## Hard rules
- Do not delete existing skills
- Do not change API endpoints / ports / payload formats unless evidence
  clearly shows they are wrong
- Use the file tools provided by OpenClaw to read sessions, write skills
```

## 实现要点 / 与 workflow 的对比

| 维度 | workflow 引擎 | agent 引擎 |
|---|---|---|
| LLM 调用次数 | 多个独立(每阶段一次) | 一个长 session,内部多次 |
| LLM 能用工具吗 | 不能 | 能(grep / read / write) |
| 状态 | 无状态,每次重读 evidence | 有状态,workspace 文件可累积 |
| 速度 | 快(分钟级) | 慢(可能小时级) |
| 成本 | 低 | 高(可能 10x) |
| 调试 | 看 `_build_*_prompt` 的 debug dump | 看 `EVOLVE_AGENTS.md` + workspace 文件 + 子进程日志 |
| 输出 | 结构化 JSON,客户端解析 | 文件系统变更,客户端 diff |
| 适用场景 | 稳定 / 高频 / 简单 skill | 复杂 / 跨多 session / 需要交叉引用 |

## 常见误区

1. **"agent 引擎会自动比 workflow 好"** —— **不**。Workflow 在很多场景下更可控,尤其当 skill 改动小、需求稳定时。Agent 引擎适合"需要跨多 session 串起来理解"的复杂情况。
2. **"agent 引擎不需要 LLM 调用客户端配置"** —— 错。`AGENT_EVOLVE_LLM_API_KEY` / `AGENT_EVOLVE_LLM_BASE_URL` / `AGENT_EVOLVE_MODEL` 是给 OpenClaw 内部 LLM 用的,跟 evolve server 自己的 `_llm`(用于 session 摘要)是两套。
3. **"fresh=true 意味着每次清空所有"** —— 是的(默认)。如果你想保留 workspace 跨多次 run_once,用 `--no-fresh`(`evolve_server/__main__.py:fresh_group`)。
4. **"agent 引擎不需要摘要阶段"** —— 错。`AgentEvolveServer._summarize_sessions`(`engines/agent.py:180`)还是会先调 LLM 做 session 摘要,再把摘要写到 workspace,然后让 OpenClaw 读这些摘要 + 原始 session 工作。
5. **"agent 引擎的输出可以直接信任"** —— 不能。`_resolve_and_upload` 仍然走冲突检测 + 合并(同 workflow 引擎)。Agent 写出来的东西也会被规范化(frontmatter 校验、name 校验)。
6. **"workspace 是临时目录"** —— **是**。但默认在 `evolve_server/agent_workspace/`(`core/config.py` 的 `workspace_root` 字段默认值),`--workspace-root` 可改。
