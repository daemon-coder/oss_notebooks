# 03.6 后台 validation worker(可选)

> 团队部署里,evolve server 跑出候选 skill 后,不是直接 publish,而是"丢一个验证任务到共享存储,等某个空闲的 client 接单、replay 评估、写回结果"。

## 设计动机

Workflow 引擎出来的 skill 是"LLM 觉得对",但没有在真实环境跑过。理论上,如果有**真实 LLM 客户端跑过一遍,新 skill 确实能比旧 skill 让对话更顺**,那才有资格 publish。

设计目标:

1. **不阻塞 evolve server** —— 候选 skill 立刻写,但 publish 延后。
2. **不阻塞 client** —— 验证必须等"client 空闲"才跑,不能跟用户对话抢资源。
3. **去中心化** —— 任何开了 `validation.enabled=true` 的 client 都是潜在验证者,运维不需要单独跑服务。
4. **可降级** —— 任何一步失败,任务留在 `jobs/` 等下个 client 接单。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| **Validated publish mode** | 服务端配置 `publish_mode=validated` 时,候选 skill 不直接 publish,先写为 job 等 client 验证 | `evolve_server/core/config.py:publish_mode` |
| **Job** | 共享存储里的 `validation/jobs/<job_id>.json` —— 一个"待评估的候选 skill + replay cases"的容器 | `validation_store.py` |
| **Result** | 共享存储里的 `validation/results/<user_alias>/<job_id>.json` —— 一个 client 跑完一个 job 后的评估结果 | `validation_store.py` |
| **Replay 评估** | 把"历史 user instruction"重新跑一遍 LLM(用 candidate skill 替换 system prompt 中的 skill 块),看 PRM 分 | `validation_worker.py:_replay_validate_job` |
| `validation.enabled` | 客户端是否参与后台验证(默认 False) | `config.py:139` |
| `validation.mode` | 验证模式(目前只 `replay`) | `config.py:140` |
| `validation.idle_after_seconds` | 多少秒没活动算"空闲"(默认 300s) | `config.py:141` |
| `validation.poll_interval_seconds` | 多久查一次新 job(默认 60s) | `config.py:142` |
| `validation.max_jobs_per_day` | 每天最多跑几个(默认 5) | `config.py:143` |
| `validation.max_concurrency` | 单次循环最多跑几个(默认 1) | `config.py:144` |
| `ValidationStore` | 共享存储里 jobs/ 和 results/ 的封装 | `validation_store.py` |
| `ValidationWorker` | 客户端的轮询循环 | `validation_worker.py` |
| `is_idle_for_validation` | api_server 提供给 worker 的"是否空闲"探针 | `api_server.py` 内部 |

## 实现流程(pseudo-code)

### A. 服务端:候选 skill 写为 job(在 workflow 引擎 `run_once` 步骤 7)

```
# evolve_server/engines/workflow.py:_finalize_validation_jobs
async def _finalize_validation_jobs(self):
    # 遍历所有 open 的 validation job,达到阈值才 publish,太多 reject 则拒绝
    for job in self._validation_store.list_open_jobs():
        if self._job_meets_thresholds(job):                 # 收集的 accept 数 / 分数达标
            # 从 job 提取 candidate_skill,走 _upload_skill(同 workflow 引擎的上传路径)
            self._upload_skill(job["candidate_skill"], "validated_publish")
            self._validation_store.mark_published(job["job_id"])
        elif self._job_too_many_rejections(job):           # reject 累计超过阈值
            self._validation_store.mark_rejected(job["job_id"])

def _job_meets_thresholds(self, job):
    return (
        job["results_count"] >= self.config.validation_required_results    # 至少 N 个 client 提交结果
        and job["accepts_count"] >= self.config.validation_required_approvals  # 至少 N 个 accept
        and job["mean_score"] >= self.config.validation_min_mean_score    # 平均分达标
        and job["rejections_count"] < self.config.validation_max_rejections   # reject 累计未到上限
    )
```

Job 的 payload 包含:
- `candidate_skill`: 候选 skill 文档(待评估)
- `current_skill`: 当前线上版本(用于 baseline 对比)
- `replay_cases`: 1-3 个历史 user instruction(从 session 摘要中抽),用于 replay 评估
- `min_score`: 该 job 要求的最低分(0.75 默认,候选 skill 在 replay 上的平均 normalized PRM 分 >= 0.75 才算 accept)

### B. 客户端:后台轮询

```
# skillclaw/validation_worker.py:run
async def run(self):
    while not self._stop_event.is_set():
        try:
            await self.run_once()
        except Exception:
            logger.warning("polling loop failed")
        await asyncio.wait_for(self._stop_event.wait(), timeout=interval)
```

### C. 单次接单 + 评估

```
# skillclaw/validation_worker.py:run_once
async def run_once(self, *, force=False):
    # 1. 三道门:enabled / quota / idle
    if not self._validation_enabled():         # validation.enabled && sharing.enabled && group_id
        return {"reason": "validation disabled or sharing not configured"}
    if not self._quota_available():           # 每天最多 max_jobs_per_day
        return {"reason": "daily validation quota reached"}
    if not self._is_idle(force=force):         # client 不在 idle 状态(force=True 跳过)
        return {"reason": "client is not idle"}
    
    # 2. 拉该 user 还没提交过结果的所有 open job
    jobs = self._store.list_open_jobs(user_alias=self._user_alias)
    if not jobs:
        return {"reason": "no open validation jobs"}
    
    # 3. 串行接单(最多 max_concurrency 个),跑 _validate_job
    for job in jobs[:max_concurrency]:
        if not self._quota_available():
            break
        result = await self._validate_job(job)        # ← 调 LLM replay 评估
        self._store.save_result(job_id, user_alias, result)
        self._jobs_completed_today += 1
```

### D. Replay 评估(把历史 user instruction 重跑,看 candidate 是否比 baseline 好)

```
# skillclaw/validation_worker.py:_replay_validate_job
async def _replay_validate_job(self, job):
    candidate = job["candidate_skill"]           # 待评估的候选 skill
    current = job.get("current_skill")           # 当前线上版(baseline,可能为 None)
    cases = job["replay_cases"]                  # 历史 user instruction × 1-3
    
    candidate_scores, baseline_scores = [], []
    
    for case in cases[:3]:                       # 最多 3 个 case(避免太慢)
        # 1. baseline: 把 current skill 塞 system prompt,跑本机 LLM
        baseline = await self._run_replay(case, current)
        # 2. candidate: 把 candidate skill 塞 system prompt,跑本机 LLM
        candidate_run = await self._run_replay(case, candidate)
        
        # 3. PRM 打分(把"回复对指令有没有用"打成 [-1, 0, 1])
        baseline_prm = await self._prm_scorer.evaluate(baseline["text"], case["instruction"])
        candidate_prm = await self._prm_scorer.evaluate(candidate_run["text"], case["instruction"])
        
        # 4. 把 {-1, 0, 1} 归一化到 [0, 1] 便于平均
        baseline_scores.append(_normalize(baseline_prm["score"]))
        candidate_scores.append(_normalize(candidate_prm["score"]))
    
    candidate_mean = mean(candidate_scores)
    baseline_mean = mean(baseline_scores) if baseline_scores else 0.0
    threshold = job["min_score"]                 # 默认 0.75
    
    # accept 需要同时满足: candidate 绝对分够高, 且 不比 baseline 差
    accepted = candidate_mean >= threshold and candidate_mean >= baseline_mean
    
    return {
        "validator_mode": "replay",
        "decision": "accept" if accepted else "reject",
        "score": candidate_mean,
        "threshold": threshold,
        "baseline_mean": baseline_mean,
        "reason": f"candidate={candidate_mean} baseline={baseline_mean} threshold={threshold}"
    }
```

`_run_replay` 干的事:把 skill 文档塞进 system prompt(模拟"用这个 skill 跑对话"),然后调本机的 LLM 跑一次,拿回复。PRM judge 评估这个"假如用这个 skill 跑出来"的回复质量。

## 常见误区

1. **"validation 默认开启"** —— 错。`validation.enabled` 默认 False,需要 `skillclaw config validation.enabled true` 显式打开。
2. **"任何 client 都能接单"** —— 部分对。`list_open_jobs` 是基于 `user_alias` 匹配的,避免重复:同一个 job 不会被同一个 user 多次接。**不同 user** 可以同时接同一个 job 跑 N 次,服务端聚合 N 个结果。
3. **"replay 用的是 client 的 LLM"** —— **是**。`AsyncLLMClient` 配的是 client 自己的 LLM(可能和 evolve server 的不同),所以"replay 评估"事实上是"用 client 自己的 LLM 视角评估"。
4. **"accept 一定 publish"** —— **不一定**。`validated` publish mode 要求**多个 client** 的结果都通过(默认 `validation_required_results=1`,但可以拉到更高)。任何一个 client 拒绝(rejection >= `validation_max_rejections`)也会让 job 失败。
5. **"force=true 跳过 idle 检查"** —— 是。`run_once(force=True)`,对应 CLI `skillclaw validation run-once --force`,专门给"想立刻测一下"的人用。
6. **"validation 跟 PRM 评分是一回事"** —— 不是。`PRMScorer` 是给 turn 打分;`ValidationWorker` 是给**候选 skill 文档**打"在新会话上跑得顺不顺"的分。两者都用同一个 LLM,但目标对象不同。
