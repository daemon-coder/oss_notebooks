# 04.11 可视化面板 `dashboard_*.py`

> 本地可视化层:扫本地 skill 库 + 共享存储 + 本地 record,渲染到 FastAPI + 静态前端。

## 设计动机

SkillClaw 跑了一段时间后,用户想看:

- "我本地有什么 skill?"
- "云端有什么 skill,我有哪个没?"
- "candidate validation job 跑到哪一步了?"
- "session 是怎么走到这的?"

不做 dashboard 的话,用户只能看 `~/.skillclaw/records/conversations.jsonl` 的纯文本。可视化把这部分封装到 web UI。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| **Snapshot** | 一次 dashboard 同步的"完整状态"对象:config + 本地 skills + 远端 skills + sessions + validation jobs + warnings | `dashboard_ingest.py:build_dashboard_snapshot` |
| `dashboard_server.py` | FastAPI 入口,提供 API + 静态资源 | `dashboard_server.py:1` |
| `dashboard_ingest.py` | 把 config + 共享存储 + 本地 record 投影成 snapshot | `dashboard_ingest.py:1` |
| `dashboard_store.py` | SQLite 投影存储(把 snapshot 写进 SQLite,API 查 SQLite 而非每次重读 jsonl) | `dashboard_store.py:1` |
| `dashboard_assets/` | 前端静态资源(纯 vanilla JS,无 React/Vue 框架) | `index.html` / `app.js` / `styles.css` |
| `DashboardService` | 业务逻辑层(API handler 调它) | `dashboard_server.py:119` |
| `build_dashboard_snapshot` | 一次性构造完整 snapshot(读 3 处数据源 + merge) | `dashboard_ingest.py` |
| `dashboard.db` | SQLite 文件,默认 `~/.skillclaw/dashboard.db` | `config.py:153` |
| `sync` / `serve` 子命令 | `skillclaw dashboard sync` / `serve` | `cli.py` |

## 实现要点

### A. 数据源

Dashboard 读三处:

```
1. 本地 skill 库(config.skills_dir)
   ↓
   dashboard_ingest._load_local_skills(config)

2. 共享存储(基于 config.sharing_*)
   ↓
   SkillHub.list_remote() + 拉 manifest

3. 本地 record(config.record_dir/conversations.jsonl)
   ↓
   dashboard_ingest._load_record_sessions(config)
```

并把它们 merge 成一个 `snapshot` dict,写进 SQLite。

### B. Snapshot 构造(`dashboard_ingest.build_dashboard_snapshot`)

```python
def build_dashboard_snapshot(config, *, include_shared=True) -> dict:
    warnings = []
    
    # 1. 本地 skills
    local_skills = _load_local_skills(config, warnings)
    
    # 2. 远端 skills(从 SkillHub)
    remote_skills = {}
    if include_shared and config.sharing_enabled:
        try:
            hub = SkillHub.from_config(config)
            remote_skills = hub.list_remote_skills()  # name → {version, sha256, ...}
        except Exception as e:
            warnings.append(f"shared skills load failed: {e}")
    
    # 3. 本地 sessions
    sessions = _load_record_sessions(config, warnings)
    sessions += _load_state_sessions(config, warnings)   # 从 runtime_state
    
    # 4. Validation jobs
    validation_jobs = []
    if config.sharing_enabled:
        try:
            store = ValidationStore.from_config(config)
            validation_jobs = store.list_all_jobs()  # 包括已 publish / rejected
        except Exception as e:
            warnings.append(f"validation jobs load failed: {e}")
    
    return {
        "config": _config_to_dict(config),
        "local_skills": local_skills,
        "remote_skills": remote_skills,
        "sessions": sessions,
        "validation_jobs": validation_jobs,
        "warnings": warnings,
        "synced_at": _utc_now_iso(),
    }
```

### C. 本地 session 加载

`_load_record_sessions` 读 `config.record_dir` 下的:
- `conversations.jsonl`(api_server 录的)
- `prm_scores.jsonl`(PRM 评分结果)
- 兼容老格式:直接 record JSON 文件

`state/` 子目录:从 `runtime_state.py` 写的"当前活动 session"快照。

`dashboard_ingest._load_state_sessions` 合并"runtime_state 中的活动 session"和"已落盘的会话"。

### D. SQLite 投影(`dashboard_store.py`)

```
sessions 表:
    session_id TEXT PRIMARY KEY
    user_alias TEXT
    timestamp TEXT
    num_turns INTEGER
    payload TEXT  (JSON, 完整 turns)

skills 表:
    name TEXT
    source TEXT (local / remote)
    version INTEGER
    sha256 TEXT
    payload TEXT

validation_jobs 表:
    job_id TEXT
    status TEXT (open / published / rejected)
    payload TEXT
```

Dashboard API 不直接读 `dashboard_ingest` 每次,而是先调 `sync` 把 snapshot 写进 SQLite,API 再查 SQLite。**为什么?** 因为读 `conversations.jsonl` 解析所有 turn 是 O(N) 慢操作,SQLite 索引能 O(log N)。

### E. FastAPI 路由(`dashboard_server.py:536+`)

```
GET  /                           → 静态 index.html
GET  /static/*                   → 静态资源
GET  /api/health                 → {"ok": true}
GET  /api/overview               → { total_skills, total_sessions, ... }
GET  /api/skills                 → list (支持 ?filter=...)
GET  /api/skills/{id}            → detail
POST /api/skills/{id}/activate   → (no-op,留接口)
GET  /api/sessions               → list
GET  /api/sessions/{id}          → detail
GET  /api/validation/jobs        → list
GET  /api/evolve/status          → 远端 evolve server 状态(可选)
POST /api/sync                   → 触发一次 snapshot rebuild
POST /api/skills/pull            → 调 SkillHub.pull_skills
POST /api/skills/push            → 调 SkillHub.push_skills
POST /api/skills/sync            → pull + push
POST /api/evolve/trigger         → 调 evolve_server_url/trigger
POST /api/validation/jobs/{id}/review → 提交人工 review(可选)
```

### F. 静态资源(`dashboard_assets/`)

- `index.html` —— 单页 HTML,fetch 上面那些 API
- `app.js` —— 纯 JS,无框架
- `styles.css` —— 简单样式

设计:**纯静态 + fetch**,**不**用 React / Vue。适合"内嵌到 SkillClaw 的小工具"。

### G. CLI 子命令

```
skillclaw dashboard sync                       # 一次 snapshot → SQLite
skillclaw dashboard serve [--host] [--port]    # 启 dashboard HTTP
skillclaw dashboard serve --no-sync-on-start   # 跳过启动时 sync
```

`serve` 启动时默认 rebuild snapshot(`dashboard_sync_on_start=true`),如果刚 `sync` 过可以 `--no-sync-on-start` 加速。

## 常见误区

1. **"dashboard 是远程服务"** —— **不是**,默认 `host=127.0.0.1`。**不**对外开放,本机看。
2. **"dashboard 跑起来就实时更新"** —— **不是**。要 `sync` 才会 rebuild snapshot。`serve` 启动时 sync 一次,之后**不**自动更新(除非外部调 `POST /api/sync`)。
3. **"dashboard 跟 SkillClaw proxy 是一回事"** —— **不是**。两个独立进程、独立端口(默认 proxy=30000, dashboard=3788)。Dashboard 只**读** `record_dir` 和共享存储,**不**改主流程。
4. **"dashboard 在没有共享时也能用"** —— **是**。`include_shared=true` 走 try/except,共享读不到时 `warnings.append(...)` 继续,`remote_skills={}`。
5. **"SQLite 是必须的吗"** —— **是**。`dashboard_store.py` 默认连接 `~/.skillclaw/dashboard.db`,不存在就建。
6. **"`dashboard_evolve_server_url` 跟 `evolve_server_url` 是同一项"** —— **是**。前者给 dashboard 用,后者给 proxy trigger 用。
