# 04.10 后台验证 `validation_worker.py` + `validation_store.py`

> 客户端上的"候选 skill 评估"循环。空闲时拉 job,replay 评估,写回结果。

## 设计动机

详见 [03.6](../03-核心流程/03.06-后台验证.md)。本章聚焦"代码层面怎么实现"。

简言之:

1. **Evolve server 写 job 到共享存储**(在 `validated` publish mode 下,见 03.04)。
2. **多个 client 在 idle 时**拉 job,跑 replay 评估,写回 result。
3. **Evolve server 聚合**所有 result,达到阈值才 publish 候选 skill。

这套机制让"用户验收"成为 skill publish 的一道关卡,而不是 LLM 自己的判断。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| **Validated publish mode** | evolve_server 配置:`publish_mode=validated` 时,候选 skill 不直接 publish,先写为 job 等 client 验证 | `evolve_server/core/config.py:publish_mode` |
| **Job** | 共享存储里的 `validation/jobs/<job_id>.json` —— 一个"待评估的候选 skill + replay cases"的容器 | `validation_store.py` |
| **Result** | 共享存储里的 `validation/results/<user_alias>/<job_id>.json` —— 一个 client 跑完一个 job 后的评估结果 | `validation_store.py` |
| **Replay 评估** | 把"历史 user instruction"重新跑一遍 LLM(用 candidate skill 替换 system prompt 中的 skill 块),看 PRM 分;支持"baseline 跟 candidate 对比" | `validation_worker.py:_replay_validate_job` |
| `ValidationWorker` | 客户端后台轮询协程(idle 时拉 job → 跑 replay → 写 result) | `validation_worker.py:64` |
| `ValidationStore` | 共享存储里 jobs / results 的封装 | `validation_store.py` |
| `IdleStateProvider` | `api_server` 提供的"是否空闲"探针(Protocol) | `validation_worker.py:25` |
| `ValidationRunSummary` | 单次 `run_once` 结果 | `validation_worker.py:35` |
| `_validation_enabled` | 检查 `validation.enabled && sharing.enabled && sharing.group_id` | `validation_worker.py:_validation_enabled` |
| `_quota_available` | 每天最多 `validation.max_jobs_per_day` | `validation_worker.py:_quota_available` |
| `_is_idle` | `api_server` 提供,基于"无 active session + 上次请求距今 N 秒" | `validation_worker.py:_is_idle` |
| `IdleStateProvider` Protocol | 三个方法:`active_session_count` / `last_request_age_seconds` / `is_idle_for_validation` | `validation_worker.py:25-29` |

## 实现要点

### A. ValidationWorker 构造

```python
class ValidationWorker:
    def __init__(self, config, *, idle_provider=None):
        self.config = config
        self._idle_provider = idle_provider     # 通常是 SkillClawAPIServer
        self._store = ValidationStore.from_config(config)
        self._stop_event = asyncio.Event()
        self._jobs_completed_today = 0
        self._jobs_completed_date = datetime.now(timezone.utc).date().isoformat()
        self._client = AsyncLLMClient(
            api_key=config.llm_api_key,
            base_url=config.llm_api_base,
            model=config.llm_model_id or config.model_name or "gpt-4o",
            max_tokens=4096,
            temperature=0.1,
        )
        prm_url = config.prm_url or config.llm_api_base
        prm_model = config.prm_model or config.llm_model_id or config.model_name or "gpt-4o"
        prm_api_key = config.prm_api_key or config.llm_api_key
        self._prm_scorer = PRMScorer(
            prm_url=prm_url, prm_model=prm_model, api_key=prm_api_key,
            prm_m=max(1, int(getattr(config, "prm_m", 1) or 1)),
            temperature=float(getattr(config, "prm_temperature", 0.1) or 0.1),
            max_new_tokens=int(getattr(config, "prm_max_new_tokens", 512) or 512),
        )
        self._user_alias = config.sharing_user_alias or os.environ.get("USER", "anonymous")
```

Worker 持有**两个** LLM 客户端:
- `AsyncLLMClient`(主对话用的)—— 跑 replay
- `PRMScorer`(用主对话的 LLM,或 PRM 专用 LLM)—— 打分

### B. Idle 检测协议

```python
class IdleStateProvider(Protocol):
    def active_session_count(self) -> int: ...
    def last_request_age_seconds(self) -> Optional[float]: ...
    def is_idle_for_validation(self, idle_after_seconds: int) -> bool: ...
```

`api_server.SkillClawAPIServer` 实现了这个 Protocol。判定逻辑大致是:

```python
def is_idle_for_validation(self, idle_after_seconds):
    return (
        self._user_turn_counts.get_total_active() == 0    # 没有活跃 session
        and (time.time() - self._last_request_timestamp) > idle_after_seconds
    )
```

`force=True` 跳过 idle 检查,供 CLI `validation run-once --force` 使用。

### C. Replay 实现

```python
async def _run_replay_branch(self, case, skill, *, label):
    messages = self._build_replay_messages(case, skill)
    if not messages or messages[-1].get("role") != "user":
        raise ValueError("replay case missing user instruction")
    response_text = await self._client.chat(messages, max_tokens=2048, temperature=0.1)
    prm_result = await self._prm_scorer.evaluate(response_text, str(case.get("instruction", "")))
    normalized_score = self._normalize_replay_score(prm_result.get("score"))
    return {
        "label": label, "response_text": response_text,
        "prm_score": prm_result.get("score"),
        "normalized_score": normalized_score,
        "prm_votes": prm_result.get("votes", []),
    }
```

> **为什么 replay 用 `temperature=0.1` 而不是 evolve 通用 `0.4`**:Replay 评估的核心目的是"用 candidate skill 替换 baseline skill,看哪个 PRM 分更高"——输入是同一段历史 user instruction,要 reproduce 的是同一份语义输出,温度越低采样越稳定,candidate vs baseline 之间的对比噪声越小,判分越公平。Evolve 流水线用 `0.4` 是另一回事:那里 LLM 要"在多个可能改进方向里探索",需要一定随机性避免总收敛到同一种优化路径。完整 temperature 策略(为什么 `0.1` / `0.4` / `prm_temperature` 这几个数同时存在)见 [04.12 AsyncLLMClient](./04.12-evolve_server核心.md)。

`_normalize_replay_score` 把 PRM 的 {-1, 0, 1} 映射到 [0, 1]:

| PRM 原始 | normalized |
|---|---|
| -1 | 0.0 |
| 0 | 0.5 |
| 1 | 1.0 |
| 0.0(默认) | 0.5 |
| 其他范围 | 裁剪到 [0, 1] |

### D. Score 聚合逻辑

```python
async def _replay_validate_job(self, job):
    candidate = job["candidate_skill"]
    current = job.get("current_skill") if isinstance(job.get("current_skill"), dict) else None
    cases = job.get("replay_cases") or []
    
    candidate_scores, baseline_scores = [], []
    case_results = []
    
    for case in cases[:3]:    # 最多 3 个 case
        baseline = await self._run_replay_branch(case, current, label="baseline")
        candidate = await self._run_replay_branch(case, candidate, label="candidate")
        # ... 记录 + 累加
    
    candidate_mean = mean(candidate_scores)
    baseline_mean = mean(baseline_scores) if baseline_scores else 0.0
    threshold = job.get("min_score", 0.75)
    
    accepted = candidate_mean >= threshold and candidate_mean >= baseline_mean
    decision = "accept" if accepted else "reject"
    return {
        "validator_mode": "replay",
        "decision": decision,
        "accepted": accepted,
        "score": candidate_mean,
        "threshold": threshold,
        "reason": f"Replay validation: candidate={candidate_mean} baseline={baseline_mean} threshold={threshold}",
        "checks": {
            "grounded_in_evidence": candidate_mean,
            "preserves_existing_value": max(0, min(1, candidate_mean - baseline_mean + 0.5)),
            ...
        },
        "replay_summary": {
            "case_count": len(case_results),
            "baseline_mean_score": baseline_mean,
            "candidate_mean_score": candidate_mean,
            "cases": case_results,
        }
    }
```

`accepted` 需要同时满足:
1. `candidate_mean >= threshold`(默认 0.75)
2. `candidate_mean >= baseline_mean`(必须比当前线上版好)

第 2 条是关键——避免"两个都很差,但都 >= 0.75"被误判为 "accept"。

### F. `run_once` 与轮询循环

```python
async def run_once(self, *, force=False):
    summary = ValidationRunSummary()
    
    if not self._validation_enabled():
        summary.reason = "validation disabled or sharing not configured"
        return summary.__dict__
    if not self._quota_available():
        summary.reason = "daily validation quota reached"
        return summary.__dict__
    if not self._is_idle(force=force):
        summary.reason = "client is not idle"
        return summary.__dict__
    
    jobs = self._store.list_open_jobs(user_alias=self._user_alias)
    summary.checked_jobs = len(jobs)
    if not jobs:
        summary.reason = "no open validation jobs"
        return summary.__dict__
    
    for job in jobs:
        if not self._quota_available():
            summary.reason = "daily validation quota reached"
            break
        try:
            result = await self._validate_job(job)
        except Exception as exc:
            logger.warning("job %s failed: %s", job_id, exc)
            summary.skipped_jobs += 1
            continue
        
        self._store.save_result(job_id, self._user_alias, result)
        self._jobs_completed_today += 1
        summary.validated_jobs += 1
        if summary.validated_jobs >= self.config.validation_max_concurrency:
            break
    
    return summary.__dict__
```

`run` 协程周期性跑 `run_once`:

```python
async def run(self):
    interval = max(5, self.config.validation_poll_interval_seconds)
    while not self._stop_event.is_set():
        try:
            await self.run_once()
        except Exception:
            logger.warning("polling loop failed")
        try:
            await asyncio.wait_for(self._stop_event.wait(), timeout=interval)
        except asyncio.TimeoutError:
            continue
```

最小间隔 5s(防 busy loop)。

## 常见误区

1. **"validation 跟 PRM 是一回事"** —— **不是**(见 04.09)。
2. **"validation 必须开启才能用 SkillClaw"** —— **错**,默认关闭。`validation.enabled=false` 时,整个 ValidationWorker 不启动,不影响主流程。
3. **"client validation 失败会拒绝候选 skill"** —— 取决于配置。Evolve server 端 `validation_max_rejections=1` 时,**累计 N 个 reject 后**才 reject job;单 client reject 不直接 reject。
4. **"replay 用的是 client 配置的 LLM,不是 server 的"** —— **是**。`AsyncLLMClient` 配的是 client 自己的(`config.llm_api_base`)。这是设计选择:"每个 client 用自己信任的 LLM 评估"。
5. **"`force=True` 会跳过 idle 但会跑 quota 检查"** —— 仍跑 quota。`force=True` 只跳过 idle。
6. **"validation run-once 跟 validation run --continuous 是两个命令"** —— 对,前者单次,后者阻塞循环。
