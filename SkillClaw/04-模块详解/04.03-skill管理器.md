# 04.3 Skill 管理器 `skill_manager.py`

> 本地 skill 库的唯一入口。负责:扫描、解析、检索、效果统计、reload。

## 设计动机

SkillClaw 的 skill 文件格式是 **AgentSkills / OpenClaw 兼容**的:

```
skills/
└── <skill-name>/
    ├── SKILL.md           # YAML frontmatter + markdown body
    ├── scripts/           # 可选
    ├── references/        # 可选
    └── assets/            # 可选
```

`SKILL.md` 的 frontmatter 必须含 `name` + `description`,body 是 markdown 文本。SkillClaw 接受所有 OpenClaw / Pi coding-agent / AgentSkills 兼容的 skill 目录,**不**发明新格式。

`SkillManager` 的职责:把这些文件**加载**到内存,**检索** top-K 相关的,**统计**每次注入的效果,**重载**当文件变化时。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| `_parse_skill_md` | 解析单文件 frontmatter + body(校验 `name` + `description` 必填,保留未识别字段) | `skill_manager.py:53` |
| `SkillManager` | 本地 skill 库的主类,负责"扫描 + 解析 + 检索 + 效果统计 + reload" | `skill_manager.py:133` |
| `retrieval_mode` | 检索模式: `template`(按 effectiveness 排序,忽略任务描述,零成本)/ `embedding`(cosine sim 加权) | `skill_manager.py:143` |
| `skill_stats.json` | 注入 / 反馈统计(本地落盘,跟 skill 文件同目录便于打包) | `skill_manager.py:_stats_path` |
| `effectiveness` | `positive_count / inject_count` —— 0.0-1.0,默认 0.5(从未被评过),用于 template 模式排序和 embedding 加权 | `:230` |

| **PRM 反馈回路** | `record_injection`(`:222`)+ `record_feedback(score)(:243)` 形成的回路:每次注入 +1,PRM 返回 -1/0/1 后更新 effectiveness | 同左 |

## 实现要点

### A. Skill 目录扫描

```
def _skill_md_paths(self):
    if self._is_hermes_skill_root():
        # Hermes 用 category 子目录
        pattern = os.path.join(self._skills_dir, "**", "SKILL.md")
    else:
        # 标准:直接 skill-name/SKILL.md
        pattern = os.path.join(self._skills_dir, "*", "SKILL.md")
    return sorted(glob.glob(pattern))
```

`_is_hermes_skill_root` 让 SkillClaw **同时** 支持"标准结构"和"Hermes 的 category-prefixed 结构"。这是为了不打破用户已经有的 Hermes skill 库。

### B. Frontmatter 解析

`_parse_skill_md`(`:53`)做这几件事:

1. 校验文件以 `---` 开头,有 frontmatter 终止符 `\n---`
2. `yaml.safe_load` 解析 frontmatter
3. 校验 `name` + `description` 必填
4. 提取 category: 优先级 `metadata.skillclaw.category` > `category`(legacy)> `"general"`
5. 计算 sha256(name)[:12] 作为稳定 `id`
6. **保留所有未识别的 frontmatter 字段** 到 `_extra_frontmatter`,便于 round-trip 写回

这是 SkillClaw **不会**丢 OpenClaw 特有字段(`homepage`、`user-invocable` 等)的关键。

### C. 检索

#### Template 模式

```
def retrieve(self, task_description, top_k=6):
    if self.retrieval_mode == "embedding":
        return self._embedding_retrieve(task_description, top_k)
    
    # template 模式:全部 skill 按 effectiveness 排序,取前 top_k
    all_skills = list(self.skills["all_skills"])
    return sorted(all_skills, key=lambda s: self.get_effectiveness(s["name"]), reverse=True)[:top_k]
```

> 注意:template 模式**完全忽略 `task_description`**!它只按"历史效果好"排序。这是 SkillClaw 的"零成本默认",适合"skill 库小、可以全塞 prompt"的场景。

#### Embedding 模式

```
def _embedding_retrieve(self, task, top_k):
    cache = self._compute_skill_embeddings()
    query_emb = self._get_embedding_model().encode([task], normalize_embeddings=True)[0]
    sims = cache["embeddings"] @ query_emb     # cosine sim
    
    # 排序:similarity * (0.3 + 0.7 * effectiveness)
    ranked = sorted(range(len(sims)), 
                    key=lambda i: sims[i] * (0.3 + 0.7 * self.get_effectiveness(items[i]["name"])),
                    reverse=True)
    
    # 取 top-K*3 个候选,然后用 embedding 去重(阈值 0.9)
    candidates = ranked[:max(top_k * 3, top_k)]
    kept = self._deduplicate_by_embedding(candidates, cache, top_k, threshold=0.9)
    return [items[i] for i in kept]
```

设计点:
- **0.3 + 0.7 * effectiveness**:即便 effectiveness 极低,相似度本身仍有 0.3 的权重(避免冷启动 skill 永远不被用)
- **去重阈值 0.9**:很激进(只过滤近乎完全重复的 skill),保留变体
- **`top_k * 3` 候选池**:给去重留余量,避免 5 个全撞重后只留 2 个

### D. 效果统计

```
def record_injection(self, skill_names):
    for name in skill_names:
        self._stats.setdefault(name, {
            "inject_count": 0,
            "positive_count": 0,
            "negative_count": 0,
            "neutral_count": 0,
            "last_injected_at": "",
            "effectiveness": 0.5,
        })
        self._stats[name]["inject_count"] += 1
        self._stats[name]["last_injected_at"] = now
    
    # 每 10 次 mutation 批量写一次盘
    self._maybe_flush_stats()

def record_feedback(self, skill_names, score):
    """PRM 反馈:score ∈ {-1, 0, 1}"""
    for name in skill_names:
        if score > 0:   self._stats[name]["positive_count"] += 1
        elif score < 0: self._stats[name]["negative_count"] += 1
        else:           self._stats[name]["neutral_count"] += 1
        self._stats[name]["effectiveness"] = positive_count / inject_count
```

存储在 `<skills_dir>/skill_stats.json`,**每 10 次 mutation 批量写盘**(`_maybe_flush_stats`)。注意这里是**和 skill 文件同目录**,而不是 `~/.skillclaw/`。这是为了 "skill 文件夹可以单独打包带走" 的可移植性。

### E. 智能 Reload

```
def refresh_if_changed(self) -> bool:
    current = self._compute_skills_fingerprint()
    if current == self._skills_fingerprint:
        return False
    self.reload()
    self.generation += 1
    return True
```

`fingerprint` 是 `(realpath, mtime_ns, size)` 的元组列表,变了就 reload。**不会**在每次请求都重扫整个目录。

`api_server` 的 polling 后台任务周期性调 `refresh_if_changed`,这是"用户手动 `skillclaw skills push` 后,客户端能感知"的机制——前提是后端时间戳变化。

## 常见误区

1. **"skill 库是中心化数据库"** —— **不**。就是文件系统上的目录,每次访问都走 IO + 内存 cache。
2. **"skill name 必须 unique"** —— **是**。`_parse_skill_md` 不会去重,如果同一个名字出现两次,后扫到的会覆盖先扫到的(顺序按字母)。`push` 阶段会去重,但本地库不会。
3. **"skill description 是文档摘要"** —— **不**。description 是**触发条件描述**("Use when X, NOT for Y"),不是 skill body 的摘要。这是 `description` 在 frontmatter 里**作为 trigger context** 的设计——LLM 通过描述决定"这个 skill 现在是否相关"。
4. **"embedding 检索会更新 effectiveness"** —— **不会**。`record_injection` 一定会调,但 effectiveness 的更新需要 `record_feedback`(PRM 评分回调),见 03.02。
5. **"skill 修改会立刻被 SkillManager 看到"** —— **不**。需要 `refresh_if_changed` 被调用。`api_server` 后台 polling 周期默认多少要查 `config.sharing_skill_reload_interval_seconds`(`config.py:130`)。
6. **"skill 库是 Hermes 兼容的"** —— **是**,但 SkillClaw 加了 `metadata.skillclaw.category` 这个扩展。`openclaw.emoji` 这种是 OpenClaw 的标准字段,会原样保留。
