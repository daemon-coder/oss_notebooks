# 04.8 守护进程与启动链路

> SkillClaw 的"用户面"——CLI 命令、首次安装向导、守护进程 fork。

## 设计动机

`skillclaw` 是用户日常用的命令。它要支持:

- `skillclaw setup` —— 首次安装,交互式向导
- `skillclaw start` / `start --daemon` —— 启动代理
- `skillclaw stop` —— 停掉
- `skillclaw status` —— 看是否在跑
- `skillclaw config KEY VAL` —— 改配置
- `skillclaw skills pull/push/sync/list/list-remote` —— 共享 skill 管理
- `skillclaw doctor hermes` —— 诊断
- `skillclaw restore hermes` —— 回滚
- `skillclaw validation status/run-once` —— 后台验证
- `skillclaw dashboard sync/serve` —— 可视化

CLI 是单进程,但**代理本身**(`SkillClawAPIServer`)是常驻进程,所以有"前台启动 / 守护进程 fork"的二选一。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| `cli.py` | Click 实现的 CLI 入口(`skillclaw` 命令组) | 全文件(950 行) |

## 实现要点

### A. CLI 派发(`cli.py`)

`cli.py` 用 Click 实现,主命令是 `skillclaw`(由 `pyproject.toml:32` 映射到 `cli:skillclaw`)。

```python
@click.group()
def skillclaw():
    """SkillClaw: Claw agent skill injection and auto-evolution."""
    pass

@skillclaw.command()
def setup():
    """Run the interactive setup wizard."""
    SetupWizard().run()

@skillclaw.command()
@click.option("--port", type=int, default=None)
@click.option("--daemon", is_flag=True, default=False)
def start(port, daemon):
    """Start the SkillClaw proxy."""
    if daemon:
        _spawn_daemon(port)
    else:
        _run_foreground(port)

@skillclaw.command()
def stop():
    """Stop a running SkillClaw instance."""
    pid = _read_pid()
    if pid and _is_process_alive(pid):
        os.kill(pid, signal.SIGTERM)
    _clear_pid()

@skillclaw.command()
def status():
    """Check whether SkillClaw is running."""
    pid = _read_pid()
    if not pid:
        click.echo("not running")
        return
    if not _is_process_alive(pid):
        click.echo(f"stale pid ({pid})")
        return
    click.echo(f"running (pid={pid})")
```

子命令组:`config` / `skills` / `validation` / `dashboard` / `doctor` / `restore` 都是 group + subcommand 形式。

### B. 守护进程 spawn(`_spawn_daemon_process`)

```python
def _spawn_daemon_process(port, log_file, effective_port):
    log_path = _default_daemon_log_path()    # ~/.skillclaw/skillclaw.log
    log_path.parent.mkdir(parents=True, exist_ok=True)
    
    with runtime_state.daemon_start_lock():    # 文件锁,避免并发 start
        _ensure_daemon_not_running()
        
        cmd = [sys.executable, "-m", "skillclaw", "start"]
        if port:
            cmd.extend(["--port", str(port)])
        
        with log_path.open("ab") as log_handle:
            child_env = os.environ.copy()
            child_env["SKILLCLAW_RUNTIME_KIND"] = "daemon"
            child_env["SKILLCLAW_RUNTIME_LOG_PATH"] = str(log_path)
            popen_kwargs = {
                "stdin": subprocess.DEVNULL,
                "stdout": log_handle,
                "stderr": subprocess.STDOUT,
                "close_fds": True,
                "env": child_env,
            }
            if os.name == "nt":
                popen_kwargs["creationflags"] = ...DETACHED_PROCESS...
            else:
                popen_kwargs["start_new_session"] = True    # setsid,脱离父进程
            
            proc = subprocess.Popen(cmd, **popen_kwargs)
        
        _wait_for_daemon_ready(proc, effective_port, log_path)
```

要点:
- **POSIX 用 `start_new_session=True`** —— `setsid` 让子进程脱离父进程的进程组,父进程退出不影响子进程
- **Windows 用 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`** —— 类似效果
- **`daemon_start_lock` 文件锁** —— 防止两个 `skillclaw start --daemon` 同时跑

### C. 守护进程就绪检查

```python
def _wait_for_daemon_ready(proc, port, log_path, timeout_s=15.0):
    deadline = time.monotonic() + timeout_s
    while time.monotonic() < deadline:
        returncode = proc.poll()
        if returncode is not None:
            raise click.ClickException(f"daemon exited with code {returncode}. Check logs: {log_path}")
        if _healthz_ready(port):
            return
        time.sleep(0.2)
    raise click.ClickException(f"daemon did not become healthy in {timeout_s}s. Check logs: {log_path}")

def _healthz_ready(port, timeout=0.5):
    try:
        with urllib.request.urlopen(f"http://127.0.0.1:{port}/healthz", timeout=timeout) as resp:
            payload = json.loads(resp.read())
            return resp.status == 200 and payload.get("ok") is True
    except Exception:
        return False
```

`SKILLCLAW_DAEMON_READY_TIMEOUT_S` 环境变量可调超时(默认 15s)。

### D. 守护进程内部(子进程跑什么)

`cli.py` 里的 `start` 命令也响应子进程的"无 `--daemon`"调用(子进程就是这样被 spawn 的):

```python
@skillclaw.command()
@click.option("--port", type=int, default=None)
@click.option("--daemon", is_flag=True, default=False)
def start(port, daemon):
    if daemon:
        _spawn_daemon(port)
        return
    
    # 前台 / 守护子进程路径
    from .launcher import SkillClawLauncher
    
    config = ConfigStore().to_skillclaw_config()
    if port:
        config.proxy_port = port
    
    launcher = SkillClawLauncher(config)
    launcher.run()    # 阻塞,直到 SIGTERM
```

### E. `SkillClawLauncher`(`launcher.py`)

```python
class SkillClawLauncher:
    def __init__(self, config):
        self.config = config
    
    def run(self):
        from .api_server import SkillClawAPIServer
        server = SkillClawAPIServer(self.config)
        server.start()     # 启 uvicorn(可能是另一线程)
        try:
            self._wait_for_signal()
        finally:
            server.stop()
    
    def _wait_for_signal(self):
        stop = threading.Event()
        def handler(signum, frame):
            stop.set()
        signal.signal(signal.SIGTERM, handler)
        signal.signal(signal.SIGINT, handler)
        stop.wait()    # 阻塞主线程
```

设计:**主线程等信号,工作线程跑 uvicorn**。`SIGTERM` / `SIGINT` 都触发优雅停止。

### G. `runtime_state.py`(PID 文件)

```python
import fcntl

def daemon_start_lock():
    """文件锁,防止并发 start"""
    lock_path = Path.home() / ".skillclaw" / "start.lock"
    lock_path.parent.mkdir(parents=True, exist_ok=True)
    f = lock_path.open("w")
    fcntl.flock(f.fileno(), fcntl.LOCK_EX)    # POSIX 文件锁
    return f    # 调用方持锁期间,其他 start 阻塞

def read_pid():
    pid_file = Path.home() / ".skillclaw" / "skillclaw.pid"
    if not pid_file.exists():
        return None
    try:
        return int(pid_file.read_text().strip())
    except (ValueError, OSError):
        return None

def process_alive(pid):
    try:
        os.kill(pid, 0)    # 信号 0 不发,只检测存在性
    except ProcessLookupError:
        return False
    except PermissionError:
        return True    # 进程存在但不是我们的用户
    return True

def clear_pid():
    pid_file = Path.home() / ".skillclaw" / "skillclaw.pid"
    pid_file.unlink(missing_ok=True)

def clear_pid_if_matches(pid):
    if read_pid() == pid:
        clear_pid()
```

`daemon_start_lock` 是**阻塞锁**,同一时间只能有一个 `start --daemon` 在跑。

### H. 守护进程日志

守护进程 stdout/stderr 重定向到 `~/.skillclaw/skillclaw.log`(append 模式)。这是用户排查问题的唯一窗口:

```bash
tail -f ~/.skillclaw/skillclaw.log
```

`_SKILLCLAW_RUNTIME_LOG_PATH` 环境变量让子进程知道自己写到哪儿(便于多实例管理,但当前不真正支持多实例)。

## 常见误区

1. **"`skillclaw start` 是阻塞命令"** —— 看 `--daemon`。`start` 前台阻塞运行(直到 SIGTERM);`start --daemon` fork 后立刻返回。
2. **"`stop` 是软停止"** —— 是。发 SIGTERM,子进程走 `_shutdown_cleanup`,最多 15s 内退出。**不**发 SIGKILL。
3. **"`status` 显示 running 但实际没响应"** —— 是 stale PID。`start` 检测到 stale PID 会自动清掉,但 `status` 命令不会。可以 `kill <pid>` 后 `skillclaw start`。
4. **"Setup wizard 可以重做"** —— 可以,但**不**会回滚旧 config,是**覆盖式**合并。已存在的字段保留,新 wizard 写入的字段覆盖 default(不覆盖已有)。
5. **"`skillclaw-evolve-server` 用同样的 CLI"** —— **不**。Evolve server 用 `argparse`(`evolve_server/__main__.py`),不是 Click。
6. **"LaunchSkillClaw 是 unix-only 概念"** —— **不是**。`_spawn_daemon_process` 有 Windows 分支(用 `DETACHED_PROCESS`),但 `start_new_session=True` 在 POSIX 上的语义不完全等同于 Windows 的 detached。
