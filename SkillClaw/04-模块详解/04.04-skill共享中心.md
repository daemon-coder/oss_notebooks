# 04.4 Skill 共享中心

> `SkillHub` + `object_store.py` + 服务端 `storage/oss_helpers.py` —— 同一套语义,3 个文件,实现"本地 ↔ 共享对象存储"的双向同步。

## 设计动机

共享后端需要支持 4 种形态:本地目录、AWS S3、阿里云 OSS、Nacos Skill Registry。前 3 个用同一套 key-value 模型(只是库不同),Nacos 是不同的 API。

`object_store.py` 是抽象的"key-value 存储":
- `put_object(key, data) / get_object(key) / iter_objects(prefix) / delete_object(key)`

`skill_hub.py` 是高层语义:
- `pull_skills(local_dir)` / `push_skills(local_dir)` / `list_remote()`

Nacos 后端**绕过**了 `object_store` 抽象,有自己的 `NacosSkillHub` 子类(见 04.05)。

## 实现要点

### A. ObjectStore 抽象

四个方法 + 一个迭代器:

```python
class ObjectStore(Protocol):
    def put_object(self, key: str, data: bytes) -> None: ...
    def get_object(self, key: str) -> bytes: ...                    # raises FileNotFoundError
    def iter_objects(self, prefix: str) -> Iterator[ObjectInfo]: ...
    def delete_object(self, key: str) -> None: ...
```

实现细节:

- **LocalObjectStore**:`put_object` 走 `pathlib.Path.write_bytes`;`iter_objects` 走 `os.walk`(递归,生成相对 prefix 的 key)。**没有**处理符号链接。
- **S3ObjectStore**:基于 boto3 `put_object` / `get_object` / `list_objects_v2` / `delete_object`。`is_not_found_error` 捕获 `ClientError` 404。
- **OSSObjectStore**:基于 oss2,接口类似 S3。
- `normalize_backend(backend, endpoint, local_root)`:后端字符串归一化,空值时按 `local_root` → `local`、按 endpoint 字符串 → `oss` 或 `s3`。

### B. SkillHub 构造与工厂

```python
class SkillHub:
    def __init__(self, *, backend, endpoint, bucket, access_key_id, 
                 secret_access_key, region, session_token, local_root, group_id, user_alias):
        self._bucket = build_object_store(backend=backend, ...)
        ...

    @classmethod
    def from_config(cls, config):
        sharing_backend = (config.sharing_backend or "").lower()
        skill_backend = (config.sharing_skill_backend or "").lower() or sharing_backend
        if skill_backend == "nacos":
            from .nacos_skill_hub import NacosSkillHub
            return NacosSkillHub.from_config(config)        # ← 切换实现
        return cls(backend=skill_backend, ...)

    @classmethod
    def object_storage_from_config(cls, config):
        """和 SkillHub 平行,但只服务会话/验证,不走 skill 资产。"""
        ...
```

**两个工厂方法**:
- `from_config` → 返回用于 **skill 资产** 的 hub(可能走 Nacos)
- `object_storage_from_config` → 返回用于 **session 录制 + 验证 job** 的 hub(必须走 object store)

这种拆分的目的是:`skill_backend=nacos` 时,技能资产走 Nacos 的 lifecycle 协议,但 session 和 validation 还是走对象存储。

### C. Push 实现细节

```python
def push_skills(self, local_dir):
    manifest = self._load_remote_manifest()
    
    for skill in scan_local(local_dir):
        name = skill["name"]
        bundle = read_skill_bundle(skill["dir"])
        tree_sha = bundle_tree_sha256(bundle)
        
        record = manifest.get(name)
        if record and record["tree_sha256"] == tree_sha:
            continue        # 增量跳过
        
        # 上传所有文件
        for rel_path, content in bundle.items():
            key = self._skill_bundle_key(name, rel_path)
            self._bucket.put_object(key, content)
        
        # 清理云端存在但本地已删除的额外文件
        if record:
            self._delete_remote_bundle_extras(name, keep_paths=bundle.keys())
    
    # 写新 manifest
    new_manifest = self._build_manifest_from_local(local_dir)
    save_manifest(self._bucket, self._prefix, new_manifest)
    
    return {"pushed": ..., "skipped": ...}
```

`_skill_bundle_key`:
- `SKILL.md` → `{prefix}skills/{name}/SKILL.md`
- 其他 → `{prefix}skills/{name}/files/{rel_path}`

### D. Pull 实现细节

```python
def pull_skills(self, local_dir, skip_names=None):
    remote_manifest = self._load_remote_manifest()
    remote_names = set(remote_manifest.keys())
    local_names = {p.name for p in scan_local(local_dir)}
    
    backup_root = self._create_local_backup(local_dir)
    
    try:
        for name in remote_names - (skip_names or set()):
            record = remote_manifest[name]
            bundle = self._download_skill_bundle(name, record)
            write_skill_bundle(os.path.join(local_dir, name), bundle)
        
        # 可选:删除 local-only(默认不删)
        for name in local_names - remote_names:
            if self._delete_local_only:
                shutil.rmtree(os.path.join(local_dir, name))
        
        return {"downloaded": N, "skipped": M, "failed": K, "deleted": D, ...}
    except Exception:
        self._restore_local_backup(backup_root, local_dir)
        raise
```

**关键**:整个 pull 包在 try/except 里,失败回滚到 backup。backup 目录是 `~/.skillclaw/backups/skills/<timestamp>/`。

### E. 服务端 storage/oss_helpers.py

`evolve_server/storage/oss_helpers.py` 是给 `EvolveServer` 用的"工具函数集",跟 `SkillHub` 是平行关系,但 API 形态不同:

```
# 工具函数(无 class)
list_session_keys(bucket, prefix)        # 列 sessions/<user>/<sid>.json
list_object_keys(bucket, prefix)         # 列 prefix 下所有 key
read_json_object(bucket, key)            # 读 + parse
load_manifest(bucket, prefix)            # 读 manifest
save_manifest(bucket, prefix, manifest)  # 写 manifest(jsonl)
delete_session_keys(bucket, keys)        # 删多条
fetch_skill_content(bucket, prefix, name)
fetch_skill_bundle(bucket, prefix, name, record)   # 读 SKILL.md + files
save_version_bundle(bucket, prefix, name, version, bundle)
fetch_version_bundle(bucket, prefix, name, version)
```

`mock_bucket.py` 是 `OSSObjectStore` 的"本地文件版",`--mock` 模式下替代真实 OSS/S3。

### F. SKILL bundle 的辅助(`skill_bundle.py`)

- `bundle_tree_sha256(files)`:对文件 dict 按 key 排序后拼接 hash
- `read_skill_bundle(skill_dir)`:递归读 `<dir>/*` 全部文件,过滤 `__pycache__`、`.git` 等
- `write_skill_bundle(skill_dir, files)`:原子写(先写临时文件再 rename)
- `coerce_skill_bundle(files)`:dict → `{str: bytes}`,处理 `str` 编码

`is_ignored_bundle_rel_path` 决定哪些路径不打包(如 `.DS_Store`、`__pycache__`、`.git` 等)。

## 常见误区

1. **"`SkillHub` 和 `oss_helpers` 是同一份代码"** —— **不**。`SkillHub` 是**客户端**的面向"本地 skill 库"的高层 API;`oss_helpers` 是**服务端**的"在 bucket 上做操作"的纯函数集。它们功能重叠(都能读 manifest),但抽象层级和使用场景不同。
2. **"object_store 接口能直接用 Nacos"** —— **不**。Nacos 没有 put_object / get_object 语义,它的"key-value"是 zip 包。所以 Nacos 走 `NacosSkillHub`,**绕开** object_store。
3. **"manifest 是 append-only log"** —— **不**。`save_manifest` 是 read-modify-write,最后整体覆盖写一次。
4. **"pull 之后立刻能用"** —— 见 04.03,还要 `SkillManager.refresh_if_changed`。
5. **"bundle_tree_sha256 == sha256(SKILL.md)"** —— **不**。前者是**所有文件**按 `path:bytes` 排序后整体的 sha256。如果 skill 有 `scripts/run.sh`,改了这个文件但不改 SKILL.md,tree_sha 也会变。
6. **"S3ObjectStore / OSSObjectStore 能跨账号"** —— **能**,只要 `access_key_id` / `secret_access_key` 有权限。`role_arn` / 临时 token 这些走 `session_token` 字段。
