# 04.6 Agent 框架适配层 `claw_adapter.py`

> 让 12 种不同的 Agent 框架"把 LLM 请求发到 SkillClaw 代理"。不改 Agent 代码,只改它们的配置文件。

## 设计动机

SkillClaw 想要"插在所有 LLM Agent 前面",但每个 Agent 框架的配置文件格式、修改方式、运行时重启机制都不一样。`claw_adapter.py` 解决这件事:

1. **统一入口** `configure_claw(cfg)` —— 根据 `cfg.claw_type` 派发到对应实现。
2. **不改 Agent 代码** —— 只动它的 config / 重启它的服务。
3. **可逆** —— 改之前会 backup,`restore_<claw>_config` 可以回滚。
4. **新增 Agent 容易** —— 加一个 `_configure_<name>(cfg)` + 注册到 `_ADAPTERS` 即可。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| **Agent 框架(Claw)** | 跟 LLM 对话的 client 端,如 Hermes / Codex / Claude Code / OpenClaw;每个框架有自己的配置文件格式和"上游 base URL"配置机制 | 01 |
| `claw_type` | `config.py` 里的 Agent 框架标识,12 种: `openclaw` / `opencode` / `hermes` / `codex` / `claude` / `qwenpaw` / `ironclaw` / `picoclaw` / `zeroclaw` / `nanoclaw` / `nemoclaw` / `none` | `config.py:88` |
| `configure_claw` | 统一入口,根据 `cfg.claw_type` 派发到对应 `_configure_<name>` | `claw_adapter.py:66` |
| `_ADAPTERS` | 派发表: `{claw_type: 适配函数}`,模块底部 12 个 key(详见下方"支持的 Agent 清单") | `claw_adapter.py`(模块底部) |
| `_configure_openclaw` / `_configure_hermes` / ... | 各 Agent 实现 | 文件内函数 |

| `_upsert_top_level_toml_keys` | TOML patch 工具(不用 toml 解析器,字符串操作) | `claw_adapter.py:292` |

## 支持的 Agent 清单

| `claw_type` | Agent | 改的配置文件 | 注入方式 |
|---|---|---|---|
| `openclaw` | OpenClaw | (无文件,直接 CLI) | `openclaw config set ...` + `openclaw gateway restart` |
| `opencode` | OpenCode | `~/.config/opencode/opencode.json` | patch JSON,注册 skillclaw provider |
| `hermes` | Hermes | `~/.hermes/config.yaml` | patch YAML,设 base_url → proxy |
| `codex` | Codex | `~/.codex/config.toml` + `skillclaw.config.toml` | 新增 opt-in profile |
| `claude` | Claude Code | `~/.claude/settings.json` | patch JSON,设 ANTHROPIC_BASE_URL |
| `qwenpaw` | QwenPaw | model config | patch 配置文件,设 active model |
| `ironclaw` | IronClaw | `~/.ironclaw/.env` | patch env,`ironclaw service restart` |
| `picoclaw` | PicoClaw | `~/.picoclaw/config.json` | patch model_list + gateway restart |
| `zeroclaw` | ZeroClaw | `~/.zeroclaw/config.toml` | patch + service restart |
| `nanoclaw` | NanoClaw | `.env` (ANTHROPIC_BASE_URL) | patch env,launchd/systemd restart |
| `nemoclaw` | NemoClaw | OpenShell 注册 | 注册 skillclaw provider,设 inference route |
| `none` | (不配置) | (不写) | 跳过 |

> **12 种 Agent 框架的协议面**——这 12 个 Agent 并不是"对等"地接入 SkillClaw,在**协议面**上可以分 3 类。理解这张表有助于"接入新 Agent 时该往哪个方向改":

| 协议面类型 | Agent | 接入方式 | SkillClaw 内部处理 |
|---|---|---|---|
| **OpenAI 兼容(`/v1/chat/completions`)** | `openclaw` / `opencode` / `hermes` / `codex` / `qwenpaw` / `ironclaw` / `picoclaw` / `zeroclaw` / `nemoclaw` | 把 Agent 的 `base_url` 指向 SkillClaw 代理的 `http://127.0.0.1:<port>/v1`;Agent 用 OpenAI chat-completions 协议发请求 | SkillClaw 几乎**不**做协议转译,直接转给上游 LLM |
| **Anthropic-native(`/v1/messages`)** | `claude` (Claude Code) / `nanoclaw` | 改 `ANTHROPIC_BASE_URL` env 指向 SkillClaw;Agent 仍发 Anthropic `/v1/messages` | SkillClaw 把 Anthropic body **转译**为 OpenAI body(`_anthropic_to_openai_body`,`api_server.py:1094`),再转给 OpenAI 兼容的上游 LLM |
| **其他/特殊** | `opencode` 的 provider block 注册 | patch JSON 注册 skillclaw 为一个 custom provider | 视 Agent 而定 |
| **N/A** | `none` | 跳过(用户手动配置 Agent) | 不介入 |

**这张表的"为什么重要"**:

- 想支持**新的 OpenAI 兼容 Agent** —— 加一个 `_configure_<name>(cfg)`,基本只改 Agent 的 base_url 字段,SkillClaw 内部不需改。
- 想支持**新的 Anthropic-native Agent** —— 加一个 `_configure_<name>(cfg)`,设 `ANTHROPIC_BASE_URL`;SkillClaw 自动把 Anthropic body 转 OpenAI,**前提**是你的上游 LLM 是 OpenAI 兼容的(可以是 Claude via LiteLLM / Bedrock / Anthropic-compat proxy)。
- 想让 Agent 真正发到 **Anthropic 上游** —— 当前 SkillClaw 默认都转给 OpenAI 兼容上游;要走真 Anthropic 上游,需要在 04.02 协议适配层加反向转译(`_anthropic_to_openai_body` 的逆操作)。

## 实现要点

### A. 派发逻辑

```python
def configure_claw(cfg):
    claw = cfg.claw_type
    if not cfg.configure_openclaw:   # 向后兼容字段
        claw = "none"
    adapter = _ADAPTERS.get(claw)
    if adapter is None:
        logger.warning("Unknown claw_type=%r — skipping auto-configuration", claw)
        return
    adapter(cfg)


_ADAPTERS: dict[str, Callable[["SkillClawConfig"], None]] = {
    "openclaw": _configure_openclaw,
    "hermes": _configure_hermes,
    "codex": _configure_codex,
    "claude": _configure_claude,
    "opencode": _configure_opencode,
    "qwenpaw": _configure_qwenpaw,
    "ironclaw": _configure_ironclaw,
    "picoclaw": _configure_picoclaw,
    "zeroclaw": _configure_zeroclaw,
    "nanoclaw": _configure_nanoclaw,
    "nemoclaw": _configure_nemoclaw,
    "none": _configure_none,    # no-op
}
```

### B. 通用工具

**原子写**:所有 patch 都用"先写临时文件 + fsync + os.replace"。原因:Agent 在运行时可能正在读这个文件,中途写一半会让 Agent 解析失败。

```python
def _write_yaml_mapping_atomic(path, data, label):
    path.parent.mkdir(parents=True, exist_ok=True)
    with tempfile.NamedTemporaryFile(mode="w", dir=path.parent, prefix=f".{path.name}.", delete=False) as handle:
        tmp_path = Path(handle.name)
        handle.write(yaml.safe_dump(data, sort_keys=False, allow_unicode=True))
        handle.flush()
        os.fsync(handle.fileno())
    os.replace(tmp_path, path)
```

**Backup**:任何 patch 之前,如果原文件存在,会 copy 到 `~/.skillclaw/backups/<claw>/<timestamp>.<suffix>`。`restore_<claw>_config(backup_path=None)` 接受可选 backup 路径,无参时取"最近一次"。

**TOML 工具**:`_upsert_top_level_toml_keys(text, updates)` 不引入 toml 解析器依赖,直接用字符串操作做"插/改顶层 key"。这够用,而不需要完整 TOML 解析。

### C. Hermes 适配(最复杂的一个)

```python
def _configure_hermes(cfg):
    config_path = Path.home() / ".hermes" / "config.yaml"
    data = _load_yaml_mapping(config_path, "hermes")
    
    # 1. 把 SkillClaw 加为 provider
    data.setdefault("providers", {})["skillclaw"] = {
        "type": "openai",
        "base_url": f"http://127.0.0.1:{cfg.proxy_port}/v1",
        "api_key": cfg.proxy_api_key or "skillclaw",
        "model": cfg.served_model_name,
    }
    
    # 2. 设默认 model
    data.setdefault("model", {})["primary"] = f"skillclaw/{cfg.served_model_name}"
    
    # 3. Backup + 原子写
    _backup_hermes_config_if_changed(config_path, new_text)
    _write_yaml_mapping_atomic(config_path, data, "hermes")
    
    # 4. 准备 skill 目录
    _prepare_hermes_skills_dir(cfg)    # ~/.hermes/skills/ + 从 ~/.skillclaw/skills 复制缺失的
```

`_prepare_hermes_skills_dir` 处理一个迁移问题:用户原来用 `~/.skillclaw/skills/`,现在改用 Hermes,需要把已有 skill 复制到 `~/.hermes/skills/`(Hermes 默认结构是 `<category>/<name>/SKILL.md`,见 04.03 的 `_is_hermes_skill_root`)。

### D. Codex 适配(profile 模式)

Codex 用 `config.toml` 配置文件,但 SkillClaw **不**直接改主 config,而是**新写一个** `~/.codex/skillclaw.config.toml`:

```toml
[providers.skillclaw]
type = "openai"
base_url = "http://127.0.0.1:30000/v1"
api_key = "skillclaw"

[profiles.skillclaw]
provider = "skillclaw"
model = "skillclaw-model"
```

用户需要**显式**在启动 Codex 时选这个 profile(`codex --profile skillclaw ...`)——这是 Codex 的"opt-in"模型,SkillClaw 不强制覆盖用户主配置。

### E. Claude 适配(改 base URL)

```python
def _configure_claude(cfg):
    settings_path = Path.home() / ".claude" / "settings.json"
    data = _load_json_mapping(settings_path, "claude")
    data["env"] = data.get("env", {})
    data["env"]["ANTHROPIC_BASE_URL"] = f"http://127.0.0.1:{cfg.proxy_port}"
    _write_json_mapping_atomic(settings_path, data, "claude")
```

Claude Code 通过 `ANTHROPIC_BASE_URL` env 变量切换上游;SkillClaw 直接改 `settings.json` 的 `env` 块,Claude Code 启动时读这个。

### F. inspect_hermes_config / restore_hermes_config

诊断命令 `skillclaw doctor hermes` 调 `inspect_hermes_config(cfg)`:

```python
def inspect_hermes_config(cfg):
    """返回 dict,描述:
    - Hermes config 是否指向 SkillClaw 代理
    - 预期 model / base_url / 当前 model / base_url
    - 是否有 mismatch

    - legacy ~/.skillclaw/skills 是否还有内容

    """
```

`restore_hermes_config(backup_path=None)` 把 Hermes config 回滚到 backup。可选 backup 路径;无参时取最近的 backup。

## 常见误区

1. **"`configure_claw` 只在 setup 时调一次"** —— **不**。`skillclaw start` 也会调(每次启动时确保 Agent 配置正确),`setup` 主要用于首次配置 + setup wizard 引导。
2. **"所有 claw 都用同一个 base_url 模式"** —— 几乎,但 Anthropic-based 的 Agent(Claude、NanoClaw)是改 `ANTHROPIC_BASE_URL`,OpenAI-based 的(Codex、QwenPaw)是改 provider 配置,**不是简单的统一替换**。
3. **"Codex 是强制覆盖"** —— **不**,是 opt-in profile,见 4.D。
4. **"claw_adapter 跟 SkillClaw 的协议层耦合"** —— **不**。claw_adapter 只改 base_url 指向代理,代理层(04.01)负责协议细节。
5. **"要新增一个 Agent,改什么?"** —— 实现 `_configure_<name>(cfg)` + 加到 `_ADAPTERS`。如果该 Agent 的 config 是 JSON/YAML/TOML,直接用通用工具;如果是自定义格式,自己加。
6. **"`skillclaw doctor` 是个配置校验器"** —— 部分。它只对**已经实现的** claw(目前是 hermes)做 inspect。其他 claw 没有 inspect,所以 doctor 不会报错但也不会诊断它们。
