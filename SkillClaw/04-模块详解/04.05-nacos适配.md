# 04.5 Nacos Skill Registry 适配 `nacos_skill_hub.py`

> 当 `sharing.skill_backend=nacos` 时,SkillClaw 不再走 OSS/S3 的 object store 协议,改用 Nacos 自身的 skill lifecycle API。

## 背景:Nacos Skill Registry 是什么(与对象存储的核心差异)

**Nacos** 是 Alibaba 开源的服务发现 + 配置中心。Nacos 3.x 在原有"服务注册/配置中心"之外,新增了**Skill Registry** 子系统,专门管理 AI agent 的 skill 资产(版本、状态机、审核流、客户端拉取 API)。**Nacos Skill Registry 不是"对象存储"**——它没有"放一个文件、读一个文件"的 key-value 语义,而是"管理一份带状态机的版本化资产":

- **核心差异**(对比 04.4 的 OSS/S3 模型):
  - **OSS/S3 模型**:每个 skill = 一组 key(`skills/<name>/SKILL.md` 等)+ 一个 manifest 文件。**没**有"状态",改写即覆盖。
  - **Nacos 模型**:每个 skill = 一个 name 下的多个 version,每个 version 有状态(`working` / `reviewing` / `published`)+ label(默认 `latest`)+ 完整的 zip 包。**有**状态机,改写要"先 submit → 审核 → publish"。
- **为什么要单独适配**:Nacos 的 `getSkill` 行为跟 `object_store.get_object` 完全不同(Nacos 走 HTTP 协议 + JSON,带审核管线等待;OSS 走 HTTP GET 拿 bytes)。强行套 `ObjectStore` 抽象会丢掉 Nacos 的"审核/版本回滚/label 切换"等能力,所以 SkillClaw 写了一个**绕过 `ObjectStore` 的独立实现** `NacosSkillHub`,但**对外**保持跟 `SkillHub` 一样的 `pull_skills` / `push_skills` / `list_remote` 接口,让上层代码无感切换。
- **谁需要这一章**:已经用 OSS / S3 的人**不需要**读这一章;只有当 `sharing.skill_backend=nacos` 才需要。

> 关键术语:`working` 版本(可编辑、未发布)= Nacos 中"草稿"状态;`published` 版本(已发布、只读)= Nacos 中"线上"状态;`latest` label = 指向当前 published 版本的指针(类似 GitHub 的 `latest` release tag)。Nacos 端管版本号(递增),客户端的"下一个版本"算法见 `nacos_versions.py`。

## 设计动机

Nacos 3.x 提供了**专门的 skill 管理 API**,具备:

- 命名空间 + 版本控制(Nacos 端管版本号)
- `working` / `published` 两种版本状态
- `latest` 标签切换
- `submit` + `review` + `publish` 审核流程
- 客户端的 `getSkill` 接口会等审核管线批准后才返回

这套 API 比"把 skill 塞进 OSS 的 `{prefix}skills/{name}/SKILL.md`"更安全:有审核、有版本回滚、有状态机。

SkillClaw 适配 Nacos 的方式是:**保留与 `SkillHub` 相同的对外接口**(pull / push / list_remote),**内部实现换成 Nacos API 调用**。这样上层代码(`api_server`、`cli` 的 `skills pull/push`)不用改。

## 实现要点

### A. HTTP 客户端(同步,不是异步)

```python
class NacosSkillClient:
    def __init__(self, *, server, namespace_id="public", access_token="", 
                 username="", password="", timeout=30.0, transport=None):
        self._client = httpx.Client(timeout=timeout, transport=transport)
        if not access_token and username and password:
            self._login()    # POST /v1/auth/login → accessToken
        ...
```

> 注意:跟 `prm_scorer.AsyncLLMClient` 不同,这里是**同步** httpx.Client。Nacos 适配的代码路径(上传 zip、查版本)在 evolve server 的 `await self._call_storage(...)` 里被包成 sync → async,见 03.04。

### B. 关键 API 调用

| Nacos 端点 | 用途 | 代码 |
|---|---|---|
| `POST /v1/auth/login` | 用户名/密码 → accessToken | `_login()` |
| `GET /v1/ai/skills/{name}` | 列 skill 的所有版本 | `list_skills` |
| `GET /v1/ai/skills/{name}/versions/{version}` | 查版本详情 | `get_skill` |
| `POST /v1/ai/skills/{name}/versions/{version}/upload` | 上传 zip | `upload_skill_zip` |
| `GET /v1/ai/skills/{name}/versions/{version}/download` | 下载 zip | `download_skill_zip` |
| `POST /v1/ai/skills/{name}/versions/{version}/submit` | 提交审核 | `submit` |
| `POST /v1/ai/skills/{name}/versions/{version}/publish` | 发布 | `publish` |

`_unwrap_json` 统一处理响应:读 `data` 字段,校验 `code`(0/200 才算成功)。

### C. Skill 上传(push 路径)

```python
def push_skill(self, name, bundle_files):
    # 1. 查远端是否已存在 working 版本
    record = self._load_remote_skill_record(name) or {}
    detail = self.get_skill(name) if record else {}
    working = _nacos_working_version(record, detail)
    
    if working:
        # 已有 working 版本:下载 → 跟本地 bundle 对比
        status, version = working
        remote_bundle = self._download_skill_zip(name, version, admin=True)
        if _bundle_matches_remote(bundle_files, remote_bundle):
            return "skipped_existing_working"
        return "skipped_existing_working"   # 一律跳过,不覆盖
    
    # 2. 没有 working 版本:算下一个版本号,上传
    target_version = _next_version(record, detail)    # 见 nacos_versions.py
    zip_bytes = _bundle_to_nacos_zip(name, bundle_files)
    self.upload_skill_zip(zip_bytes=zip_bytes, filename=f"{name}-{target_version}.zip",
                          overwrite=True, target_version=target_version)
    
    # 3. 根据 publish_mode 走不同后续路径
    if publish_mode in {"review", "direct"}:
        self.submit(name, target_version)
    if publish_mode == "direct":
        confirmed = self._wait_nacos_publish(name, target_version, timeout=30)
    return "uploaded_pending_publish" if not confirmed else "uploaded"
```

**关键约束**:
- **从不覆盖已有 working 版本**(只跳过)—— 设计上避免"用户改了一半被 evolve server 覆盖"
- **下一个版本号算法** 见 `nacos_versions.py:_next_version`——支持 semver (`1.2.3`)和 `v<N>` 两种格式
- **publish 等待**(`_wait_nacos_publish`):Nacos v3 跑异步审核管线,evolve server 轮询 `labels["latest"] == version` 确认

### D. Skill 拉取(pull 路径)

```python
def pull_skill(self, name, record):
    # 优先 working,其次 published label(默认 "latest")
    working = _nacos_working_version(record, self.get_skill(name))
    if working:
        _status, version = working
        zip_bytes = self.download_skill_zip(name, version, admin=True)
    else:
        label = self.config.nacos_label or "latest"
        version = _nacos_published_version(record, detail, label=label)
        zip_bytes = self.download_skill_zip(name, version, label=label)
    
    bundle = _nacos_zip_to_bundle(zip_bytes)
    return bundle["SKILL.md"].decode("utf-8")
```

> `admin=True` 是 working 版本(只服务端可读),`label=latest` 是 published 版本(可被 client 读)。

### E. zip ↔ bundle 转换

Nacos 上传和下载都是 zip,SkillClaw 内部是 `{path: bytes}` 的 bundle dict:

```python
def _bundle_to_nacos_zip(skill_name, bundle_files):
    buf = io.BytesIO()
    with zipfile.ZipFile(buf, "w", zipfile.ZIP_DEFLATED) as zf:
        for rel_path, content in bundle_files.items():
            zf.writestr(rel_path, content)
    return buf.getvalue()

def _nacos_zip_to_bundle(zip_bytes):
    bundle = {}
    with zipfile.ZipFile(io.BytesIO(zip_bytes), "r") as zf:
        for info in zf.infolist():
            bundle[info.filename] = zf.read(info.filename)
    return bundle
```

### F. 与 OSS 路径的互斥

```python
# skill_hub.py: from_config
@classmethod
def from_config(cls, config):
    skill_backend = (config.sharing_skill_backend or "").lower() or config.sharing_backend
    if skill_backend == "nacos":
        return NacosSkillHub.from_config(config)   # ← 切换走 Nacos
    return cls(backend=skill_backend, ...)         # ← 否则走 OSS/S3/Local
```

**Nacos 走 skill 资产,OSS/S3 仍走 session + validation**——这是 `_split_skill_storage` 模式的体现。

## 常见误区

1. **"Nacos 后端可以替代所有 OSS 后端"** —— **不**。Nacos 只承担**技能资产**;session 录制、validation job 仍需 OSS/S3/Local。
2. **"working 版本可以无限迭代"** —— **不能**。SkillClaw 推 Nacos 时如果发现已有 working 版本,**跳过不上传**。这是为了避免覆盖"用户正在手工编辑"的状态。要回滚:在 Nacos 控制台手动 `discard` working 版本。
3. **"nacos_publish_mode=direct 不需要审核"** —— **看 Nacos 端配置**。`direct` 只表示"提交后自动 publish 调用",但 Nacos 服务端可以仍然有审核管线(异步)。`_wait_nacos_publish` 就是等审核批准的——30s 超时。
4. **"Nacos 适配的传输是异步"** —— **不**。Nacos 客户端是**同步** httpx,evolve server 在 `await self._call_storage(...)` 里把它转成异步。这是为简化 Nacos API(同步 admin 操作)而做的取舍。
5. **"Nacos label 必须叫 'latest'"** —— **不**。`sharing.nacos_label` 可配,但默认 `"latest"`。`direct` 模式会把上传的 version 自动设为 `latest`。
6. **"`admin=True` 是管理员权限"** —— **是**。Nacos 区分"客户端可读"和"管理员可读"working 版本,`admin=True` 走的是管理员端点,需要 `nacos_access_token`。
