# 04.7 配置中心 `config.py` + `config_store.py`

> SkillClaw 的所有配置项。`config.py` 定义 dataclass,`config_store.py` 负责持久化到 `~/.skillclaw/config.yaml` 并做校验。

## 设计动机

SkillClaw 有大量配置项(70+),散落在:
- LLM 接入(`llm_api_base`、`llm_api_key`、`llm_model_id`、`llm_api_mode`)
- PRM 评分(`use_prm`、`prm_provider`、`prm_m`、`prm_temperature`)
- 共享存储(`sharing.backend`、`sharing.bucket`、`sharing.access_key_id`...)
- 后台验证(`validation.enabled`、`validation.idle_after_seconds`...)
- 可视化面板(`dashboard.enabled`、`dashboard_port`...)
- 多 agent(`claw_type`、`configure_openclaw`)

`config.py` 用一个 `@dataclass` 集中所有字段;`config_store.py` 负责:
- 加载 `~/.skillclaw/config.yaml` 到 dataclass
- 写入(整文件覆盖)
- 校验(各字段的"合法值"和"约束")
- CLI 入口 `skillclaw config KEY VAL` 改单个字段

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| `SkillClawConfig` | 顶层 dataclass(70+ 字段,聚焦"如何接 agent 请求") | `config.py` 全文 |
| `ConfigStore` | 配置持久化 + 校验(读 / 写 / 嵌套路径访问) | `config_store.py:250` |
| `CONFIG_FILE` | 默认路径 `~/.skillclaw/config.yaml`(YAML 嵌套结构) | `config_store.py` 顶部 |
| `default_skills_dir_for_claw` | 根据 `claw_type` 选默认 skills 目录(hermes → `~/.hermes/skills` 等) | `config_store.py:193` |
| `default_llm_api_mode_for_claw` | 根据 `claw_type` 选 chat / responses | `config_store.py:207` |
| `resolve_skills_dir` | 处理 `~` 展开 + 默认值 | `config_store.py:213` |
| `_deep_merge` | dict 合并(preserve user 改动) | `config_store.py:117` |
| `_infer_sharing_backend` | 从 sharing 子字段推断主 backend | `config_store.py:154` |
| `to_skillclaw_config` | ConfigStore → SkillClawConfig 转换(嵌套 → 平铺) | `ConfigStore` 类内 |
| **Group ID** | `sharing.group_id` —— 一个共享命名空间 = 一颗共享对象存储的 prefix tree | `config.py:124` |
| **User alias** | `sharing.user_alias` —— 用户上传时打的 tag,隔离不同用户的 session | `config.py:125` |

### B. ConfigStore 加载逻辑

```python
class ConfigStore:
    def __init__(self, config_path=None):
        self._path = Path(config_path) if config_path else Path(CONFIG_FILE)
        self._data = self._load()

    def _load(self):
        if not self._path.exists():
            return self._default()
        with self._path.open(encoding="utf-8") as f:
            user_data = yaml.safe_load(f) or {}
        return _deep_merge(self._default(), user_data)   # user 覆盖 default
```

`_default()` 返回一个**嵌套 dict** 表示默认配置。所有字段都有默认值,所以新用户不写 config 也能跑(只是 `use_skills=False`、`sharing_enabled=False` 之类的默认会让代理是"空壳")。

### D. CLI 入口:`skillclaw config KEY VAL`

```
skillclaw config proxy.port 30000
skillclaw config sharing.enabled true
skillclaw config show
```

实现:`cli.py` 里 `config` 子命令:

```python
@cli.command()
@click.argument("key")
@click.argument("value", required=False)
def config(key, value):
    store = ConfigStore()
    if key == "show":
        click.echo(yaml.safe_dump(store.to_skillclaw_config_dict(), ...))
        return
    if value is None:
        click.echo(store.get(key))
        return
    store.set(key, value)
    store.save()
```

`store.get("proxy.port")` 走 nested key path lookup(类似 `dict["proxy"]["port"]`),`store.set` 同理。

### E. 校验与归一化

```python
@staticmethod
def _normalize_validation_mode(value):
    if value in ("replay",):
        return value
    return "replay"   # 默认

@staticmethod
def _normalize_choice(value, allowed, default):
    return value if value in allowed else default
```

这种归一化在 `ConfigStore.__init__` 里调一次,保证读出来的 config 都是合法值。

### F. `default_skills_dir_for_claw(claw_type)`

根据 claw 类型选不同的默认 skills 目录:

| claw_type | 默认 skills_dir |
|---|---|
| `hermes` | `~/.hermes/skills` |
| `codex` | `~/.codex/skills` |
| `claude` | `~/.claude/skills` |
| `opencode` | `~/.config/opencode/skills` |
| 其他(默认) | `~/.skillclaw/skills` |

设计意图:不同 Agent 框架有自己的 skill 目录约定,SkillClaw 跟随。

## 常见误区

1. **"配置改了立刻生效"** —— **不**。`ConfigStore.set` 只改内存和写盘,**运行时**的 SkillClawAPIServer / SkillManager 已经构造过,需要重启。`skillclaw start --daemon` 会 spawn 新进程读新 config。
2. **"dataclass 字段顺序就是配置顺序"** —— 是,源文件里就是按"Model → PRM → Skills → ..."分块排的。
3. **"所有字段都暴露给 CLI"** —— **是**。`skillclaw config <key> <value>` 用 nested path 访问(`proxy.port` 而非 `proxy_port`)。YAML 里也用嵌套结构。
4. **"PRM 配置跟 LLM 配置是分开的"** —— **是**。`prm_url/prm_model/prm_api_key` 是给 PRM judge 用的,`llm_api_base/llm_api_key/llm_model_id` 是给主对话用的。理论上可以配成"主对话走 Qwen,PRM 走 GPT-5"。
5. **"`sharing.skill_backend` 默认会跟 `sharing.backend` 一致"** —— **是**。前者空时,代码用后者填充。
6. **"config.yaml 改错字段名会启动失败"** —— **不**。`_deep_merge(default, user_data)` 只取 default 里有的 key;用户多写的 key 会被丢弃,不报错。
