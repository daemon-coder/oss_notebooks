# 04.9 PRM 评分 `prm_scorer.py`

> Process Reward Model 评分。给"LLM 的回复对用户的指令是否有用"打 {-1, 0, 1} 三档分。

## 设计动机

"Agent 用了一个 skill 之后,这次对话有没有变好"是个判断题。SkillClaw 想把这个判断**自动化**,作为 skill 进化的反馈信号。

最直接的办法:调一个 LLM judge,给它"用户指令 + 助手回复",问它"这次回复有用吗?"。但单次判断不稳,所以:

1. **多次投票**(默认 `prm_m=3`):同 prompt 跑 M 次,majority vote 出最终分。
2. **明确判定标准**:"Use +1 when... Use -1 when... Use 0 when..."(见 `_build_prm_judge_prompt`)。
3. **简单解析**:`Score: 1` / `Score: -1` / `Score: 0`(避免 LLM 用 JSON 包裹带来的脆弱性)。
4. **后置异步**:`api_server` fire-and-forget,不阻塞主请求。

> PRM 是 Process Reward Model 的简称。在传统 RLHF / RLAIF 语境里指"过程级奖励"(给中间步骤打分),在 SkillClaw 里弱化成了"turn 级回复质量打分"。**不要**用 PRM 的传统定义来理解 SkillClaw 的实现。

## 核心概念

| 概念 | 定义 | 引用 |
|---|---|---|
| **PRM(Process Reward Model)** | 在传统 RLHF/RLAIF 语境里指"过程级奖励"(给中间步骤打分);在 SkillClaw 里**弱化**为"turn-level 回复质量评分",LLM judge 给单 turn 回复打 {-1, 0, 1} 三档 | 全章 |

| `prm_m` | 投票次数,默认 3(> 1 时走 majority vote) | `prm_scorer.py:107` |

| `prm_max_new_tokens` | 单次 judge 输出 token 上限 | `prm_scorer.py:109` |

## 实现要点

### A. judge prompt 模板

```python
def _build_prm_judge_prompt(response_text, instruction_text):
    system = (
        "You are a quality reviewer for conversational responses.\n"
        "You will be shown a user instruction and the assistant response to that instruction.\n"
        "Based on instruction alignment and task completion quality, decide whether the response was "
        "helpful (+1), unhelpful (-1), or unclear (0).\n"
        "Do NOT compare against any follow-up turn.\n"
        "Only evaluate whether the response addresses the given instruction.\n"
        "Use +1 when the response clearly follows and substantially completes the instruction.\n"
        "Use -1 when the response is off-task, wrong, or fails to complete core requirements.\n"
        "Use 0 when completion is ambiguous or evidence is insufficient.\n"
        "Think briefly, then end your reply with exactly one of: Score: 1 / Score: -1 / Score: 0"
    )
    user = (
        f"Instruction:\n{_sanitize_text(instruction_text)}\n\n"
        f"Response:\n{_sanitize_text(response_text)}\n\n"
        "Was the response helpful for this instruction? "
        "End with Score: 1, Score: -1, or Score: 0."
    )
    return [{"role": "system", "content": system}, {"role": "user", "content": user}]
```

关键设计:

- **"Do NOT compare against any follow-up turn"** —— 防止 LLM 看到"用户后续的抱怨/认可"后倒推本次评分。这是防 leak 的关键句。
- **"Think briefly, then end your reply with..."** —— 让 LLM 先思考,再输出"结构化结尾"。比直接要求"只输出分数"更稳。
- **`_sanitize_text`** —— 把 `<tool_call>...</tool_call>` 这种 XML-like 标签替换成 `[tool_call block]`,避免触发上游 LLM 的 content filter。

### B. 解析逻辑

```python
_BOXED_RE = re.compile(r"\\boxed\{([-+]?\d)\}")
_SCORE_RE = re.compile(r"Score:\s*([-+]?\d)", re.IGNORECASE)

def _parse_prm_score(text):
    matches = _SCORE_RE.findall(text)
    if matches:
        val = int(matches[-1])
        if val in (1, -1, 0):
            return val
    matches = _BOXED_RE.findall(text)
    if matches:
        val = int(matches[-1])
        if val in (1, -1, 0):
            return val
    return None
```

**主格式**:`Score: N`(避免 Azure 之类平台的 JSON 过滤问题)。
**回退格式**:`\boxed{N}`(支持 GPT-5 / DeepSeek / 一些老模型)。
**取最后一个**:`findall` 拿到全部 match,取最后一个——防止 LLM 在思考里写"Score: 1 ... Score: 0"被前面的骗。
**只接受 -1 / 0 / 1**:其他数字(2、3、99)无效,返回 None。

### C. 投票与聚合

```python
def _majority_vote(scores):
    valid = [s for s in scores if s is not None]
    if not valid:
        return 0.0
    counter = collections.Counter(valid)
    top = counter.most_common(1)[0]
    if list(counter.values()).count(top[1]) > 1:
        return 0.0    # 平局 → 0
    return float(top[0])
```

平局 → 0(中性),不偏向任何一方。
所有失败 → 0(不更新 feedback)。

### D. 异步执行

```python
class PRMScorer:
    async def evaluate(self, response, instruction, session_id="", turn_num=0):
        msgs = _build_prm_judge_prompt(response, instruction)
        
        # 并行投票
        results = await asyncio.gather(*[
            self._query_once(msgs, i) for i in range(self.prm_m)
        ])
        
        scores = [r[0] for r in results]
        final = _majority_vote(scores)
        
        representative = ""
        if final != 0.0:
            for s, text in results:
                if s is not None and s == int(final):
                    representative = text
                    break
        
        votes_display = [s if s is not None else "fail" for s in scores]
        logger.info(f"[PRMScorer] session={session_id} turn={turn_num} "
                    f"model={self.prm_model} votes={votes_display} → score={final}")
        return {"score": final, "votes": votes_display, "eval_text": representative}

    async def _query_once(self, messages, vote_id):
        try:
            completion = await asyncio.to_thread(
                self._client.chat.completions.create,
                model=self.prm_model,
                messages=messages,
                temperature=self.temperature,
                max_completion_tokens=self.max_new_tokens,
            )
            content = completion.choices[0].message.content or ""
            return _parse_prm_score(content), content
        except Exception as e:
            logger.warning(f"[PRMScorer] query failed (vote {vote_id}): {e}")
            return None, ""
```

要点:
- **`asyncio.to_thread`** 把同步 OpenAI SDK 包成异步
- **投票并行**(`asyncio.gather`)—— 3 次投票 ~1 次的延迟
- **失败不抛** —— 任何一次 judge 失败,这一票记 None,继续聚合

### E. 与 SkillManager 的反馈回路

```
api_server._post_request_hooks
    ↓
self._safe_create_task(self._prm_score_turn(session_id, turn))
    ↓
prm_score = await prm_scorer.evaluate(response, instruction)
    ↓
self.skill_manager.record_feedback(turn.skills_injected, prm_score["score"])
    ↓
更新 _stats[skill_name].positive_count / negative_count / effectiveness
```

注意:feedback 是给**所有被注入的 skill** 都加一次同样的分,而不是"哪个 skill 贡献了哪一分"。这意味着 effectiveness 是个**聚合**信号,不能定位到单 skill。

## 常见误区

1. **"PRM 是 skill 验证器"** —— **不是**。`pipeline/skill_verifier.py` 是对**候选 skill 文档**打 5 个分;PRM 是对**单 turn 回复**打 1 个分。两者都用 LLM judge 但目标不同。
2. **"PRM 评分影响下次 skill 注入"** —— **是,但只在 embedding 检索模式**。Template 模式完全忽略 effectiveness(见 04.03)。
3. **"`prm_m=1` 跟 `prm_m=3` 等价"** —— **不**。`prm_m=1` 是单次判定,完全没投票,容易抖。`prm_m=3` 投票,稳但 3x 成本。
4. **"PRM judge 必须跟主对话同一个 LLM"** —— **不**。`prm_url` / `prm_model` / `prm_api_key` 是独立的,可以配 GPT-5 judge 但主对话用 Qwen。常见配置:便宜的本地模型跑主对话,GPT-5 跑 PRM。
5. **"Azure OpenAI 走不通"** —— 能,`_sanitize_text` + 主格式 `Score: N` 都是为绕开 Azure content filter 设计的。
6. **"PRM judge 输出 `\boxed{0}` 时被丢弃"** —— 不会,见 `_BOXED_RE`,这是回退格式。
7. **"effectiveness 在 0.5 时是好是坏"** —— **默认 0.5**(从未被 feedback 过的 skill)。这是"未观察"而不是"中性"。
