# 前言

## 这份文档是什么

这是一份**从源码反推**的 SkillClaw 技术参考书。它不重复 README 里的安装/使用步骤,而是回答另一个问题:

> 一个工程师打开这个仓库,读完这套文档,能不能讲清楚 SkillClaw 是怎么工作的——为什么是双进程,为什么用共享存储做"桥梁",为什么 skill 的演进要分三阶段,为什么本地要先注入 skill 再打 PRM 分数。

## 读者画像

- **目标读者**:有 Python 工程经验的工程师;读代码优先,先想看"实现是不是这么回事",再看 README 里的"如何用"。
- **不需要的先验知识**:不需要了解 Hermes / OpenClaw 这些具体 agent 框架的 API;它们只是 SkillClaw 适配的协议方,文档里会按需点出。
- **需要的先验知识**:基本的 FastAPI 异步用法、asyncio、对象存储(S3/OSS)的概念、YAML/JSON/Markdown 处理。

## 阅读建议

1. **先读 [01-项目概述.md](./01-项目概述.md) 抓定位**,再读 [02-整体架构.md](./02-整体架构.md) 拿全局。
2. 想**理解 client 怎么工作**的:03.01 → 03.02 → 03.03 → 04.01 → 04.03。
3. 想**理解 evolve server 怎么工作**的:03.04 → 03.05 → 04.12 → 04.13 → 04.14。
4. 想**理解 LLM 怎么把会话凝练成 skill** 的:看 04.13 的三阶段流水线、04.12 的 `evolve_strategy`,以及 03.04 里的 pseudo-code。
5. 想**接入新 agent 框架**的:04.06(`claw_adapter.py`)+ 04.01 的协议适配部分。
6. 想**部署到生产**的:02(架构) + 03.03(共享存储后端) + 05(决策:为什么用 OSS 不用 Git)。

## 文档不覆盖什么

- 真实部署到阿里云 OSS / Nacos / Bedrock 的运维细节(配置字段文档里会列,具体云厂商控制台操作不在此书范围)。
- 与 README 重复的"如何在 5 分钟内跑起来"步骤——那份指南在 README 里更直观。
- SkillClaw 引用的学术论文(arXiv:2604.08377)的方法论讨论——本书讲工程实现。

## 写作原则

- 引用代码用 `path/to/file.py:42`,**不**做代码搬运。
- 关键流程用 **pseudo-code** 描述"形状",而不是贴原始 token。
- 容易混淆的概念(例如 `SkillManager` vs `SkillHub`、`evolve server` vs `validation worker`、Nacos Skill vs Nacos 配置中心)在首次出现时给出对比表。
- 源码读不透的项标"**待确认**",绝不编造。
