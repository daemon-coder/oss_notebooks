# 41 · 部署形态

## 这一章讲什么

这一章把 SkillClaw 的 3 种部署模式（单机自用 / 团队共享 / validated 流程）一次讲完——包括最小配置、运行手册、监控指标、回滚路径。

## 它在整个系统的哪个位置

端到端层的最后一篇。其它 20 章都在讲"系统怎么工作"，这一章讲"怎么把它跑起来"。

## 设计目的

让运维 / 平台工程师能照着这一章把 SkillClaw 部署起来——不需要通读前 20 章，但能跳到对应章节查细节。

---

## 1. 部署模式总览

> **决策树**:
> 1. **共享存储用什么** → 决定 A / B / C / D:
>    - 本地目录: A(无服务端)或 B(含本地演化)
>    - OSS / S3 / MinIO bucket: C
>    - Nacos(已有 Nacos 基础设施): D
> 2. **要不要审核 / 要不要 LLM 自由发挥** → 在 A / B / C / D 基础上**叠加** E / F:
>    - E = 在 C 或 D 基础上**两端**启用 `validation.enabled` + `EVOLVE_PUBLISH_MODE=validated`
>    - F = 在 C 或 D 基础上服务端切 `--engine agent` + `--no-fresh`
> 3. **E 和 F 是"叠加关系",不是独立路径**——选 E 之前先选 C 还是 D,选 F 之前也先选 C 还是 D。
>
> **生产建议**:`A / B` 跑通后跳 `C`;`C` 跑通稳定后再叠加 `E`(开启前先关闭它跑 1-2 周,积累 `manifest.jsonl` 足够 session 才有可验证对象);`F` 仅在你已经看到 `C / D` 的稳定演化结果后**作为实验**启用。

| 模式 | 客户端 | 服务端 | 共享存储 | 适用 | 与其它模式关系 |
|---|---|---|---|---|---|
| **A. 单机自用（无服务端）** | `skillclaw start` | — | `~/.skillclaw/skills/` 本地目录 | 个人试用 / 不需要集体演化 | 基础模式 |
| **B. 单机自用（含本地演化）** | `skillclaw start` | `skillclaw-evolve-server --use-skillclaw-config` | `sharing.backend=local` + `sharing.local_root=~/.skillclaw/local-share` | 个人想"自己用 + 自动演化"（最常见的最小可行部署） | A + 本地 evolve |
| **C. 团队共享（OSS / S3）** | 多台 `skillclaw start` | 1 台 `skillclaw-evolve-server` | OSS / S3 / MinIO bucket | 团队 / 跨用户 / 跨设备 | 基础团队模式 |
| **D. 团队共享（Nacos）** | 多台 `skillclaw start` | 1 台 `skillclaw-evolve-server` | skill 走 Nacos，session/validation 走 OSS | 团队 + 需要 skill 版本审核流 | C 的 Nacos 派生(需现有 Nacos 基础设施) |
| **E. Validated 模式** | 在 C/D 基础上启用 `validation.enabled=true` | `EVOLVE_PUBLISH_MODE=validated` | 同 C/D | 团队 + 不信任单 LLM 输出（要客户端 replay 验证） | C/D 的"叠加"——必须先选 C 或 D |
| **F. Agent 引擎** | 同 C/D | `--engine agent` + `--no-fresh` | 同 C/D | 团队 + 想看 LLM 自由发挥 | C/D 的"叠加"——必须先选 C 或 D;生产建议先用 C 跑通 workflow 稳定后再切 agent |

下面逐个给最小可运行配置。

## 2. 模式 A：单机自用（无服务端）

```bash
# 1. 装
git clone https://github.com/AMAP-ML/SkillClaw.git
cd SkillClaw
bash scripts/install_skillclaw.sh
source .venv/bin/activate

# 2. setup（选 none = 不自动改 agent 配置）
skillclaw setup
#   claw_type: none
#   llm: openai, model: gpt-4o, api_key: sk-...
#   skills: enabled, dir: ~/.skillclaw/skills
#   prm: enabled
#   sharing: false
#   proxy: port 30000

# 3. 手动把 agent 指向代理（用户自己改 agent 配置）
#    base_url: http://127.0.0.1:30000/v1
#    model: skillclaw-model

# 4. 启动
skillclaw start --daemon
skillclaw status    # 应该是 "running"
curl http://127.0.0.1:30000/healthz    # {"ok": true}
```

**默认 skills 目录**：`~/.skillclaw/skills/`。用户手动维护 SKILL.md。

**`claw_adapter.configure_claw` 不会被调**（`claw_type=none`）——用户自己改 agent 配置。

**没有 evolve server**——skill 不会自动改进。

**适合**：临时试用 / 个人不想用 collective feature。

## 3. 模式 B：单机自用（含本地演化）

```bash
# 1. 同模式 A 的 1-2 步

# 2. setup 时启用本地共享
skillclaw setup
#   sharing: enabled
#   sharing.backend: local
#   sharing.local_root: ~/.skillclaw/local-share
#   sharing.group_id: alice-personal
#   sharing.user_alias: alice
#   sharing.auto_pull_on_start: true

# 3. 启动 client
skillclaw start --daemon

# 4. 启动 evolve server（同台机器）
skillclaw-evolve-server --use-skillclaw-config --interval 300 --port 8787
#   interval: 5 分钟
#   port: 8787 (HTTP trigger + health/status)
```

**`--use-skillclaw-config`** 让 evolve server 复用 `~/.skillclaw/config.yaml` 的 sharing + LLM 配置——**不用**单独维护 `.env`。

**完整闭环**：
- client → session.json → local-share/sessions/ → evolve server drain → LLM evolve → local-share/skills/ → client pull

**`auto_pull_on_start: true`** → 启动时立即拉一次最新 skill（不等 30s poll）。

**适合**：个人想"自动从自己的使用中改进 skill"，没有团队分享需求。

**`local-share` 目录**结构：
```
~/.skillclaw/local-share/
└── alice-personal/        # group_id
    ├── manifest.jsonl
    ├── skills/
    │   └── debug-systematically/SKILL.md
    └── sessions/
        └── 2026-04-20T15-30-00-abcd.json
```

**`SkillHub.object_storage_from_config` 走 `LocalObjectStore`**，evolve server 走 `LocalBucket` / `LocalObjectStore`——**同一份数据**。

## 4. 模式 C：团队共享（OSS / S3）

```bash
# === 服务端（单独一台机器） ===

# 1. 装
bash scripts/install_skillclaw_server.sh
source .venv-server/bin/activate

# 2. 配 .env
cp evolve_server/evolve_server.env.example evolve_server/.env
# 编辑 .env：
#   EVOLVE_ENGINE=workflow
#   EVOLVE_STORAGE_BACKEND=oss
#   EVOLVE_STORAGE_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
#   EVOLVE_STORAGE_BUCKET=acme-team-skills
#   EVOLVE_STORAGE_ACCESS_KEY_ID=LTAI...
#   EVOLVE_STORAGE_SECRET_ACCESS_KEY=...
#   EVOLVE_GROUP_ID=acme
#   OPENAI_API_KEY=sk-...
#   EVOLVE_MODEL=kimi-k2.5
#   EVOLVE_INTERVAL=300
#   EVOLVE_PORT=8787

# 3. 启 evolve server
skillclaw-evolve-server --port 8787

# 4. (可选) 启 dashboard 同步
skillclaw dashboard sync --sharing-backend oss --sharing-endpoint ... --sharing-bucket ...
```

```bash
# === 客户端（每个 user） ===

# 1. 装 SkillClaw
bash scripts/install_skillclaw.sh
source .venv/bin/activate

# 2. 配 sharing
skillclaw setup
#   sharing: enabled
#   sharing.backend: oss
#   sharing.endpoint: https://oss-cn-hangzhou.aliyuncs.com
#   sharing.bucket: acme-team-skills
#   sharing.access_key_id: ...
#   sharing.secret_access_key: ...
#   sharing.group_id: acme
#   sharing.user_alias: alice
#   sharing.auto_pull_on_start: true

# 3. 配 LLM + PRM
#   llm.provider: openai
#   llm.model_id: gpt-4o
#   llm.api_key: sk-...
#   prm: enabled, model: gpt-5.2

# 4. 配代理 auth（**团队部署必填**）── 防 agent 绕过 SkillClaw 直连上游 LLM
skillclaw config proxy.api_key "$(openssl rand -hex 32)"      # 生成 32 字节随机 token
# 或在 setup 第 27 步填入
#   proxy.api_key  字段默认 ""(空 = 不校验)
# 团队部署: **必须填非空**——`_check_auth` 校验 `Authorization: Bearer <proxy_api_key>` header
# 单机自用可留空(本机 127.0.0.1 一般不强制,但建议填)

# 5. 启动
skillclaw start --daemon
```

**多用户并存**：`sharing.user_alias` 不同即可——每个 user 拉相同的 skill、上传各自的 session（session.json 里的 `user_alias` 标记来源）。

**OSS bucket 布局**：
```
acme-team-skills/
└── acme/                              # group_id
    ├── manifest.jsonl
    ├── skills/<name>/SKILL.md
    ├── skills/<name>/versions/v<N>/...
    ├── sessions/<sid>.json
    ├── validation_jobs/...
    └── evolve_skill_registry.json
```

**适合**：5-50 人团队，跨设备 / 跨 agent 共享。

## 5. 模式 D：团队共享（Nacos skill + OSS session）

```yaml
# ~/.skillclaw/config.yaml
sharing:
  enabled: true
  skill_backend: nacos            # skill 走 Nacos
  backend: oss                    # session/validation 走 OSS
  endpoint: https://oss-cn-hangzhou.aliyuncs.com
  bucket: acme-team-skills
  access_key_id: ...
  secret_access_key: ...
  nacos_server: https://nacos.acme.internal
  nacos_namespace_id: acme
  nacos_username: alice
  nacos_password: ...
  nacos_label: latest
  nacos_publish_mode: review       # draft / review / direct
  group_id: acme
  user_alias: alice
```

`skillclaw setup` 当前不提供 Nacos 选项——手动编辑 `config.yaml` 添加上述字段。

> **前置**:Nacos 服务**已就绪** + `acme` 命名空间已建 + `alice` 用户已注册并有命名空间读写权限(否则 Nacos 端 401 / 403)。

**`NacosSkillClient` 用 username/password 登录**拿 `accessToken`，之后所有 API 带 `accessToken` header。

**验证 Nacos 连通**:
```bash
curl -H "Authorization: Bearer <nacos_accessToken>" \
  "https://nacos.acme.internal/v3/admin/ai/skills/list?namespaceId=acme&pageNo=1&pageSize=10"
# 期望返回 {"code":0,"data":{"totalCount":N,...}}
```

**`evolve_server/.env` 增配**:
```bash
EVOLVE_ENGINE=workflow
EVOLVE_STORAGE_BACKEND=oss
EVOLVE_STORAGE_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
EVOLVE_STORAGE_BUCKET=acme-team-skills
EVOLVE_STORAGE_ACCESS_KEY_ID=LTAI...
EVOLVE_STORAGE_SECRET_ACCESS_KEY=...
EVOLVE_NACOS_SERVER=https://nacos.acme.internal
EVOLVE_NACOS_NAMESPACE_ID=acme
EVOLVE_NACOS_USERNAME=alice
EVOLVE_NACOS_PASSWORD=...
```

**推第一个 skill 到 Nacos**:
```bash
# 1. 客户端 pull 一次让本地 skill 库建立
skillclaw start --daemon
# 2. 编辑 ~/.skillclaw/config.yaml,改 skill_backend: nacos,设 nacos_* 字段
# 3. 重启 daemon 让 SkillHub.from_config 重新走 NacosSkillHub
skillclaw stop && skillclaw start --daemon
# 4. push
skillclaw skills push
# 5. 验证:用上面的 curl 命令列 skill,看 uploaded skill 是否出现
```

**Nacos skill 生命周期**：
- `nacos_publish_mode=draft`：upload 即结束（不进审核）
- `nacos_publish_mode=review`（默认）：upload → `submit()` → 人工 review → `publish()` 改 `latest` label
- `nacos_publish_mode=direct`：upload → `submit()` → 立即 `publish()` 改 `latest` label

**evolve server 端 Nacos**：
- `--engine workflow` 默认 Nacos-aware：`_upload_skill` 检测 `_nacos_skill_client is not None` 走 Nacos 路径
- `_wait_nacos_publish(name, version, timeout=30.0)` 同步阻塞等 Nacos publish 成功

**适合**：需要正式 skill 版本审核的团队（合规 / 治理）。

## 6. 模式 E：Validated 模式

在模式 C/D 基础上**两端**都启用：

**服务端** `evolve_server/.env`：
```bash
EVOLVE_PUBLISH_MODE=validated
EVOLVE_VALIDATION_REQUIRED_RESULTS=2       # 至少 2 个客户端 result
EVOLVE_VALIDATION_REQUIRED_APPROVALS=2     # 至少 2 个 accept
EVOLVE_VALIDATION_MIN_MEAN_SCORE=0.75      # mean score 阈值
EVOLVE_VALIDATION_MAX_REJECTIONS=1         # 单 reject 即 reject
```

**客户端** `~/.skillclaw/config.yaml`：
```yaml
validation:
  enabled: true
  idle_after_seconds: 300
  poll_interval_seconds: 60
  max_jobs_per_day: 5
  max_concurrency: 1
```

**完整流程**（详见 21 章）：
1. workflow engine 生成 candidate → `_queue_validation_job` → 写 `validation_jobs/<job_id>.json` + `candidate_skills/<job_id>/SKILL.md`
2. 客户端 idle 时（无活跃 session 且 last request ≥ 300s）跑 `ValidationWorker.run_once`
3. 客户端拉 open jobs（自己没写过的）→ 跑 replay validation（用本地 LLM 跑 replay_cases，最多 3 个 case）
4. 写 `validation_results/<job_id>/<user>.json`（accepted/score/votes）
5. 下次 evolve cycle 的 `_finalize_validation_jobs` 检查：
   - `result_count >= required_results` AND `accepted >= required_approvals` AND `mean_score >= min_mean_score` → publish candidate
   - `rejected >= max_rejections` → reject candidate
6. publish → 写 `skills/<name>/SKILL.md` + 写 `validation_decisions/<job_id>.json`

**`validation.required_results=2` 意味着需要至少 2 个客户端都 accept**——单一用户不能自己"批准"自己的修改。

**`max_rejections=1` 意味着单个 reject 即拒**——保护机制。

**`replay_cases` 服务端构造**（从原始 session 抽 `(session_id, turn_num, instruction, baseline_response, candidate_response)`）——客户端跑"用 candidate skill vs baseline skill 跑同一个 instruction"，看 candidate mean score 是否 ≥ threshold 且 ≥ baseline。

**适合**：不信任单 LLM 输出、要求多用户都 OK 才能上线的团队。

## 7. 模式 F：Agent Engine

> **Agent 引擎是"想看 LLM 自由发挥"的研究者模式**——生产里建议**先**用模式 C/D 跑通 workflow 引擎,再**可选**开 agent 引擎。Agent 引擎在共享存储路径上跟 C/D 一样,只是 evolve server 内部用 OpenClaw 子进程替 workflow 流水线;所以部署上**先**走 C/D 装好客户端 / 服务端 / 共享存储,再**切** evolve server engine。

```bash
# === 前置:按模式 C 装好客户端 + 服务端 + 共享存储 ===
# (略,见 §4 / §5)

# === 在 evolve server 那一台:装 OpenClaw ===
# OpenClaw 是 SkillClaw 调用的外部 agent runtime,必须先装
npm install -g openclaw                        # 或按 OpenClaw 官方文档装
which openclaw                                 # 验证在 PATH

# === evolve server 配 env ===
cat >> evolve_server/.env <<EOF
EVOLVE_ENGINE=agent                           # 切到 agent 引擎
AGENT_EVOLVE_OPENCLAW_BIN=openclaw            # 子进程调用哪个 binary
AGENT_EVOLVE_LLM_API_TYPE=openai-completions  # 喂给 OpenClaw 的协议
AGENT_EVOLVE_LLM_BASE_URL=https://api.openai.com/v1
AGENT_EVOLVE_LLM_API_KEY=sk-...
AGENT_EVOLVE_MODEL=gpt-5.4
AGENT_EVOLVE_FRESH=0                          # 0 = --no-fresh(跨轮记忆);1 = --fresh(每次重置)
AGENT_EVOLVE_TIMEOUT=1200                     # 20 分钟超时
AGENT_EVOLVE_WORKSPACE_ROOT=/var/skillclaw/agent-workspace
# 可选: AGENT_EVOLVE_AGENTS_MD=/path/to/custom-prompts.md  自定义 EVOLVE_AGENTS.md
EVOLVE_INTERVAL=600
EOF

# === 启 evolve server(用 --engine agent 覆盖 env,或直接靠 EVOLVE_ENGINE=agent) ===
skillclaw-evolve-server --engine agent --no-fresh --port 8787
```

**首次 cycle(`--fresh=True` 或 `AGENT_EVOLVE_FRESH=1`,默认)**:
- workspace 整个 wipe → 重新填充 sessions + skills + bootstrap
- OpenClaw 子进程启动,读 `AGENTS.md` → 读 `EVOLVE_AGENTS.md` 协议
- OpenClaw 改 `skills/<name>/SKILL.md`
- `collect_changes` diff before/after,识别 create / improve
- 上传到共享存储(走模式 C/D 同样的 `_upload_skill`)

**后续 cycle(`--no-fresh` / `AGENT_EVOLVE_FRESH=0`)**:
- workspace 增量保留 + `~/.openclaw/`(OpenClaw HOME)也保留
- OpenClaw 的 `MEMORY.md` / `memory/` 跨轮累积(`memory-core` 是 OpenClaw 内部子模块,SkillClaw **不**接管)
- 经验:第一次跑用 `--fresh` 验证配置 OK,跑稳了想持续演进切到 `--no-fresh`

**关键变量速查**:

| env 变量 | 默认 | 作用 |
|---|---|---|
| `EVOLVE_ENGINE` | `workflow` | 选 `agent` 切到 agent 引擎 |
| `AGENT_EVOLVE_OPENCLAW_BIN` | `openclaw` | OpenClaw binary 路径(PATH 里有就不用改) |
| `AGENT_EVOLVE_LLM_API_TYPE` | `openai-completions` | 喂给 OpenClaw 的 LLM 协议;`anthropic-messages` 走 `_AnthropicMessagesLLMClient`(自建,不走 boto3) |
| `AGENT_EVOLVE_LLM_BASE_URL` | (空) | 上游 LLM endpoint |
| `AGENT_EVOLVE_LLM_API_KEY` | (空) | 上游 LLM key |
| `AGENT_EVOLVE_MODEL` | (空) | 上游 LLM model id |
| `AGENT_EVOLVE_FRESH` | `1` | 1 = 每次 cycle wipe workspace;0 = 保留 |
| `AGENT_EVOLVE_TIMEOUT` | `1200` | 单次 OpenClaw 子进程超时(秒) |
| `AGENT_EVOLVE_WORKSPACE_ROOT` | `<pkg>/agent_workspace` | workspace 根目录,生产建议改到 `/var/skillclaw/agent-workspace` |
| `AGENT_EVOLVE_AGENTS_MD` | (空) | 自定义 EVOLVE_AGENTS.md 路径;留空用 SkillClaw 自带的 |

**验证 worker LLM 归属澄清**:模式 E(validated)的 `_replay_validate_job` 跑 baseline + candidate 两条 LLM 推理时,**用的是 `cfg.llm_*` 字段**(默认 `gpt-4o`)——**不是** `prm_*` 字段;但**打分**走的是 `cfg.prm_*` 字段(默认 `gpt-4o`)。两者可以不同源(LLM 用便宜的,PRM 用准的),配置上各走各的;但**默认都是从 OpenAI 协议**。详见 [21 · 后台验证工作流](02-客户端共享层/21-后台验证工作流.md) §3.3。

**适合**:想看 LLM 自由发挥的研究者。**生产建议先用模式 C/D 跑通 workflow,验证稳定后再切 agent**——agent 引擎调 LLM 频次高、输出不可预测、对 prompt 细节敏感。

## 8. 监控与日志

### 8.1 客户端日志

- `~/.skillclaw/skillclaw.log`（daemon 模式）
- 控制台带颜色（`log_color.py` 注入 ANSI 颜色）

**关键 log prefix**：
- `[Launcher]`：launcher 启动 / 信号
- `[OpenClaw]`：代理主流程
- `[SkillManager]`：skill 注入 / 读取
- `[SessionDetect]`：session 边界检测
- `[PRMScorer]`：PRM 投票结果
- `[SkillHub]`：共享存储同步
- `[ClawAdapter]`：agent 配置改写
- `[Dashboard]`：dashboard 同步

### 8.2 服务端日志

- `evolve_history.jsonl`（每个 cycle 一行 JSON summary）
- 控制台日志

**关键 log prefix**：
- `[EvolveServer]`：workflow 引擎
- `[AgentEvolveServer]`：agent 引擎
- `[Aggregation]`：session 聚合
- `[Storage]`：OSS/S3 读写
- `[SkillVerifier]`：verifier 结果

### 8.3 关键指标

**客户端**：
- `GET /healthz`：服务存活
- `GET /v1/models`：model 列表（永远只有 1 个：served_model_name）
- `~/.skillclaw/skillclaw.log` 日志大小
- `~/.skillclaw/records/conversations.jsonl` 行数（本次进程 turn 数）
- `~/.skillclaw/records/prm_scores.jsonl` PRM 投票数
- `~/.skillclaw/skills/skill_stats.json` 每个 skill 的 effectiveness

**服务端**：
- `GET /health`：服务存活
- `GET /status`：pending_sessions / registered_skills
- `evolve_history.jsonl` 每个 cycle 的 elapsed_seconds / sessions / skills_evolved / queued_candidates / had_processing_error
- `evolve_skill_registry.json` 持久化的 skill_id / version / history

**Dashboard**：
- `GET /api/v1/health`：dashboard 存活
- `GET /api/v1/overview`：totals / by_source / last_sync / warnings
- `GET /api/v1/skills`：skill 列表（按 session_count 降序）
- `GET /api/v1/validation/jobs`：validation job 状态分布

### 8.4 告警建议

| 指标 | 阈值 | 含义 |
|---|---|---|
| 客户端 `daemon` 状态 | 持续 down | SkillClaw 不在跑 |
| 客户端 `_last_request_age` | > 1h 且无 active session | SkillClaw 静默（agent 不用） |
| 服务端 `pending_sessions` | 持续 > 100 | sessions 累积 / storage 慢 / LLM 卡 |
| 服务端 `had_processing_error=true` | 连续 3 个 cycle | 单 skill 反复出错 |
| 服务端 `elapsed_seconds` | > 5min / cycle | LLM 慢 / sessions 太多 |
| Dashboard `warnings` 非空 | 任一 cycle | 拉取失败 / 字段缺失 |
| `validation_jobs.pending` | > 10 | 客户端 validator 没跑 / 不可达 |

## 9. 回滚 / 升级

### 9.1 客户端回滚

`doctor <claw>` + `restore <claw>` 恢复 agent 配置（详见 17 章）：
```bash
skillclaw doctor hermes     # 看当前集成状态
skillclaw restore hermes    # 从 ~/.skillclaw/backups/hermes/ 最新备份还原
```

`/skillclaw/skills/skill_stats.json` 是普通 JSON——可以手动备份 / 恢复。

### 9.2 服务端回滚

`EvolveServer` 上传 SKILL.md 时**总是**写 `versions/v<N>/SKILL.md`——历史版本**不会**被覆盖。

`SkillClawAPIServer` reload 拉最新 manifest → 只更 `skills/<name>/SKILL.md`（v<N>/ 仍可访问）。

**手工回滚**（绕过 SkillClaw）：从 `<group_id>/skills/<name>/versions/v<N>/SKILL.md` 把 v<N> 内容写回 `<group_id>/skills/<name>/SKILL.md`——但 manifest 不会自动改 `version` 字段（**会**和 `evolve_skill_registry.json` 不一致），下次 evolve 可能再次 conflict。

**正确回滚**：
1. 编辑 `manifest.jsonl` 把 `version` 改回 N
2. 编辑 `evolve_skill_registry.json` 把对应 entry 的 `version` / `content_sha` / `history[]` 改回 N
3. 下次 evolve 看到 `version=N` + 现有 SKILL.md 是 v<N> 内容 → `tree_sha256` 匹配 → 不算 conflict

**dashboard 的 `activate_skill_version`** 是**反向**操作（v<N> → current）——`POST /api/v1/skills/{id}/activate` body `{"target": "3"}` 触发；只动本地目录 + manifest 那个 skill entry，**不**改 `evolve_skill_registry.json`。**待确认**是否该同步改 registry。

### 9.3 升级 SkillClaw 版本

**客户端**：
```bash
cd SkillClaw
git pull
.venv/bin/pip install -e ".[evolve,sharing,server]"
skillclaw status    # 仍在跑（uvicorn 不需要重载）
skillclaw stop
skillclaw start --daemon
```

**服务端**：
```bash
cd SkillClaw
git pull
.venv-server/bin/pip install -e ".[server]"
# 优雅停：kill -TERM <pid>  (skillclaw-evolve-server run_periodic 收到 SIGTERM 等下个 cycle 退出)
# 或：直接 kill -9 然后重启
.venv-server/bin/skillclaw-evolve-server --port 8787
```

**配置兼容**：`ConfigStore.load()` 用 `_deep_merge(_DEFAULTS, data)`——新版本加新字段会**自动**带默认值，老用户配置不会破。

## 10. 性能与规模

| 维度 | 默认 / 当前建议 | 瓶颈点 |
|---|---|---|
| 单机并发 agent 数 | < 10 | 内存（每个 session 在内存）+ SkillManager embed cache |
| 单 skill 库 skill 数 | < 1000（template）/ < 10K（embedding） | template 模式无瓶颈；embedding 模式 model 推理 |
| session 上传频率 | session 关闭时一次 | OSS 写入 IO |
| reload 延迟 | 30s（poll）/ < 1s（callback） | pull_skills 跑 `os.walk` 镜像 |
| evolve server 周期 | 600s | LLM 调用（summarize 1 + judge 1 + evolve N + verifier N + merge K） |
| 单 cycle 处理的 session 数 | 实测 5-50 | LLM 并发（默认用 `asyncio.gather` 全部并行） |

**生产建议**：
- 大团队（> 50 users）：evolve server **单独**部署（不和 client 同台）
- 高频使用：考虑 `EVOLVE_INTERVAL=60`（默认 600s 太慢）+ 客户端 `sharing_session_upload_interval=5`（每 5 个 user turn 上传一次）+ `EVOLVE_PUBLISH_MODE=callback` 模式

## 13. 待确认 / 已知限制

- **`scripts/install_skillclaw.sh` macOS / Linux 路径 Windows 不可用**：Windows 必须手动按 README §"Path A" 的 PowerShell 步骤装。**待确认**要不要加 `.ps1` 装脚本。
- **生产没 systemd unit / launchd plist**：用户**必须**自己写 service 文件管理 daemon 启停。SkillClaw 不会自动生成。**待确认**这是有意（让部署灵活）还是疏忽。
- **Nacos 的 token 过期**：当前 `_login()` 只在构造时跑一次。生产 Nacos 默认 token TTL 几小时——**待确认**是否要在每次 request 前 check `expireTime` 自动 re-login（`nacos_skill_hub._login` 是 `self.access_token` 重读，没自动刷新）。
- **Evolve server 多副本冲突**：两个 evolve server 跑同一个 group → 抢同一 sessions/ → race condition。**待确认**是否该加 advisory lock（OSS 不支持强 lock）。
- **客户端 `claw_type=openclaw` 但没装 openclaw**：`_configure_openclaw` 走 `openclaw config set` → FileNotFoundError → 警告但不致命——**但** Hermes 客户端的 base_url 没改，**所有 LLM 请求会绕过 SkillClaw**。生产**必须**先装 agent。
