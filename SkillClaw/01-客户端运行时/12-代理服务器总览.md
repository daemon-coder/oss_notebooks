# 12 · 代理服务器总览

## 这一章讲什么

这一章回答"`SkillClawAPIServer` 这个类长什么样、它对外暴露哪些 HTTP 端点、它的生命周期由谁管"。

## 它在整个系统的哪个位置

`SkillClawLauncher._run()` 构造 `SkillClawAPIServer` 并 `server.start()`，所以它**是**整个客户端的"运行时主体"——所有 agent 的 LLM 请求都打到这里。

## 设计目的

让 SkillClaw 在 agent 视角下是**一个完全可替代的 OpenAI / Anthropic endpoint**——agent 不用改一行代码，只把 base URL 改到 `http://127.0.0.1:30000` 即可。但内部又塞进了 6 件事：
1. skill 注入
2. record 持久化
3. PRM 评分
4. session 边界追踪
5. session 关闭时上传
6. 后台拉新 skill

---

## 1. 类的形状

```python
class SkillClawAPIServer:
    def __init__(
        self, config: SkillClawConfig,
        *, skill_manager=None, prm_scorer=None, dashboard_store=None,
    ):
        # 见 api_server.py:SkillClawAPIServer.__init__
        ...
```

**构造时**的副作用：
1. `os.makedirs(config.record_dir, exist_ok=True)`
2. `os.makedirs(config.record_dir, exist_ok=True)` + 用 `"w"` 模式 `open()` **清空** `conversations.jsonl` 和 `prm_scores.jsonl`（如果 `record_enabled=True`）——record 是"本次进程"的，不跨重启
3. 实例化 `self.app = self._build_app()`
4. 准备好 `self._server: uvicorn.Server`、`self._thread`、`self._ready_event`、`self._server_stopped_event`（实际 run 时才填）

**构造时读配置**：
- `self._served_model = config.served_model_name`
- `self._expected_api_key = config.proxy_api_key`
- `self._compress_system_prompt = config.claw_type == "openclaw"`（**只有 OpenClaw 启用了**这个优化）
- `self._system_prompt_cache_file = f"{record_dir}/system_prompt_cache_{claw_type}_{llm_provider}.json"`
- 各种时间常量从 config 读，否则用模块级默认：
  - `_SESSION_IDLE_CLOSE_SECONDS = 180`
  - `_SESSION_SWEEP_INTERVAL_SECONDS = 15`
  - `_SHUTDOWN_DRAIN_TIMEOUT_SECONDS = 15`
  - `_skill_reload_interval_seconds = max(5, sharing_skill_reload_interval_seconds or 30)`

**实例状态机**（`self._*` 字段）：
- `_turn_counts: dict[str, int]`：`session_id -> 1-based turn 序号`
- `_user_turn_counts: dict[str, int]`：`session_id -> user 边界计数`
- `_pending_turn_data: dict[str, dict[int, dict]]`：`session_id -> {turn_num -> {prompt_text, response_text, ...}}`
- `_prm_tasks: dict[str, dict[int, asyncio.Task]]`：`session_id -> {turn_num -> PRM 评分 task}`
- `_pending_records: dict[str, dict]`：当前 turn 的 record 缓冲（等 next_state 进来后 flush）
- `_session_scored_turns: dict[str, int]`：`session_id -> 已 finalize 的 PRM turn 数`
- `_session_turns: dict[str, list[dict]]`：`session_id -> 累积的 turn_record 列表`（用于 session 上传）
- `_session_last_active: dict[str, float]`：`session_id -> 上次活动时间戳`（用于 idle sweeper）
- `_closing_sessions: set[str]`：正在被关闭的 session id（防止重入）
- `_background_tasks: set[asyncio.Task]`：上传 / 提交等一次性后台任务
- `_responses_store: dict[str, dict]`：OpenAI Responses API 的 `response_id -> {response, messages}` 内存存储
- `_tui_session_meta: dict[str, dict]`：TUI 类 agent 的伪 session 元数据（`tui-<model> -> {session_id, last_msg_count, last_request_time}`）
- `_session_sweeper_task` / `_skill_reload_task`：两个常驻后台 asyncio task

**`__init__` 不做的事**：
- 不读 `~/.skillclaw/skills/`（那是 SkillManager 自己的事）
- 不连任何外部 LLM（PRMScorer 由外部传进来）
- 不连任何共享存储（`SkillHub` 在调用现场临时构造）
- 不发任何网络请求

## 2. FastAPI 端点（`_build_app` 完整列表）

| 路径 | 方法 | 处理函数 | 用途 |
|---|---|---|---|
| `/healthz` | GET | `healthz` | 健康检查。固定返回 `{"ok": true}` |
| `/internal/reload-skills` | POST | `reload_skills` | 内部：从共享存储拉新 skill + 重载 `SkillManager`。需要 `Authorization: Bearer <proxy_api_key>` |
| `/v1/models` | GET | `list_models` | 兼容 OpenAI `/v1/models`。返回 `{"object": "list", "data": [{"id": "<served_model_name>", "object": "model", "created": 0, "owned_by": "skillclaw"}]}` |
| `/v1/chat/completions` | POST | `chat_completions` | OpenAI Chat Completions。**主入口** |
| `/v1/responses` | POST | `responses` | OpenAI Responses API。Codex 默认走这个 |
| `/v1/responses/{response_id}` | GET | `get_response` | Responses API 的 retrieve |
| `/v1/responses/{response_id}` | DELETE | `delete_response` | Responses API 的 delete |
| `/v1/messages/count_tokens` | POST | `anthropic_count_tokens` | Anthropic Messages 的 token 计数估算（走 OpenAI 等价 token 估算） |
| `/v1/messages` | POST | `anthropic_messages` | Anthropic Messages。NanoClaw / Claude Code 默认走这个 |

### 2.1 `/healthz` 与 CLI 集成

CLI 的 `status` 命令每 2s 一次 GET `/healthz` 探活：

```python
def _healthz_ready(port, timeout=0.5):
    with urllib.request.urlopen(f"http://127.0.0.1:{port}/healthz", timeout=timeout) as resp:
        if resp.status != 200: return False
        return json.loads(resp.read())["ok"] is True
```

`start --daemon` 模式下父进程用这个等待子进程就绪。

### 2.2 `/internal/reload-skills`

**唯一的非 OpenAI/Anthropic 端点**。被 evolve server 的 `callback` 模式调用：

```python
@app.post("/internal/reload-skills")
async def reload_skills(request, authorization=None):
    owner = request.app.state.owner
    await owner._check_auth(authorization)
    await owner._pull_skills_from_cloud()
    skill_count = len(owner.skill_manager.get_all_skills()) if owner.skill_manager else 0
    return {"ok": True, "skills": skill_count}
```

`_check_auth` 比对 `Bearer {proxy_api_key}`（如果有设）。`proxy_api_key` 默认空字符串——意味着默认不强制鉴权，**待确认**生产环境应当强制设置。

### 2.3 `/v1/models` 与"模型名伪装"

`/v1/models` 永远只返回**一个** model：`served_model_name`（默认 `"skillclaw-model"`）。

`/v1/chat/completions` 进入时，body 里的 `model` 字段会被**忽略**（转发时用 `self._served_model`）：

```python
# _handle_request 末尾:
forward_body["model"] = self._served_model   # if "model" not in forward_body
output["model"] = forward_body.get("model") or self._served_model
```

这让 agent 看到的所有 model 都叫 `skillclaw-model`，但实际上游可以配 `gpt-4o` / `claude-3-7` / `kimi-k2.5` 任意一个。

### 2.4 `/v1/chat/completions` 的请求头

```python
@app.post("/v1/chat/completions")
async def chat_completions(
    request,
    authorization=None,
    x_session_id=None,
    x_turn_type=None,
    x_session_done=None,
):
```

| 头 | 必填 | 默认 | 用途 |
|---|---|---|---|
| `Authorization` | 否 | 无 | Bearer token 鉴权（与 `proxy_api_key` 比对） |
| `X-Session-Id` | 否 | 启发式生成 | OpenClaw 用这个把多次请求串成 session |
| `X-Turn-Type` | 否 | `"main"` | OpenClaw 主/子任务区分 |
| `X-Session-Done` | 否 | `false` | 显式关 session |

`x_session_id` 没传且 body 里没 `session_id` 时，进入 `_resolve_tui_session(model, msg_count)`——按"消息数下降 / 300s 不活动"启发式生成 `tui-<model>-<8hex>`。

### 2.5 三个 chat-style 端点的协议分工

- **`/v1/chat/completions`**：OpenAI 经典 chat completions。所有 LLM provider 都支持。Agent 调用时 body 里有 `messages: [{role, content}, ...]`
- **`/v1/responses`**：OpenAI 新版 Responses API。Codex 客户端默认用这个（`previous_response_id` 链式调用、`store: true` 状态保留、`tools: [{type: "custom"|"web_search"|...}]`）。SkillClaw 提供**两种实现模式**：
  - `llm_api_mode = "responses"`：直接转发到上游 `/v1/responses`（用 `_forward_to_llm_responses`），保持 Responses-only tools 不动
  - `llm_api_mode = "chat"`（默认）：把 Responses body 翻译成 chat completions（`_responses_to_openai_body`）再转发；response 也翻回 Responses 格式
- **`/v1/messages`**：Anthropic Messages API。NanoClaw / Claude Code 用这个。SkillClaw 把 body 翻译成 OpenAI chat 格式（`_anthropic_to_openai_body`），转发后用 `_openai_to_anthropic_response` 把响应翻回 Anthropic 格式

## 3. 启动 / 停止 / 就绪

### 3.1 `start()`

```python
def start(self):
    if self._thread and self._thread.is_alive():
        return                                # 幂等
    self._ready_event.clear()
    self._server_stopped_event.clear()
    cfg = uvicorn.Config(self.app, host=..., port=..., log_level="info")
    self._server = uvicorn.Server(cfg)
    self._thread = threading.Thread(target=self._run_server, daemon=True)
    self._thread.start()
    threading.Thread(target=self._print_ready_banner, daemon=True).start()
```

**两件事在子线程里发生**：
- `self._run_server` → `self._server.run()` → uvicorn 进入 event loop
- `self._print_ready_banner` → `self._ready_event.wait(30)` → 收到后打印 banner

`self._ready_event` 在 FastAPI `lifespan` 启动时 `set()`（见下面）。

### 3.2 `lifespan` 上下文

```python
@asynccontextmanager
async def lifespan(_app):
    owner._ready_event.set()                    # 通知 CLI "我活着"
    owner._start_session_idle_sweeper()         # 启动 idle sweeper
    owner._start_skill_reload_polling()         # 启动 skill reload poller
    try:
        yield
    finally:
        owner._ready_event.clear()
        await owner._shutdown_cleanup()
```

**`lifespan` 是 `_build_app` 注册的**。所以"server 起来"意味着 idle sweeper + skill reload poller 已经在跑。

### 3.3 `wait_until_ready`

```python
def wait_until_ready(self, timeout_s: float = 30.0) -> bool:
    return self._ready_event.wait(timeout_s)
```

被 `SkillClawLauncher._run()` 在构造完 server 之后调一次。返回 True = 30s 内拿到 lifespan 的 ready 信号。

### 3.4 `stop()`

```python
def stop(self):
    self._server.should_exit = True
    # 不 wait thread，让 daemon 走完自然退出
```

**幂等**——重复调安全。Launcher 的信号 handler + FastAPI lifespan 的 finally + `server.run()` 内部，三处都会让进程干净退出。

### 3.5 `_shutdown_cleanup`

被 FastAPI lifespan 的 finally 调用：

```python
async def _shutdown_cleanup(self):
    if self._skill_reload_task is not None:
        self._skill_reload_task.cancel()
        await asyncio.gather(self._skill_reload_task, return_exceptions=True)
    if self._session_sweeper_task is not None:
        self._session_sweeper_task.cancel()
        await asyncio.gather(self._session_sweeper_task, return_exceptions=True)
    await self._drain_active_sessions(reason="server_shutdown")
    await self._await_background_tasks(self._shutdown_drain_timeout_seconds)
```

`_drain_active_sessions` 调 `_close_session` 关掉所有未关闭的 session（带 `server_shutdown` reason）。`_await_background_tasks` 等最多 15s 让上传 task 跑完。

## 4. 后台协程

### 4.1 Session idle sweeper

`_start_session_idle_sweeper()` → 起 `_session_sweeper_task = asyncio.create_task(_session_idle_sweeper_loop())`：

```python
async def _session_idle_sweeper_loop(self):
    while True:
        await asyncio.sleep(self._session_sweep_interval_seconds)
        for sid in self._collect_idle_session_ids():
            await self._close_session(sid, reason="idle_timeout")
```

`_collect_idle_session_ids` 扫描 `_session_last_active`，挑出"距上次活动 ≥ 180s 且不在 `_closing_sessions` 里"的 session。

### 4.2 Skill reload poller

`_start_skill_reload_polling()` 检查 `sharing_skill_reload_mode`：
- `off` 或 `callback`：直接 return，不启
- `poll`（默认）：起 `_skill_reload_poll_loop()`

```python
async def _skill_reload_poll_loop(self):
    first_pull = True
    while True:
        if first_pull or has_pending_reload():
            await self._pull_skills_from_cloud()
            first_pull = False
        await asyncio.sleep(self._skill_reload_poll_seconds)
```

- 默认 30s 一次；`min=5s`（`_normalize_reload_interval` 兜底）
- 失败 backoff：`min(streak*5, 60)s`，**最长 1 分钟**
- `_pull_skills_from_cloud` 失败会**重试**（next loop iteration），但 backoff 在 60s 封顶

### 4.3 Validation worker

`SkillClawAPIServer` **本身不**起 `ValidationWorker`——是 `SkillClawLauncher` 在 `cfg.validation_enabled` 时用 `asyncio.create_task(worker.run())` 启的。`server` 本身作为 `idle_provider` 注入 worker。详见 [21 · 后台验证工作流](02-客户端共享层/21-后台验证工作流.md)。

## 5. 鉴权

```python
async def _check_auth(self, authorization: Optional[str]):
    if not self._expected_api_key:
        return                                 # 没设 = 不强制
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(401, "missing bearer token")
    token = authorization.split(" ", 1)[1].strip()
    if token != self._expected_api_key:
        raise HTTPException(401, "invalid api key")
```

只对 `/internal/reload-skills` 强制。OpenAI 端点 **不** 强制鉴权——因为 agent 客户端通常不会主动带 Authorization。

`/v1/messages` 的 Anthropic 端点同时接受 `Authorization: Bearer ...` 和 `x-api-key: ...` 两种鉴权头（`_anthropic_messages` 处理函数）。

## 6. 与 SkillClawConfig 的对应

`SkillClawAPIServer` 用到的 config 字段（按消费顺序）：
- `record_dir` / `record_enabled` / `proxy_api_key` / `claw_type` / `llm_provider`（构造时）
- `served_model_name`（每个请求）
- `use_prm` / `prm_scorer`（每个 main turn）
- `skill_manager`（每个 main turn）
- `max_context_tokens` + `body.max_tokens`（每次 _truncate_messages）
- `use_skills` / `max_skills_prompt_chars`（_inject_skills）
- `sharing_enabled` / `sharing_session_upload_interval`（上传 + 触发 evolve）
- `evolve_server_url`（_trigger_evolve）
- `sharing_skill_reload_mode` / `sharing_skill_reload_interval_seconds`（reload poller）
- `llm_api_mode`（决定 /v1/responses 走 native 还是 chat 翻译）
- `session_idle_close_seconds` / `session_sweep_interval_seconds` / `shutdown_drain_timeout_seconds`（生命周期）

## 7. 安全与限制

- **`/v1/messages/count_tokens` 的精度**：用 `_estimate_openai_body_input_tokens`（tiktoken-free 的近似估算，详 [13 · 请求处理与协议适配]）。不调上游 Anthropic。
- **OpenAI 响应里 `tool_calls` 的去重**：`_deduplicate_tool_calls` 用 `(name, arguments)` 去重，避免模型重复 emit。
- **`/v1/responses` 内存存储**：`_responses_store` 永远在内存里——**不持久化**。进程重启后所有 `response_id` 失效。Codex 在重启时用空 store 是正常的。
- **X-Session-Id 来源信任**：`X-Session-Id` 由 agent 设置——SkillClaw 不验证它。**待确认**生产里如果有恶意 client 伪造 session_id 隔离别的 user，目前没有防。

## 8. 待确认 / 已知限制

- **`record_enabled=False` 仍写文件**：`__init__` 不分支 `if record_enabled`——空 `conversations.jsonl` 仍会被创建（无害但奇怪）。`api_server.py` 的几个判 `self._record_file` 才决定要不要写。**待确认**是否该把 `os.makedirs` 也走 if 分支。
- **`max_context_tokens` 兜底逻辑**：`max_prompt = self.config.max_context_tokens - int(body.get("max_tokens") or 2048)`——如果 `body.max_tokens` 很大（>= max_context_tokens），`max_prompt` ≤ 0，**`_truncate_messages` 不触发**，整段 messages 原样转发——**可能**触发上游 LLM context 溢出。**待确认**生产里是否要加 max_prompt 下限。
- **`wait_until_ready` 超时 = False**：launcher 在 `_run` 里只 warning "did not report ready"，但**仍**继续往下走（起 validation worker 等）。生产应该让 launcher 失败退出——**待确认**这是设计选择还是疏忽。
