# 15 · 技能库与注入

## 这一章讲什么

这一章回答"本地 `~/.skillclaw/skills/` 下的 N 个 SKILL.md，是怎么被 SkillClaw 加载、检索、注入到 system prompt 的；以及 PRM 的反馈怎么写回"。

## 它在整个系统的哪个位置

`SkillClawAPIServer._handle_request` 调 `_inject_skills` 时使用 `SkillManager`（**热路径**）；`SkillClawLauncher` 启动时构造 `SkillManager`（**冷启动路径**）；`SkillHub.pull_skills` 下载完新 skill 后调 `skill_manager.reload()`（**同步旁路**）。

## 设计目的

让模型在每个 main turn 都"看到"一个**完整的 skill 目录索引**——但实际加载只在模型主动 `read` 时发生。这条"列全 → 选 → 按需读"的链是 SkillClaw 区别于"自动向量检索 RAG"的关键。

> **本章用到的术语速览**:
> - **Turn**(详 [02 · 核心概念词典 §9](../00-总览/02-核心概念词典.md)):一次 LLM 往返。**main turn** 是 Turn 的两种之一(另一是 **side turn**——指 sub-tool 调用、Codex Responses 协议里与 main 区分);`_inject_skills` 在 `turn_type=main` 时才注入。
> - **Two Loops**(详 [01 · 全景与设计哲学](../00-总览/01-全景与设计哲学.md)):SkillClaw 把"客户端注入 ↔ 服务端演化"两条反馈回路解耦;**本章对应客户端 loop**(Evolve loop 见 [30-32 章](../03-Evolve服务/))。

## 1. `SKILL.md` 文件格式

```markdown
---
name: debug-systematically
description: "Use when diagnosing a bug. Gather evidence before forming hypotheses. NOT for: simple typo fixes."
metadata:
  {
    "openclaw": { "emoji": "🔍" },
    "skillclaw": { "category": "coding" }
  }
---

# Debug Systematically

1. Reproduce the bug.
2. ...
```

最小必要字段：
- `name`：kebab-case，正则 `^[a-z][a-z0-9-]{1,63}$`
- `description`：必填，**触发描述**（写"什么时候用、什么时候不要用"）

可选字段：
- `metadata.openclaw.emoji`：OpenClaw 适配器用的 emoji
- `metadata.skillclaw.category`：分类（`coding` / `research` / `data_analysis` / `security` / `communication` / `automation` / `agentic` / `productivity` / `common_mistakes` / `general`）
- 顶层 `category`（**legacy 字段**）：如果 `metadata.skillclaw.category` 缺失，回退到这个
- 其它任意字段（`homepage` / `user-invocable` / `disable-model-invocation`）：会保留在 `_extra_frontmatter` 里

## 2. `SkillManager` 构造

```python
SkillManager(
    skills_dir="~/.skillclaw/skills",          # 或 claw 适配的目录
    public_skill_root="",                      # 用于 XML 注入的 <location>
    retrieval_mode="template",                 # 或 "embedding"
    embedding_model_path="Qwen/Qwen3-Embedding-0.6B",  # 仅 embedding 模式
)
```

构造时**同步**扫描 `skills_dir`：
1. 找 `*/SKILL.md`（或 `**/SKILL.md` for Hermes）
2. `_parse_skill_md(path)` 每个文件
3. 跳过 name/description 缺失的、YAML 解析失败的、不以 `---` 开头的
4. 维护 `self.skills = {"all_skills": [...]}`、`self._skills_fingerprint`、`self._stats`、`self._category_counts`
5. embedding 模式额外 `_compute_skill_embeddings()`（懒加载 SentenceTransformer）

`skills_dir` 不存在时抛 `FileNotFoundError`。`retrieval_mode` 不是 `"template"` 或 `"embedding"` 时抛 `ValueError`。

### 2.1 `_parse_skill_md` 流程

```python
# 伪代码骨架（见 skill_manager.py:SkillManager._parse_skill_md）:
def _parse_skill_md(path: str) -> dict | None:
    # 1. 读文件、校验 --- 包裹
    # 2. yaml.safe_load frontmatter
    # 3. 校验 name (kebab-case 正则) / description 非空
    # 4. category 解析：metadata.skillclaw.category > 顶层 category > "general"
    # 5. 返回 {id, name, description, category, content, file_path, metadata, _extra_frontmatter}
    ...
```

**核心不变量**：
- `id` 是 `sha256(name)[:12]`——和 `SkillIDRegistry` 用同一个算法
- `_extra_frontmatter` 把不认识的字段原样保留——下游 `add_skill` / `_write_skill_md` 能 round-trip 写回
- `content` 不含 frontmatter

### 2.2 `_is_hermes_skill_root()`

Hermes 用 `~/.hermes/skills/<category>/<name>/SKILL.md`（category 是子目录）。其它都是 `<name>/SKILL.md`。`SkillManager._is_hermes_skill_root` 用 realpath 比对 `~/.hermes/skills`：

```python
return os.path.realpath(self._skills_dir) == os.path.realpath(os.path.join(os.path.expanduser("~"), ".hermes", "skills"))
```

`_skill_md_paths` 在 Hermes root 下用 `**/SKILL.md`（recursive），其它用 `* /SKILL.md`（非 recursive）。

`_skill_dir_path(skill)` 在 Hermes + category ≠ general 时用 `category/skill_name` 子目录；其它用 `skill_name`。

## 3. 两种检索模式

### 3.1 `template`（默认）

```python
def retrieve(self, task_description, top_k=6) -> list[dict]:
    all_skills = list(self.skills.get("all_skills", []))
    sorted_by_eff = sorted(all_skills, key=lambda s: self.get_effectiveness(s["name"]), reverse=True)
    return sorted_by_eff[:top_k]
```

**按 effectiveness 排序取 top-k**——和 `task_description` 无关。

适用场景：本地 skill 数量少（< 几十个），需要快 + 零额外依赖。SkillClaw 的默认行为。

### 3.2 `embedding`

```python
def _embedding_retrieve(self, task_description, top_k):
    cache = self._compute_skill_embeddings()    # 缓存命中直接返
    sims = cache["embeddings"] @ model.encode([task_description])[0]
    ranked = sorted(..., key=lambda i: self._weighted_score(sims[i], ...), reverse=True)
    kept = self._deduplicate_by_embedding(ranked[:max(top_k*3, top_k)], cache, top_k)
    return [cache["items"][i] for i in kept]
```

- `_compute_skill_embeddings()`：把每个 skill 的 `name + description + content[:200]` 拼成文本，SentenceTransformer 编码（默认 `Qwen/Qwen3-Embedding-0.6B`）
- 余弦相似度 = `embeddings @ query_emb`（已 normalize，点积就是 cos）
- `_weighted_score = similarity * (0.3 + 0.7 * eff)`：30% 相似度 + 70% 效果权重——**高 effectiveness 的 skill 在相似度相近时优先**
- `_deduplicate_by_embedding(candidates, cache, top_k, threshold=0.9)`：候选前 `max(top_k*3, top_k)` 个按相似度去重（余弦 > 0.9 视为重复），留出 top_k 个 slot 让后续更低相似度的填进来

依赖：需要 `skillclaw[embedding]` extra（`numpy` + `sentence-transformers`）。

`refresh_if_changed()` 通过 `_compute_skills_fingerprint`（`(path, mtime_ns, size)` 元组列表）判断本地 skill 文件是否变化，变了就 `reload()` 并 `self.generation += 1`。

## 4. `format_skills_for_prompt`（核心输出）

`SkillManager.get_all_skills()` 拿全部**未被 `disable-model-invocation` 屏蔽的** skill：

```python
return [s for s in self.skills["all_skills"] if not s.get("_extra_frontmatter", {}).get("disable-model-invocation", False)]
```

`format_skills_for_prompt(skills)` 构造 OpenClaw 兼容的 `<available_skills>` XML：

```xml
The following skills provide specialized instructions for specific tasks.
Use the read tool to load a skill's file when the task matches its description.
When a skill file references a relative path, resolve it against the skill
directory (parent of SKILL.md / dirname of the path) and use that absolute
path in tool commands.

<available_skills>
  <skill>
    <name>debug-systematically</name>
    <description>Use when diagnosing a bug. ... NOT for: simple typo fixes.</description>
    <location>/Users/alice/.hermes/skills/debug-systematically/SKILL.md</location>
  </skill>
  ...
</available_skills>
```

`_escape_xml` 替换 5 个 XML 特殊字符（`&` / `<` / `>` / `"` / `'`）。

`<location>` 优先用 `public_skill_root` 下的路径（如果有设），否则用 `file_path`（绝对路径）。

### 4.1 `format_skills_compact`（节省 token）

```xml
<available_skills>
  <skill>
    <name>debug-systematically</name>
    <location>/path/to/SKILL.md</location>
  </skill>
  ...
</available_skills>
```

`build_injection_prompt(max_chars=30_000, read_tool_name="read")`：
- 拿 `get_all_skills()`
- 拼 full prompt；如果 ≤ `max_chars` → 用 full
- 否则用 compact
- 用 `build_skills_section(catalog, read_tool_name)` 包成"## Skills (mandatory)"块

`build_skills_section` 的指示语：

```
## Skills (mandatory)
Before replying: scan <available_skills> <description> entries.
- If exactly one skill clearly applies: read its SKILL.md at <location> with `read`, then follow it.
- If multiple could apply: choose the most specific one, then read/follow it.
- If none clearly apply: do not read any SKILL.md.
Constraints: never read more than one skill up front; only read after selecting.
- When a skill drives external API writes, assume rate limits: prefer fewer larger writes, avoid tight one-item loops, serialize bursts when possible, and respect 429/Retry-After.
<available_skills>...</available_skills>
```

**`read_tool_name`** 默认 `"read"`,在 Hermes 场景会被改成 `"skill_view"`,在 Claude Code 场景改成 `"skill"`(见 `api_server._extract_read_skills_from_tool_calls`)。**注:这条 `read_tool_name` 是注入 prompt 里"指示模型用哪个工具读 skill"的提示语,跟下面 §6 里的 `_READ_TOOL_NAMES` 是两条独立机制**——前者是 prompt 文本的"工具名字符串",后者是 SkillClaw 后处理时**反向解析**模型调用的"工具名白名单"。具体见 §6.1。

## 5. `_inject_skills`(实际调用点)

```python
# 伪代码骨架（见 api_server.py:SkillClawAPIServer._inject_skills）:
def _inject_skills(self, messages):
    if not self.skill_manager: return messages, []
    self.skill_manager.refresh_if_changed()    # 监听文件变化
    skill_text = self.skill_manager.build_injection_prompt(max_chars=30_000)
    if not skill_text: return messages, []
    # 拼到第一条 system message 末尾；没有 system 就 insert(0, ...)
    return _append_to_system(messages, skill_text), skill_names
```

**4 步**:
1. `refresh_if_changed()`:本地 skill 文件可能刚被 evolve server 改过(其它客户端写入同步过来)——检测到变化就 reload
2. `build_injection_prompt(max_chars=30_000)`:拼 system prompt 段
3. `record_injection(skill_names)`:**每个 skill 的 `inject_count += 1`**(用于 effectiveness 计算和推送过滤)
4. 把 `skill_text` 拼到第一条 system message 末尾;如果没有 system message 就插一条

**返回** `(messages, skill_names)`——`skill_names` 会进 turn_record 的 `injected_skills`,PRM 完成后回灌 feedback(见 §7.1)。

### 5.1 Codex Responses 端点的注入路径(隐藏)

**注意**:`_inject_skills` 是 **OpenAI Chat Completions 路径**(`/v1/chat/completions`)的注入。Codex 客户端默认走 **OpenAI Responses 协议**(`/v1/responses`),它有**第二条注入路径**:`SkillClawAPIServer._prepare_native_responses_body_inplace(body, turn_type=...)`(`api_server.py:2596+`)。

```python
def _prepare_native_responses_body_inplace(self, body, *, turn_type):
    if not self.skill_manager or turn_type != "main":
        return []                                          # side turn 不注入
    self.skill_manager.refresh_if_changed()               # 同上:监听文件变化
    skill_text = self.skill_manager.build_injection_prompt(
        max_chars=getattr(self.config, "max_skills_prompt_chars", 30_000),
    )
    if not skill_text:
        return []
    all_skills = self.skill_manager.get_all_skills()
    skill_names = [s.get("name", "unknown_skill") for s in all_skills if isinstance(s, dict)]
    self.skill_manager.record_injection(skill_names)      # 同样:inject_count += 1
    existing = _normalize_responses_content(body.get("instructions", ""))
    body["instructions"] = (existing + "\n\n" + skill_text).strip() if existing else skill_text
    return skill_names
```

**关键差异**(对比 `_inject_skills`):
- 注入位置是 `body["instructions"]`(Responses 协议的"系统提示"位),**不是** system message;
- `max_chars` 来源:Codex Responses 路径读 `self.config.max_skills_prompt_chars`(默认 30K);Chat Completions 路径硬编码 30K——**两条路径未统一**:`config` 设值(如 `max_skills_prompt_chars=10000`)**只影响 Codex 路径**,Chat Completions 仍是 30K。重写时应统一为同一 `config` 字段;
- `record_injection` 调用同 §5 第 3 步。

> 重写 SkillClaw 时**两条路径都要实现**——任何只实现 `_inject_skills` 而漏了 `_prepare_native_responses_body_inplace` 的实现,在 Codex 客户端上会得到一个没有 skill 的 system prompt。

## 6. 解析模型读了哪些 skill

`_extract_read_skills_from_tool_calls(tool_calls, skill_path_map)`：

```python
_READ_TOOL_NAMES = {"read", "file_read", "read_file", "readfile"}
_HERMES_SKILL_READ_TOOL_NAMES = {"skill_view"}
_CLAUDE_CODE_SKILL_TOOL_NAMES = {"skill"}
```

流程：
1. 从 tool_call 的 `name` 匹配 read 类工具（OpenClaw: `read` / Hermes: `skill_view` / Claude Code: `skill`）
2. 解析 args：`_extract_skill_paths_from_args_dict(args)`——用正则抓 `path` / `file_path` / `file` 字段
3. `realpath` 后去 `skill_path_map` 查（map 来自 `SkillManager.get_skill_path_map()`，把每个 skill 下的所有可能文件路径映射回 skill name）
4. 匹配上 → 记 `read_skills.append({"skill_name": "X", "path": "..."})`

`_extract_skill_paths_from_patch` / `_extract_skill_paths_from_shell` / `_extract_skill_paths_from_args_dict`：从 patch 格式 / shell 命令 / 通用 args 字典中提取 skill 路径。

`_HERMES_SKILL_WRITE_TOOL_NAMES = {"skill_manage"}`：Hermes 通过 `skill_manage` 工具改 skill（不只是 write 文件）——这个工具的 args 里有 `command` / `action` 字段，SkillClaw 在 `_extract_hermes_skill_name_from_tool_call` 里单独解析。

`_extract_modified_skills_from_tool_calls` 用 `_SKILL_WRITE_TOOL_NAMES`（write / edit / patch / move 等）匹配。

### 6.1 `read_tool_name` 与 `_READ_TOOL_NAMES` 是两条独立机制

> 这一对名词在新读者那里**最容易被混为一谈**——名字相似、作用点接近,但语义完全不同:

- **`read_tool_name`**:一个**字符串参数**,用于 `build_injection_prompt(max_chars=..., read_tool_name="read")` 的指示语里——告诉模型"用 read 工具读 SKILL.md"。**影响 prompt 文本**,**不**影响后处理。
  - 默认 `"read"`(OpenClaw);Hermes 场景传入 `"skill_view"`;Claude Code 场景传入 `"skill"`。
  - **单一字符串**,不是集合。

- **`_READ_TOOL_NAMES` / `_HERMES_SKILL_READ_TOOL_NAMES` / `_CLAUDE_CODE_SKILL_TOOL_NAMES`**:**三个**常量集合,在 `_extract_read_skills_from_tool_calls` 里被**反向**用来匹配"模型实际调用了哪个 read 工具"——**不**影响 prompt,**只**影响后处理(决定 `read_skills` 里记录谁)。
  - 包含变体形式(`read` / `file_read` / `read_file` / `readfile` 等),因为不同 agent 框架的 read 工具命名约定不同。

**两者关系**:`read_tool_name` 是"应该用哪个名字",`_READ_TOOL_NAMES` 是"实际可能叫什么"——前者是规范,后者是兼容。重写 SkillClaw 时**必须保持两者同步**:你 prompt 里让模型用 `read` 调,后处理就得认 `read`;改 prompt 用 `Read`(大写 R)就得把后处理集合也加上。

## 7. Skill 统计（`_stats` / `record_*`）

`SkillManager._stats`：`{skill_name: {inject_count, positive_count, negative_count, neutral_count, last_injected_at, effectiveness}}`，持久化到 `skill_stats.json`。

`record_injection(skill_names)`：
```python
for name in skill_names:
    entry = self._stats.setdefault(name, {
        "inject_count": 0, "positive_count": 0, "negative_count": 0,
        "neutral_count": 0, "last_injected_at": "", "effectiveness": 0.5,
    })
    entry["inject_count"] += 1
    entry["last_injected_at"] = now  # 形如 "2026-07-16T14:30:00"
```

`record_feedback(skill_names, score)`：
- score > 0 → `positive_count += 1`
- score < 0 → `negative_count += 1`
- score == 0 → `neutral_count += 1`
- `effectiveness = positive_count / inject_count`（inject_count == 0 → 0.5）

`_maybe_flush_stats` 每 10 次 mutation 写一次磁盘（`self._stats_dirty = 0`）。`save` / `reload` / `_close_session` 时强制 flush。

`get_effectiveness(name) -> float`：默认 0.5（未观察 = 中性）。

### 7.1 `record_feedback` 的上游调用链

`record_feedback` 是 PRM 反馈回灌 SkillManager 的**末端**。从 PRM 任务完成到 `record_feedback` 被调用,中间经历 3 步(`api_server.py:2244+`):

```python
# 1. PRM 任务完成,asyncio task done callback 触发
task.add_done_callback(lambda _t: self._on_prm_done(session_id, turn_num, _t))

# 2. _on_prm_done 拿 PRM 结果,转交给 _apply_prm_result
def _on_prm_done(self, session_id, turn_num, task):
    prm_result = task.result()  # {"score": float, "votes": [...], "eval_text": str}
    self._apply_prm_result(session_id, turn_num, prm_result)

# 3. _apply_prm_result 把 score 派给 injected + read 两组 skill
def _apply_prm_result(self, session_id, turn_num, prm_result):
    score = prm_result.get("score", 0.0)
    turn = self._pending_turn_data[session_id].pop(turn_num, None)
    if not turn:
        return
    injected = turn.get("injected_skills") or []
    read = turn.get("read_skills") or []
    if injected:
        self.skill_manager.record_feedback(injected, score)   # 对"注入到 prompt 的全部 skill"计分
    read_names = [item.get("skill_name") for item in read if isinstance(item, dict)]
    if read_names:
        self.skill_manager.record_feedback(read_names, score) # 对"模型实际读了的 skill"计分
```

**注意**:
- `score` 由 PRM 多数票给出,值 ∈ {-1.0, 0.0, +1.0}(`prm_scorer.py:_majority_vote` 返 float,平票返 0.0);
- `record_feedback` 会被调**两次**:一次对 `injected_skills`,一次对 `read_skills`——同一个 score 计到两组 skill 的 `positive_count` / `negative_count` / `neutral_count` 上。**这不是 bug**——"注入了"和"读了"是两类独立事件,被分别记分才能正确推 effectiveness;
- `record_only` 模式(`_on_prm_done_record_only`)只写 `prm_scores.jsonl` 不调 `record_feedback`——用于"只想看分数,不想影响 effectiveness"的情形。

## 8. 写入 / 还原（`add_skill` / `_write_skill_md`）

> **注意**:`add_skill` / `add_skills` 这两个 API 在 `SkillManager` 里是**公开**方法,但**产品代码里目前无 caller**(`SkillClawLauncher` / `SkillClawAPIServer` / `SkillHub.pull_skills` 都不调它们——pull 走的是 bundle 写盘路径,不是 in-memory dict 路径)。它们保留在 API 里是给:
> 1. **测试代码**(测试用例直接 `add_skill` 验证 round-trip);
> 2. **未来 plan**——`evolve` server 的 agent 引擎可能用 `add_skill` 把生成的 SKILL.md 灌进 `SkillManager`,而不是写盘;
> 3. **第三方扩展**——开发者可以用 SDK 方式扩展 SkillManager。
>
> 重写 SkillClaw 时,**如果不需要"in-memory add"路径,这两个方法可以删除**(但记得它们会在测试里被引用)。

`add_skill(skill)`：
- name 必须匹配 `^[a-z][a-z0-9-]{1,63}$`，否则拒绝
- name 重复时**默认拒绝**；`skill["_replace"]=True` 强制覆盖
- 写到 `_skill_md_path(skill)`（在 Hermes root 下是 `<category>/<name>/SKILL.md`，否则 `<name>/SKILL.md`）
- 重算 fingerprint；如果 `add_skills` 加了至少一个，`self.generation += 1`（让 caller 检测变化）

`_write_skill_md(skill)`：
- 安全检查：`os.path.realpath(skill_dir)` 必须 `startswith(os.path.realpath(self._skills_dir))`（**防 path traversal**）
- `mkdir(parents=True, exist_ok=True)`
- frontmatter 用 `_format_frontmatter` 序列化：name / description（带特殊字符时加双引号 + 转义）/ extra frontmatter / metadata（用 JSON 块）
- 文件内容：`---\n{fm}\n---\n\n{content}\n`

`_format_frontmatter` 的 description 引号规则（防 YAML 解析错误）：

```python
needs_quoting = any(c in description for c in ':{}[],\"\x27#&*!|>%@\x60\n')
if needs_quoting:
    escaped = description.replace("\\", "\\\\").replace('"', '\\"').replace("\n", "\\n")
    lines.append(f'description: "{escaped}"')
```

`category` **不**写顶层——写到 `metadata.skillclaw.category`（保证 OpenClaw 兼容）。`category` 默认 `"general"`。

## 9. Bundle / 多文件支持

`SkillBundle` 工具集（`skill_bundle.py`）：
- `read_skill_bundle(skill_dir) -> {rel_path: bytes}`：递归读 skill 目录所有文件
- `bundle_tree_sha256(bundle)`：对每个文件的 (path, sha256, size) 排序后拼 SHA-256
- `bundle_file_records(bundle) -> [{"path", "sha256", "size"}, ...]`
- `write_skill_bundle(skill_dir, bundle, clean=False)`：写多文件
- `bundle_entrypoint_text(bundle)`：拿 `SKILL.md` 的文本内容
- `coerce_skill_bundle(bundle)`：把 dict 里的 str / bytes 统一成 bytes，且过滤 ignored 路径

`is_ignored_bundle_rel_path` 过滤：`.DS_Store` / `.git/` / `__pycache__/` / `.pytest_cache/` / `.mypy_cache/` / `.ruff_cache/` / `*.pyc` / `*.pyo`。

`get_skill_path_map` 返回 `{bundle_path: {skill_id, skill_name}}`——agent 工具 read 任何一个文件，SkillClaw 都能反查回 skill。

## 10. 注入边角

- **`max_skills_prompt_chars=30_000`**：硬编码默认值。如果 `format_skills_for_prompt`（带 description）拼出来 ≤ 30K → 用 full；否则 fallback compact（只 name + location）。极端情况下 30K 不够——**待确认**是否要给更激进的"按 effectiveness 砍尾部"。
- **空 skill 库**：`build_injection_prompt` 返回 `""` → `_inject_skills` 跳过注入，skill_names = []。agent 不会收到 `<available_skills>` 块。
- **`_extra_frontmatter` 的 `disable-model-invocation: true`**：从 `get_all_skills` 过滤掉（用于"只让人手动调用的 skill"——比如 `/review` 这样的 slash command）。

## 11. 待确认 / 已知限制

- **`refresh_if_changed` 是 lazy**：只有在 `_inject_skills` 调用时跑——**两次请求之间如果其它进程改了 SKILL.md，下次请求才看到**。生产里若想立刻看到，需要 `skillclaw skills pull` 显式触发 + `reload()`。
- **`_skill_md_paths` 在 Hermes root 用 recursive glob**：可能匹配到 `references/` 下的非主 SKILL.md（如果用户在 references 里又放了一份）。**待确认**这个行为是否有意。
- **`add_skill` 的 path traversal 检查**只对 `_write_skill_md` 起作用——直接 `write_skill_bundle(skill_dir, ...)` 不会有这道关。**待确认**要不要把 path traversal 检查放到更上层。
- **`skill_stats.json` 在 `_save_stats` 时全量写**：100+ skill 时没问题，10000+ skill 时有 IO 抖动。**待确认**生产规模。
- **Embedding 缓存与 reload**：`self._skill_embeddings_cache = None` 在 `reload()` / `add_skill` 时清空——下一次 `retrieve` 会重新编码。频繁 reload 时 embedding 编码是热点。**待确认**是否要 invalidate by skill 而不是全清。
