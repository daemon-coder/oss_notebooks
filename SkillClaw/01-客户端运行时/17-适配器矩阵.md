# 17 · 适配器矩阵

## 这一章讲什么

这一章回答"SkillClaw 怎么让 12 种 CLI agent 的本地配置指向自己的代理、并支持完整回滚"。覆盖 `_ADAPTERS` 注册表、每个 adapter 的具体做法（备份 / 改写 / 还原）、`doctor` 和 `restore` 子命令。

## 它在整个系统的哪个位置

`SkillClawLauncher._run` 在 server ready 后调 `claw_adapter.configure_claw(cfg)`。`doctor` / `restore` CLI 子命令调 `inspect_*_config` / `restore_*_config`。

## 设计目的

让"接入一个新 agent"这件事**对用户零感知**——agent 启动前的配置（OpenClaw 的 `config set`、Hermes 的 `config.yaml`、Codex 的 `config.toml`、Claude Code 的 `settings.json`、NemoClaw 的 OpenShell）被 SkillClaw 接管；用户不需要手动改。

**12 个 claw 的统一接口**：每个 adapter 是一个接受 `SkillClawConfig` 的函数（`Callable[["SkillClawConfig"], None]`），由 `_ADAPTERS` 字典按 `claw_type` 索引。**`none` 是不做任何事的占位**。

## 1. `_ADAPTERS` 注册表

```python
_ADAPTERS: dict[str, Callable[["SkillClawConfig"], None]] = {
    "openclaw": _configure_openclaw, "hermes": _configure_hermes,
    "codex": _configure_codex, "claude": _configure_claude,
    "opencode": _configure_opencode, "qwenpaw": _configure_qwenpaw,
    "ironclaw": _configure_ironclaw, "picoclaw": _configure_picoclaw,
    "zeroclaw": _configure_zeroclaw, "nanoclaw": _configure_nanoclaw,
    "nemoclaw": _configure_nemoclaw, "none": _configure_none,
}   # 12 个 claw type；dispatch 用 if/elif 不是 set
```

`configure_claw(cfg)` dispatcher：

```python
def configure_claw(cfg):
    claw = getattr(cfg, "claw_type", "openclaw")
    if not getattr(cfg, "configure_openclaw", True):
        claw = "none"        # 兼容老配置
    adapter = _ADAPTERS.get(claw)
    if adapter is None:
        logger.warning("[ClawAdapter] Unknown claw_type=%r — skipping auto-configuration", claw)
        return
    adapter(cfg)
```

## 2. 共用工具

### 2.1 配置加载/写入

- `_load_yaml_mapping(path, label) -> dict`：读 YAML 映射；坏 YAML、非 dict 全部兜底成 `{}`
- `_load_json_mapping(path, label) -> dict`：同上但 JSON
- `_write_yaml_mapping_atomic(path, data, label)`：用 `tempfile.NamedTemporaryFile` + `os.fsync` + `os.replace` 做原子写
- `_write_json_mapping_atomic(path, data, label)`：同上但 JSON
- `_yaml_mapping_to_text(data)` / `_write_text_atomic(path, text, label)`：底层 helper

**为什么原子写**？配置文件被两个进程同时改（用户在 IDE 里改 + SkillClaw 自动改）会丢。`os.replace` 在 POSIX 上是 atomic，避免半写状态。

### 2.2 备份机制

```python
_BACKUP_DIRS = {
    "hermes":   "~/.skillclaw/backups/hermes",
    "codex":    "~/.skillclaw/backups/codex",
    "claude":   "~/.skillclaw/backups/claude",
    "opencode": "~/.skillclaw/backups/opencode",
}
```

`_backup_text_file_if_changed(config_path, new_text, backup_dir, label)`：
- 如果新文本**等于**当前 config → return None（不污染备份目录）
- 否则：
  1. `mkdir ~/.skillclaw/backups/<claw>/`
  2. 写 `<backup_dir>/<label>-<YYYYMMDDHHMMSS>-<8hex>.bak`
  3. 写新 config（`os.replace` 原子）

`_latest_backup_path(backup_dir, backup_stem, backup_suffix)`：按 mtime 倒序拿最新一份。

### 2.3 路径安全

```python
def _prepare_external_skills_dir(target_dir, label) -> None:
    path = Path(target_dir).expanduser()
    path.parent.mkdir(parents=True, exist_ok=True)
    if not path.exists():
        path.mkdir(parents=True, exist_ok=True)
        logger.info("[ClawAdapter] created %s skills dir: %s", label, path)
```

统一为 Hermes / Codex / Claude / OpenCode 创建 `~/.hermes/skills` / `~/.codex/skills` / `~/.claude/skills` / `~/.config/opencode/skills`。

### 2.4 TOML 处理（Codex / ZeroClaw）

Codex 用 TOML，SkillClaw 不引 `tomllib` / `tomli` 也不引 `tomlkit`——用**正则**做最小子集：
- `_upsert_top_level_toml_keys(text, updates)`：替换 / 追加顶层 key
- `_remove_top_level_toml_keys(text, keys)`：删顶层 key
- `_remove_toml_table(text, table_name)`：删整个 `[table]`
- `_extract_toml_table(text, table_name)`：提某个 `[table]`
- `_extract_top_level_toml_value(text, key)`：取单个值
- `_format_toml_value(value)` / `_parse_toml_value(raw)`：值 ↔ 文本

**只支持 Codex 用到的 TOML 子集**（string / int / float / bool / inline table），嵌套 table 用 `_extract_toml_table` + 文本重组。

### 2.5 `_run_commands(agent_name, commands, ignore_missing)`

```python
def _run_commands(agent_name, commands, ignore_missing=False):
    for cmd in commands:
        try:
            result = subprocess.run(cmd, capture_output=True, text=True, timeout=15)
        except FileNotFoundError:
            if ignore_missing:
                logger.warning("[ClawAdapter] %s command not found: %s — skipping", agent_name, cmd[0])
                break
            raise
        except subprocess.TimeoutExpired:
            logger.warning("[ClawAdapter] %s command timed out (15s): %s", agent_name, " ".join(cmd))
            continue
        if result.returncode != 0:
            logger.warning(
                "[ClawAdapter] %s command failed: %s\n  stderr: %s",
                agent_name, " ".join(cmd), result.stderr.strip(),
            )
        else:
            logger.info("[ClawAdapter] %s → ok", " ".join(cmd[:4]))
```

**`ignore_missing=True`** 用于"PicoClaw / ZeroClaw / NanoClaw / NemoClaw / IronClaw / QwenPaw 的 restart 步骤"——命令不存在时**不致命**(只是 log 一行 warning,然后 `break` 出循环),让 SkillClaw 在没有完整装好的 agent 机器上也能跑。

`timeout=15s` 防止子进程 hang 死 SkillClaw;超时被捕获并 `continue` 下一条命令,不抛给 caller。

### 2.6 备份目录设计取舍

`SkillClaw` 只对**写文本配置文件**的 4 个 claw 进 `_BACKUP_DIRS`:
- `hermes` 写 `~/.hermes/config.yaml`(YAML)
- `codex` 写 `~/.codex/config.toml` + `~/.codex/skillclaw.config.toml`(TOML)
- `claude` 写 `~/.claude/settings.json`(JSON)
- `opencode` 写 `~/.config/opencode/opencode.json`(JSON)

**其他 8 个 claw 不进 `_BACKUP_DIRS`** 的原因:
- `openclaw` —— OpenClaw CLI 自带 `config set` 的内置 backup(`~/.openclaw/backups/`),SkillClaw 借用,不再叠一份
- `ironclaw` / `picoclaw` / `zeroclaw` / `nanoclaw` / `nemoclaw` —— 配置写在各自进程的工作目录(launchd plist / systemd unit / 容器内)的 `.env` / `config.json` / `config.toml`;这些**进程级配置**改错的代价低(进程重启会重读,改回原值),且 backup 路径没跨进程稳定位置,故不做本地备份;用户用 `service restart` 重读最新配置即可
- `qwenpaw` —— 同上,`providers/builtin/qwenpaw-local.json` + `active_model.json` 是 secret_dir 下的两个文件;改错的代价低(QwenPaw daemon 重启重读)
- `none` —— 占位,不动任何配置

> **结论**:如果你要用 `restore <claw>`,**目前只支持 4 个**;其它 claw 要回滚请直接改对应配置文件。

## 3. 每个 Adapter 的具体做法

### 3.1 OpenClaw

`_configure_openclaw` 走 `openclaw` CLI 子命令：

```bash
openclaw config set models.providers.skillclaw --json '{...provider json...}'
openclaw config set agents.defaults.model.primary skillclaw/skillclaw-model
openclaw config set agents.defaults.sandbox.mode off
openclaw gateway restart
```

provider JSON：
```json
{
  "api": "openai-completions",
  "baseUrl": "http://127.0.0.1:30000/v1",
  "apiKey": "<proxy_api_key or 'skillclaw'>",
  "models": [{
    "id": "skillclaw-model",
    "name": "skillclaw-model",
    "reasoning": false,
    "input": ["text"],
    "cost": {"input": 0, "output": 0, "cacheRead": 0, "cacheWrite": 0},
    "contextWindow": 32768,
    "maxTokens": 8192
  }]
}
```

**没有 backup / restore**——因为 `openclaw` 本身有内置 backup。`_run_commands` 用 `ignore_missing=False`（没装 OpenClaw 会警告）。

### 3.2 Hermes

`_configure_hermes` 直接改 `~/.hermes/config.yaml`：

```python
config["providers"] = {"skillclaw": {..., "baseUrl": f"http://127.0.0.1:{cfg.proxy_port}/v1"}}
config["defaultModel"] = "skillclaw/skillclaw-model"
```

如果 user-invocable 字段已经有其它 provider，**保留**其它 provider，**只覆盖** `defaultModel`。

**特殊处理**：
- `_prepare_hermes_skills_dir(cfg)`：mkdir `~/.hermes/skills` + 把 `~/.skillclaw/skills/` 里有但 `~/.hermes/skills/` 里没有的 skill 复制过去（legacy skills 迁移）
- `_copy_missing_skill_dirs(src_root, dst_root)`：递归复制（不删 dst 里的）——只"补缺"

**Hermes 的备份目录**：`~/.skillclaw/backups/hermes/`。`_backup_hermes_config_if_changed` + `_latest_hermes_backup_path` 提供回滚点。

`inspect_hermes_config(cfg)` 返回有序字段（含 `proxy_match` / `skills_dir_exists` / `legacy_skillclaw_skills_present` 等）。

`restore_hermes_config(backup_path=None)` 调 `_latest_hermes_backup_path()` 选最新备份（或显式指定），原子写回 `~/.hermes/config.yaml`。

### 3.3 Codex

`_configure_codex` 改 `~/.codex/skillclaw.config.toml`（**用户的 `~/.codex/config.toml` 不动**）：

```toml
# ~/.codex/skillclaw.config.toml  (SkillClaw 专属 profile)
[providers.skillclaw]
base_url = "http://127.0.0.1:30000/v1"
api_key = "skillclaw"

[profiles.skillclaw]
model = "skillclaw-model"
provider = "skillclaw"
```

**关键设计**：Codex 用**profile**机制——`~/.codex/config.toml` 顶层有用户默认配置（不改动），SkillClaw 写一个独立 profile `~/.codex/skillclaw.config.toml`。Codex 在启动时按自身约定扫描 `~/.codex/<profile>.config.toml`，SkillClaw 直接写 `skillclaw.config.toml`，无需在主 config 注册 `profile_paths`。

用户用 `codex --profile skillclaw` 启用 SkillClaw，**不传** `--profile` 时还是用原配置——**不污染**用户默认。

**重跑 SkillClaw 行为**:`_configure_codex` 每次都用 SkillClaw 自己的内容**完整重写** `~/.codex/skillclaw.config.toml`(不保留上次额外的字段);如果用户在 profile 块里手工加了别的 model,每次 `skillclaw start` 会被覆盖。

**Codex 的 backup**：`~/.skillclaw/backups/codex/`。`restore_codex_config(backup_path=None)` 原子还原 + 删 `~/.codex/skillclaw.config.toml`。

### 3.4 Claude Code

`_configure_claude` 改 `~/.claude/settings.json`：

```json
{
  "providers": {
    "skillclaw": {
      "baseUrl": "http://127.0.0.1:30000/v1",
      "apiKey": "skillclaw"
    }
  },
  "defaultModel": "skillclaw/skillclaw-model"
}
```

`inspect_claude_config` / `restore_claude_config` 同 Hermes / Codex 模式。备份目录 `~/.skillclaw/backups/claude/`。

### 3.5 OpenCode

`_configure_opencode` 改 `~/.config/opencode/opencode.json`：

```json
{
  "providers": {
    "skillclaw": {
      "baseUrl": "http://127.0.0.1:30000/v1",
      "apiKey": "skillclaw",
      "models": [{"id": "skillclaw-model", "name": "skillclaw-model", "contextWindow": 32768, "maxTokens": 8192}]
    }
  },
  "defaultModel": "skillclaw/skillclaw-model"
}
```

`_prepare_opencode_skills_dir` 创建 `~/.config/opencode/skills`。备份目录 `~/.skillclaw/backups/opencode/`。

### 3.6 QwenPaw

`_configure_qwenpaw`(`claw_adapter.py:1146+`)通过 QwenPaw 的 **"两个目录"** 机制(不是"config+skills"——是"working_dir + secret_dir"):

```python
def _resolve_qwenpaw_dirs() -> tuple[Path, Path]:
    working_dir = (
        Path(_get_qwenpaw_env("QWENPAW_WORKING_DIR", "~/.qwenpaw")).expanduser().resolve()
    )
    secret_dir = (
        Path(_get_qwenpaw_env("QWENPAW_SECRET_DIR", f"{working_dir}.secret")).expanduser().resolve()
    )
    return working_dir, secret_dir
```

**两个目录的职责**:
- `working_dir` (= `~/.qwenpaw`,可被 `QWENPAW_WORKING_DIR` env 覆盖)—— 存 QwenPaw 的 app config(`config.json`)
- `secret_dir` (= `<working_dir>.secret`,可被 `QWENPAW_SECRET_DIR` env 覆盖)—— 存 provider secret + active model
- 两者通过 symlink 关联(QwenPaw 自己管理),**不是 SkillClaw 创建的**

**`configure_qwenpaw(cfg)` 写 3 个文件**:
1. `working_dir/config.json` —— 写 `models: [skillclaw-model, ...]`,用 `_upsert_model_info` 把 model_id 加入列表(已存在则保持)
2. `secret_dir/providers/builtin/qwenpaw-local.json` —— 写 provider 描述(`id=qwenpaw-local`,`base_url=http://127.0.0.1:{proxy_port}/v1`,`api_key=proxy_api_key or 'skillclaw'`)
3. `secret_dir/providers/active_model.json` —— `{"provider_id": "qwenpaw-local", "model": "<model_id>"}`(激活 SkillClaw 作为默认)

**restart**:`_run_commands("qwenpaw", [["qwenpaw", "daemon", "restart"]], ignore_missing=True)`。QwenPaw daemon 启动时读这 3 个文件,所以 restart 是必需的。

**skills 目录**:`resolve_skills_dir` 默认 `~/.qwenpaw/skills`(从 `working_dir` 派生)。`_configure_qwenpaw` **不**主动创建或迁移 skills——用户自己放。

### 3.7 IronClaw

`_configure_ironclaw`(`claw_adapter.py:1216+`)改 `~/.ironclaw/.env` —— 写 **4 个 key**(不是 `IRONCLAW_*` 前缀):

```bash
LLM_BACKEND=openai_compatible
LLM_BASE_URL=http://127.0.0.1:30000/v1
LLM_MODEL=skillclaw-model
LLM_API_KEY=skillclaw
```

`new_vars` 字典构造(从 cfg 派生):
```python
new_vars = {
    "LLM_BACKEND": "openai_compatible",
    "LLM_BASE_URL": f"http://127.0.0.1:{cfg.proxy_port}/v1",
    "LLM_MODEL": cfg.served_model_name or cfg.llm_model_id or "skillclaw-model",
    "LLM_API_KEY": cfg.proxy_api_key or "skillclaw",
}
```

`_patch_dotenv(env_path, new_vars, label)`(`claw_adapter.py:1240+`)**识别 SkillClaw 注入 key 的规则**:**key 必须出现在 `new_vars` dict 里**——不是按前缀(`IRONCLAW_*` 是没用的),也不是按注释标记。逻辑:
- 逐行读旧 .env,跳过注释行和空行;
- 遇到 `KEY=VALUE` 且 `KEY in new_vars` → 覆盖为 `new_vars[KEY]`;
- 其它行原样保留(用户自己的环境变量不被覆盖);
- 旧文件没有的 `new_vars` key → 在末尾追加。

**restart**:`_run_commands("ironclaw", [["ironclaw", "service", "restart"]], ignore_missing=True)`。IronClaw 在启动时读 .env,所以 restart 是必需的。

### 3.8 PicoClaw

`_configure_picoclaw`(`claw_adapter.py:1285+`)改 `~/.picoclaw/config.json` 的 `model_list` —— 读 JSON、拿 `model_list` 列表、把 skillclaw provider(`{"id": "skillclaw", "baseUrl": f"http://127.0.0.1:{proxy_port}/v1", "apiKey": proxy_api_key or "skillclaw", "defaultModel": model_id}`)**插到列表头**、原子写回。如果 `model_list` 字段不存在,创建空列表后插。

**restart**:`_run_commands("picoclaw", [["picoclaw", "gateway", "restart"]], ignore_missing=True)`。PicoClaw gateway 启动时读 config.json。

**backup**:不进入 `_BACKUP_DIRS`(见 §2.6)。配置文件是单 JSON,出错直接手动 `~/.picoclaw/config.json` 改回。

### 3.9 ZeroClaw

`_configure_zeroclaw`(`claw_adapter.py:1349+`)改 `~/.zeroclaw/config.toml` —— 用 §2.4 的 `_upsert_top_level_toml_keys` 替换 / 追加顶层 key(如 `provider = "skillclaw"` / `base_url = "http://127.0.0.1:30000/v1"` / `default_model = "skillclaw-model"`)。**只覆盖 SkillClaw 关心的 key**(用 `new_vars` dict 控制),不动其它顶层 key。

**restart**:`_run_commands("zeroclaw", [["zeroclaw", "service", "restart"]], ignore_missing=True)`。

**backup**:不进入 `_BACKUP_DIRS`(见 §2.6)。

### 3.10 NanoClaw

`_configure_nanoclaw`(`claw_adapter.py:1422+`)**特殊点**:用 `_find_nanoclaw_env()` 多平台查找 NanoClaw 的 `.env` 路径,优先级:
1. macOS:`~/Library/LaunchAgents/com.nanoclaw.plist` 的 `WorkingDirectory` 字段 → 那里的 `.env`
2. Linux:`~/.config/systemd/user/nanoclaw.service` 的 `WorkingDirectory` 字段 → 那里的 `.env`
3. 常见 dev path:`~/nanoclaw/.env` / `~/code/nanoclaw/.env` / `~/.nanoclaw/.env`

找到后用 `_patch_dotenv` 注入 1 个 key:`ANTHROPIC_BASE_URL=http://127.0.0.1:{proxy_port}`(NanoClaw 用 Anthropic SDK 调 LLM,所以走 SkillClaw 的 `/v1/messages` 端点)。

**重启服务**(`_run_commands`):
- macOS:`launchctl unload <plist>` + `launchctl load <plist>`(两步)
- Linux:`systemctl --user restart nanoclaw`
- 找不到 plist / service:warning + skip

**backup**:不进入 `_BACKUP_DIRS`(见 §2.6)。

### 3.11 NemoClaw

`_configure_nemoclaw` 注册 skillclaw provider 到 NVIDIA NemoClaw 的 **OpenShell** + 设 inference route。`_write_nemoclaw_config(endpoint_url, model, api_key)` 写 NemoClaw 自己的 config 路径(由 `NemoClaw` 安装约定决定,SkillClaw 不主动指定)。

**restart**:由 NemoClaw 自身 OpenShell 机制触发(SkillClaw 不直接 run 任何命令),失败时仅 warning。

**backup**:不进入 `_BACKUP_DIRS`(见 §2.6)。NemoClaw 的 OpenShell 自身有 audit log,出错可查。

### 3.12 none（占位）

```python
def _configure_none(cfg):
    logger.info("[ClawAdapter] claw_type=none — skipping auto-configuration")
```

`claw_type=none` 意味着用户**不**想 SkillClaw 自动改 agent 配置——用户自己手动把 agent 指向 `http://127.0.0.1:30000`。

**当 `configure_openclaw=False` 时**（老配置兼容），`configure_claw` 也会强制走 `none`。

## 4. `doctor <claw>`：诊断当前集成状态

`doctor` 子命令调 `inspect_<claw>_config(cfg)` 返回一个 dict。`cli._echo_report` 按固定顺序打印（让机器可解析）：

```
status: configured
integration_scope: client
config_path: /Users/alice/.hermes/config.yaml
config_exists: True
expected_model: skillclaw/skillclaw-model
configured_model: skillclaw/kimi-k2.5
expected_base_url: http://127.0.0.1:30000/v1
configured_base_url: https://api.moonshot.cn/v1
configured_provider: anthropic
proxy_match: False
expected_skills_dir: /Users/alice/.hermes/skills
skills_dir_exists: True
skills_dir_mode: hermes
legacy_skillclaw_skills_dir: /Users/alice/.skillclaw/skills
legacy_skillclaw_skills_present: True
latest_backup: /Users/alice/.skillclaw/backups/hermes/hermes-20260420-150000-ab12cd34.bak
session_boundary_mode: explicit_headers
issues:
  - configured provider 'anthropic' but expected 'skillclaw'
  - configured model 'skillclaw/kimi-k2.5' does not include expected baseUrl 'http://127.0.0.1:30000/v1'
notes:
  - legacy skills in ~/.skillclaw/skills were copied to ~/.hermes/skills
next_steps:
  - re-run 'skillclaw start' to apply the integration
```

`status` 通常是 `configured` / `misconfigured` / `not_configured` / `unknown_claw` 之一。

`integration_scope` 区分 `client`（SkillClaw 只改客户端设置）和 `server`（改了服务端配置）。

**`session_boundary_mode` 的两种值**：
- `explicit_headers`：agent 自己发 `X-Session-Id` / `X-Session-Done` ——OpenClaw / Hermes / Claude Code
- `proxy_heuristic`：agent 不发，SkillClaw 用 TUI 边界启发式——QwenPaw / IronClaw 等

## 5. `restore <claw> [--backup PATH]`：回滚

`restore_hermes_config(backup_path=None)` 等函数：
1. `backup_path` 为 None → `_latest_<claw>_backup_path()` 选 mtime 最新
2. 读备份文件内容
3. `os.replace(backup, target)` 原子写回
4. 返回 `{"target": "<target>", "source": "<backup>"}`

CLI 输出：
```
Restored Hermes config: /Users/alice/.hermes/config.yaml <- /Users/alice/.skillclaw/backups/hermes/hermes-20260420-150000-ab12cd34.bak
```

**Codex 特殊**：还原后还会删 `~/.codex/skillclaw.config.toml`（SkillClaw 自己的 profile 文件）。

**不会**重启 agent——用户要自己重启。

## 6. `SkillsClaw` 的 skills 目录适配

每个 claw 适配器在它的"config 改写"之后会**确保** skills 目录存在：

| claw | skills 目录 |
|---|---|
| `openclaw` | （OpenClaw 自己决定） |
| `hermes` | `~/.hermes/skills`（按 category 子目录） |
| `codex` | `~/.codex/skills` |
| `claude` | `~/.claude/skills` |
| `opencode` | `~/.config/opencode/skills` |
| `qwenpaw` | `~/.qwenpaw/skills` |
| `ironclaw` | （跟 IronClaw 约定） |
| `picoclaw` | （跟 PicoClaw 约定） |
| `zeroclaw` | （跟 ZeroClaw 约定） |
| `nanoclaw` | （跟 NanoClaw 约定） |
| `nemoclaw` | （跟 NemoClaw 约定） |
| `none` | `~/.skillclaw/skills`（默认） |

`ConfigStore.resolve_skills_dir` 把"用户填了 `~/.skillclaw/skills` 但 claw 是 hermes/codex/claude/opencode"的情况**自动改写**为该 claw 的 native 目录——见 [11 · 配置系统](11-配置系统.md) §3.3。

## 7. 添加新 Claw 的步骤

要加一个新 agent（假设叫 `foobarclaw`）：

1. 在 `claw_adapter.py` 加 `_configure_foobarclaw(cfg)` 函数
2. 在 `_ADAPTERS` 字典注册：`"foobarclaw": _configure_foobarclaw`
3. 在 `CLAW_TYPES` 自动出现（用 `list(_ADAPTERS)`）
4. 在 `ConfigStore.default_skills_dir_for_claw` 加 `if normalized == "foobarclaw": return _DEFAULT_FOOBARCLAW_SKILLS_DIR`
5. （可选）在 `ConfigStore.default_llm_api_mode_for_claw` 加特殊 llm_api_mode
6. （可选）写 `inspect_foobarclaw_config` + `restore_foobarclaw_config` + 在 `cli.doctor` / `cli.restore` 注册
7. `SKILL.md` 不需要改（frontmatter 通用）

## 8. 待确认 / 已知限制

- **`_configure_openclaw` 依赖 `openclaw` 在 PATH**：没装 OpenClaw 时 `_run_commands` 警告但不失败——**但 proxy 没人接**。生产应该让 `claw_type=openclaw` 但没装 openclaw 时**报错**而不是 warning。**待确认**这是设计还是疏忽。
- **Hermes backup 命名冲突**：`_backup_text_file_if_changed` 用 `<label>-<YYYYMMDDHHMMSS>-<8hex>.bak`——同一秒多次备份可能撞 hash（8hex = 32M 可能性）。**待确认**要不要加进程内 counter。
- **Codex 的 `[profile.skillclaw]` 模式**：用户传 `--profile skillclaw` 启用，但 `inspect_codex_config` 检查的是**默认** `config.toml`——可能 report "misconfigured" 但实际 `--profile skillclaw` 跑得好。**待确认**doctor 该不该检查两个文件。
- **PicoClaw / ZeroClaw / NanoClaw / NemoClaw 的 restart 命令**：用 `ignore_missing=True`——如果 restart 失败（daemon 装但 start 命令不对），SkillClaw 改完 config 但 agent 还是用旧 config 跑。**待确认**该在 `_run_commands` 返回非零时给 `inspect_*_config` 加个 warning 标记。
- **`doctor` 报告的 `proxy_match` 字段**：当前实现对"base URL 是否匹配"的判断基于字符串相等——`configured_base_url=http://127.0.0.1:30000/v1` 但 `expected=http://127.0.0.1:30001/v1` 会判 False。**待确认**是否要 normalize port / host 之后再比。
